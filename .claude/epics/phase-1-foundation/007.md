# Task: NinjaOne API Wrapper

## Description
Create a typed API wrapper for NinjaOne RMM integration. Support fetching devices by customer, device details, and mapping to RepairShopr assets. Implement caching to respect rate limits.

## Acceptance Criteria
- [ ] `src/lib/ninjaone.ts` created with typed API client
- [ ] Can authenticate with NinjaOne API
- [ ] Can fetch devices by customer email or name
- [ ] Can get device details (OS, hardware, status)
- [ ] Responses cached with 5-minute TTL
- [ ] Device mappings stored in `device_mappings` table
- [ ] Graceful degradation if NinjaOne is unavailable

## Technical Details

**New file: `src/lib/ninjaone.ts`**
```typescript
interface NinjaOneDevice {
  id: string;
  name: string;
  os: string;
  status: 'online' | 'offline';
  lastSeen: Date;
  hardware: {...};
}

export async function getDevices(): Promise<NinjaOneDevice[]>
export async function getDeviceById(id: string): Promise<NinjaOneDevice>
export async function getDevicesByCustomer(email: string): Promise<NinjaOneDevice[]>
export async function mapDeviceToAsset(ninjaId: string, repairshoprAssetId: number): Promise<void>
```

**API Routes:**
- `GET /api/ninjaone/devices` - List all devices
- `GET /api/ninjaone/devices/[id]` - Get device details
- `GET /api/ninjaone/devices/customer/[email]` - Devices by customer

**Caching Strategy:**
- Use in-memory cache with 5-minute TTL for lists
- 1-minute TTL for individual device details
- Cache key includes query parameters

**Error Handling:**
- Retry with exponential backoff on rate limits
- Return cached data if API unavailable
- Log errors for monitoring

**Files affected:**
- `src/lib/ninjaone.ts` (new)
- `src/app/api/ninjaone/devices/route.ts` (new)
- `.env.example` (add NINJAONE_API_KEY, NINJAONE_API_URL)
