1. System Overview & Architecture

Current State Analysis

Currently, technicians at The Computer Store must navigate between multiple systems:

System Purpose Pain Points
RepairShopr Tickets, invoices, customer records, appointments No real-time device status, requires separate login
NinjaOne Device monitoring, remote access, scripting, patching Separate interface, customer context not visible

⚠️ Current Workflow Inefficiency

Technicians must switch between 2-3 browser tabs constantly, leading to context switching, data re-entry, and missed alerts. A unified portal eliminates this friction.

2. API Capabilities Overview

NinjaOne Public API v2

📚 API Documentation

Base URL: https://app.ninjarmm.com/api/v2/
Auth: OAuth 2.0 (Client Credentials or Authorization Code)
Docs: app.ninjarmm.com/apidocs

Key Endpoints for Technician Portal

GET /api/v2/device/{id}

Retrieve comprehensive device details including OS, hardware specs, last seen, policy, and custom fields.

GET /api/v2/device/{id}/alerts

List active alerts for a specific device with severity, type, and timestamp.

GET /api/v2/device/{id}/activities

Retrieve activity log including script runs, patches, user actions.

GET /api/v2/device/{id}/software

Get installed software inventory with versions and publishers.

POST /api/v2/device/{id}/script/{scriptId}

Run a script or built-in action on the device (reboot, shutdown, etc.).

GET /api/v2/device/{id}/dashboard-url

Get authenticated URL to device dashboard for quick navigation.

GET /api/v2/organizations

List all organizations (customers) with their devices.

DELETE /api/v2/alert/{uid}

Clear/acknowledge an alert after resolving the issue.

POST /api/v2/device/{id}/reboot/{mode}

Initiate normal or forced device restart with optional reason.

API Scopes Required

  • Monitoring: Read-only access to device data, alerts, and organizations
  • Management: Ability to run scripts, reboot devices, modify custom fields
  • Control: Remote access session initiation (optional)

RepairShopr REST API

📚 API Documentation

Base URL: https://thecomputerstore.repairshopr.com/api/v1/
Auth: API Key (append ?api_key=YOUR_KEY)
Rate Limit: 180 requests/minute per IP
Docs: api-docs.repairshopr.com

Key Endpoints for Technician Portal

GET /api/v1/tickets

List tickets with filtering by status, customer, date range. Supports pagination.

POST /api/v1/tickets

Create a new ticket with customer_id, subject, problem_type, status.

PUT /api/v1/tickets/{id}

Update ticket status, add comments, change assignment.

GET /api/v1/customers/{id}

Get customer details including contacts, addresses, custom fields.

GET /api/v1/customers/{id}/assets

List all assets (devices) linked to a customer.

GET /api/v1/invoices

List invoices with filtering by customer, status, date.

GET /api/v1/appointments

Get upcoming appointments for scheduling view.

GET /api/v1/rmm_alerts

Get RMM alerts that have been synced from NinjaOne.

3. Integration Strategy

Data Flow Design

The unified portal uses a Backend-for-Frontend (BFF) pattern where your Next.js API routes act as a proxy to both NinjaOne and RepairShopr APIs.

// Simplified data flow architecture

Browser (Technician)
    │
    ├── GET /api/portal/customer/:id
    │       │
    │       └── Next.js API Route
    │               │
    │               ├── RepairShopr: GET /customers/:id
    │               ├── RepairShopr: GET /customers/:id/assets
    │               ├── RepairShopr: GET /tickets?customer_id=:id
    │               └── NinjaOne: GET /devices (mapped by asset)
    │
    └── Returns unified customer object with:
        • Customer info
        • Assets with NinjaOne device status
        • Open tickets
        • Recent invoices

🔗 Customer-Device Mapping

The existing NinjaOne + RepairShopr integration maps Ninja "Organizations" to RepairShopr "Customers" and Ninja "Devices" to RepairShopr "Assets". Your portal can use the RepairShopr asset's serial number or custom field to look up the corresponding NinjaOne device ID.

Caching Strategy

To stay within API rate limits and ensure fast response times:

Data Type Cache Duration Refresh Trigger
Customer List 5 minutes Manual refresh, new ticket
Device Status 30 seconds Page load, polling
Alerts 15 seconds Real-time with webhooks (optional)
Tickets 1 minute Ticket creation, status change
Software Inventory 1 hour Manual scan

import { Redis } from '@upstash/redis'

const redis = new Redis({
  url: process.env.UPSTASH_REDIS_URL,
  token: process.env.UPSTASH_REDIS_TOKEN,
})

async function getDeviceStatus(deviceId: string) {
  const cacheKey = `ninja:device:${deviceId}`

  // Check cache first
  const cached = await redis.get(cacheKey)
  if (cached) return cached

  // Fetch from NinjaOne API
  const device = await fetchNinjaDevice(deviceId)

  // Cache for 30 seconds
  await redis.setex(cacheKey, 30, device)

  return device
}

5. Implementation Guide

Authentication Setup

NinjaOne OAuth 2.0 Configuration

  1. Go to Administration → Apps → API in NinjaOne
  2. Create a new application (select "Client Credentials" for server-to-server)
  3. Note your Client ID and Client Secret
  4. Set scopes: monitoring, management
// lib/ninjaone.ts - NinjaOne API client

class NinjaOneClient {
  private accessToken: string | null = null
  private tokenExpiry: Date | null = null

  private baseUrl = 'https://app.ninjarmm.com/api/v2'
  private authUrl = 'https://app.ninjarmm.com/oauth/token'

  async getToken(): Promise<string> {
    // Return cached token if still valid
    if (this.accessToken && this.tokenExpiry && new Date() < this.tokenExpiry) {
      return this.accessToken
    }

    // Request new token
    const response = await fetch(this.authUrl, {
      method: 'POST',
      headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
      body: new URLSearchParams({
        grant_type: 'client_credentials',
        client_id: process.env.NINJAONE_CLIENT_ID!,
        client_secret: process.env.NINJAONE_CLIENT_SECRET!,
        scope: 'monitoring management',
      }),
    })

    const data = await response.json()
    this.accessToken = data.access_token
    this.tokenExpiry = new Date(Date.now() + data.expires_in * 1000)

    return this.accessToken
  }

  async getDevice(deviceId: string) {
    const token = await this.getToken()
    const response = await fetch(`${this.baseUrl}/device/${deviceId}`, {
      headers: { Authorization: `Bearer ${token}` },
    })
    return response.json()
  }

  async getDeviceAlerts(deviceId: string) {
    const token = await this.getToken()
    const response = await fetch(`${this.baseUrl}/device/${deviceId}/alerts`, {
      headers: { Authorization: `Bearer ${token}` },
    })
    return response.json()
  }

  async runScript(deviceId: string, scriptId: string) {
    const token = await this.getToken()
    const response = await fetch(
      `${this.baseUrl}/device/${deviceId}/script/${scriptId}`,
      {
        method: 'POST',
        headers: { Authorization: `Bearer ${token}` },
      }
    )
    return response.json()
  }

  async rebootDevice(deviceId: string, mode: 'NORMAL' | 'FORCED' = 'NORMAL') {
    const token = await this.getToken()
    const response = await fetch(
      `${this.baseUrl}/device/${deviceId}/reboot/${mode}`,
      {
        method: 'POST',
        headers: { Authorization: `Bearer ${token}` },
      }
    )
    return response.json()
  }
}

export const ninjaOne = new NinjaOneClient()

RepairShopr API Configuration

// lib/repairshopr.ts - RepairShopr API client

class RepairShoprClient {
  private baseUrl = `https://${process.env.REPAIRSHOPR_SUBDOMAIN}.repairshopr.com/api/v1`
  private apiKey = process.env.REPAIRSHOPR_API_KEY

  private buildUrl(endpoint: string, params: Record<string, string> = {}) {
    const url = new URL(`${this.baseUrl}${endpoint}`)
    url.searchParams.set('api_key', this.apiKey!)
    Object.entries(params).forEach(([key, value]) => {
      url.searchParams.set(key, value)
    })
    return url.toString()
  }

  async getCustomer(customerId: string) {
    const response = await fetch(this.buildUrl(`/customers/${customerId}`))
    return response.json()
  }

  async getCustomerAssets(customerId: string) {
    const response = await fetch(this.buildUrl(`/customers/${customerId}/assets`))
    return response.json()
  }

  async getTickets(filters: { customerId?: string; status?: string } = {}) {
    const params: Record<string, string> = {}
    if (filters.customerId) params.customer_id = filters.customerId
    if (filters.status) params.status = filters.status

    const response = await fetch(this.buildUrl('/tickets', params))
    return response.json()
  }

  async createTicket(data: {
    customer_id: number
    subject: string
    problem_type: string
    status?: string
    asset_ids?: number[]
  }) {
    const response = await fetch(this.buildUrl('/tickets'), {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(data),
    })
    return response.json()
  }

  async updateTicket(ticketId: string, data: { status?: string; comment?: string }) {
    const response = await fetch(this.buildUrl(`/tickets/${ticketId}`), {
      method: 'PUT',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(data),
    })
    return response.json()
  }

  async getInvoices(customerId: string) {
    const response = await fetch(this.buildUrl('/invoices', { customer_id: customerId }))
    return response.json()
  }
}

export const repairShopr = new RepairShoprClient()

Unified API Route Example

// app/api/portal/customer/[id]/route.ts

import { NextRequest, NextResponse } from 'next/server'
import { ninjaOne } from '@/lib/ninjaone'
import { repairShopr } from '@/lib/repairshopr'

export async function GET(
  request: NextRequest,
  { params }: { params: { id: string } }
) {
  try {
    // Fetch data from both APIs in parallel
    const [customer, assets, tickets, invoices] = await Promise.all([
      repairShopr.getCustomer(params.id),
      repairShopr.getCustomerAssets(params.id),
      repairShopr.getTickets({ customerId: params.id }),
      repairShopr.getInvoices(params.id),
    ])

    // Enrich assets with NinjaOne device data
    const enrichedAssets = await Promise.all(
      assets.assets.map(async (asset: any) => {
        // Look up NinjaOne device by serial number or custom field
        if (asset.ninja_device_id) {
          try {
            const [device, alerts] = await Promise.all([
              ninjaOne.getDevice(asset.ninja_device_id),
              ninjaOne.getDeviceAlerts(asset.ninja_device_id),
            ])
            return {
              ...asset,
              ninjaDevice: device,
              alerts: alerts,
              status: calculateDeviceStatus(device, alerts),
            }
          } catch (e) {
            return { ...asset, status: 'unknown' }
          }
        }
        return { ...asset, status: 'unmonitored' }
      })
    )

    return NextResponse.json({
      customer: customer.customer,
      assets: enrichedAssets,
      tickets: tickets.tickets.filter((t: any) => t.status !== 'Resolved'),
      invoices: invoices.invoices.slice(0, 5),
    })
  } catch (error) {
    return NextResponse.json(
      { error: 'Failed to fetch customer data' },
      { status: 500 }
    )
  }
}

function calculateDeviceStatus(device: any, alerts: any[]): string {
  if (!device.online) return 'offline'
  if (alerts.some((a: any) => a.severity === 'critical')) return 'critical'
  if (alerts.some((a: any) => a.severity === 'warning')) return 'warning'
  return 'healthy'
}

UI Component Example

// components/portal/CustomerDevices.tsx

'use client'

import { useState } from 'react'

interface Device {
  id: number
  name: string
  asset_serial: string
  ninja_device_id?: string
  status: 'healthy' | 'warning' | 'critical' | 'offline' | 'unmonitored'
  ninjaDevice?: {
    systemName: string
    os: { name: string }
    lastContact: string
  }
  alerts?: any[]
}

export function CustomerDevices({ devices }: { devices: Device[] }) {
  const [loading, setLoading] = useState<string | null>(null)

  const handleReboot = async (deviceId: string) => {
    setLoading(deviceId)
    await fetch(`/api/portal/device/${deviceId}/reboot`, { method: 'POST' })
    setLoading(null)
    // Show toast notification
  }

  const handleRemote = async (deviceId: string) => {
    const response = await fetch(`/api/portal/device/${deviceId}/remote-url`)
    const { url } = await response.json()
    window.open(url, '_blank')
  }

  const statusColors = {
    healthy: 'bg-green-100 text-green-800',
    warning: 'bg-yellow-100 text-yellow-800',
    critical: 'bg-red-100 text-red-800',
    offline: 'bg-gray-100 text-gray-800',
    unmonitored: 'bg-gray-50 text-gray-500',
  }

  return (
    <div className="space-y-4">
      {devices.map((device) => (
        <div key={device.id} className="border rounded-lg p-4 hover:shadow-md">
          <div className="flex items-center justify-between">
            <div className="flex items-center gap-3">
              <span className={`px-2 py-1 rounded text-sm ${statusColors[device.status]}`}>
                {device.status.toUpperCase()}
              </span>
              <div>
                <h4 className="font-medium">{device.name}</h4>
                <p className="text-sm text-gray-500">
                  {device.ninjaDevice?.os?.name || 'Unknown OS'}
                </p>
              </div>
            </div>

            {device.ninja_device_id && (
              <div className="flex gap-2">
                <button
                  onClick={() => handleRemote(device.ninja_device_id!)}
                  className="px-3 py-1 bg-blue-600 text-white rounded hover:bg-blue-700"
                >
                  Remote
                </button>
                <button
                  onClick={() => handleReboot(device.ninja_device_id!)}
                  disabled={loading === device.ninja_device_id}
                  className="px-3 py-1 bg-gray-600 text-white rounded hover:bg-gray-700"
                >
                  {loading === device.ninja_device_id ? '...' : 'Reboot'}
                </button>
              </div>
            )}
          </div>

          {device.alerts && device.alerts.length > 0 && (
            <div className="mt-3 p-2 bg-yellow-50 rounded">
              <p className="text-sm text-yellow-800">
                ⚠️ {device.alerts.length} active alert(s)
              </p>
            </div>
          )}
        </div>
      ))}
    </div>
  )
}

7. Security & Performance Considerations

Security Best Practices

🔐 API Keys Must Be Server-Side Only

Never expose NinjaOne or RepairShopr API keys to the browser. All API calls must go through your Next.js API routes.

  • Authentication: Use existing RepairShopr login (already implemented) to gate portal access
  • Authorization: Verify technician permissions before allowing device actions
  • Audit Logging: Log all destructive actions (reboots, script runs) with user and timestamp
  • Rate Limiting: Implement rate limiting on your API routes to prevent abuse
  • HTTPS Only: Ensure all communications are encrypted (Render provides this automatically)

Performance Optimization

  • Parallel Requests: Always fetch from multiple APIs simultaneously using Promise.all()
  • Caching: Cache device status, customer data to reduce API calls
  • Pagination: Implement infinite scroll or pagination for large lists
  • Optimistic Updates: Update UI immediately before API confirms for snappy feel
  • Background Refresh: Use setInterval or Server-Sent Events for live updates
