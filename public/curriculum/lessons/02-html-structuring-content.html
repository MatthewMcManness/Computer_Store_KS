Lesson 02: HTML — Structuring Content

The foundational language that gives every web page its structure and meaning

Learning Objectives

  • By the end of this lesson, you will be able to write a complete, valid HTML document from scratch
  • By the end of this lesson, you will be able to use semantic elements to give your content meaningful structure
  • By the end of this lesson, you will be able to create text content with headings, paragraphs, and lists
  • By the end of this lesson, you will be able to add links, images, and tables to a page
  • By the end of this lesson, you will be able to build forms with various input types for collecting user data
  • By the end of this lesson, you will be able to apply basic accessibility practices including alt text and ARIA roles

What Is HTML?

HTML (HyperText Markup Language) is the standard language used to create and structure content on the web. Every web page you have ever visited is built with HTML at its foundation. HTML is not a programming language — it does not perform calculations, make decisions, or loop through data. Instead, it is a markup language: it "marks up" plain text to give it structure and meaning.

Analogy: The Blueprint of a Building
If a web page were a building, HTML would be the structural blueprint — it defines the rooms (sections), doors (links), windows (images), and walls (divisions). CSS (which we cover in the next lesson) is the interior design — paint colors, flooring, and furniture. JavaScript (covered in Lesson 5) is the electrical and plumbing systems that make things interactive. You must have the blueprint before you can decorate or wire anything.

HTML uses elements (also called "tags") to wrap content and tell the browser what that content is. For example, the <p> element tells the browser "this is a paragraph," while the <h1> element says "this is the most important heading on the page."

Anatomy of an HTML Element

An HTML element has three parts:

<p class="intro">Welcome to our website.</p>
 |     |                |                  |
 |     |                |                  +-- Closing tag
 |     |                +-- Content (text, other elements, etc.)
 |     +-- Attribute (name="value")
 +-- Opening tag
  • The opening tag (<p>) begins the element. It may contain attributes.
  • Attributes (class="intro") provide additional information about the element. They always appear in the opening tag.
  • The content is whatever appears between the opening and closing tags — text, other elements, or both.
  • The closing tag (</p>) ends the element. Note the forward slash before the tag name.

Some elements are self-closing (also called "void elements") — they have no content and no closing tag:

<img src="photo.jpg" alt="A computer on a desk">
<br>
<hr>
<input type="text" name="username">

The Anatomy of an HTML Document

Every HTML page follows the same basic structure. Let us build one from scratch and explain every line:

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>My First Web Page</title>
</head>
<body>
  <h1>Hello, World!</h1>
  <p>This is my first web page.</p>
</body>
</html>

Let us examine each piece:

<!DOCTYPE html> — This declaration must be the very first line of every HTML document. It tells the browser: "This is an HTML5 document." Without it, the browser might fall into "quirks mode" and render things inconsistently. This is not an HTML element — it is an instruction to the browser.

<html lang="en"> — The root element that wraps everything else. The lang="en" attribute tells browsers and screen readers that the page content is in English. This is important for accessibility — screen readers use this to choose the correct pronunciation.

<head> — The head contains metadata — information about the page that is not displayed directly on the page itself. Think of it as the backstage area.

<meta charset="UTF-8"> — Specifies the character encoding. UTF-8 supports virtually all characters from all languages and is the universal standard. Always include this.

<meta name="viewport" ...> — This is essential for mobile devices. It tells the browser to set the page width to match the device's screen width and start at a 1:1 zoom level. Without this, mobile browsers render pages as if the screen were desktop-sized and then shrink everything down, making text unreadably small.

<title> — The page title that appears in the browser tab, in search engine results, and when you bookmark the page. Every page should have a unique, descriptive title.

<body> — Everything visible on the page goes inside the body. This is the "stage" where your content performs for the user.

Common Beginner Mistake Forgetting the <!DOCTYPE html> declaration or the viewport meta tag are two of the most common mistakes new developers make. The DOCTYPE ensures standards mode rendering, and the viewport meta tag ensures your page works on mobile devices. Always include both.

Semantic HTML Elements

Semantic means "relating to meaning." In HTML, semantic elements clearly describe their purpose to both the browser and the developer. Compare these two approaches:

<!-- Non-semantic: What does this mean? -->
<div id="top-part">
  <div class="links">...</div>
</div>
<div id="main-stuff">...</div>
<div id="bottom-part">...</div>

<!-- Semantic: Crystal clear meaning -->
<header>
  <nav>...</nav>
</header>
<main>...</main>
<footer>...</footer>

Both approaches produce visually identical results (by default), but the semantic version communicates meaning. This matters for three important reasons:

  1. Accessibility: Screen readers (software that reads web pages aloud for visually impaired users) rely on semantic elements to navigate pages. A screen reader can announce "navigation" when it encounters <nav>, or "main content" for <main>, helping users jump to the section they want.
  2. SEO (Search Engine Optimization): Search engines like Google use semantic elements to understand page structure and content importance. Proper semantics can improve your search ranking.
  3. Maintainability: When you or another developer reads the code six months later, semantic elements make the structure immediately clear. <header> is infinitely more understandable than <div class="hdr-wrp">.

The Key Semantic Elements

<header> — Represents introductory content, typically containing the site logo, site title, and main navigation. A page can have multiple headers (for example, a page header and an article header), but there is usually one main header at the top.

<header>
  <img src="/logo.svg" alt="Computer Store KS logo">
  <h1>Computer Store KS</h1>
  <nav>...</nav>
</header>

<nav> — Represents a section of navigation links. This tells screen readers "this is a navigation area" and lets users skip directly to or past the navigation.

<nav>
  <a href="/">Home</a>
  <a href="/services">Services</a>
  <a href="/gallery">Gallery</a>
  <a href="/blog">Blog</a>
  <a href="/contact">Contact</a>
</nav>

<main> — Represents the dominant content of the page — the content that is unique to this specific page and not repeated across pages (unlike the header and footer). There should be only one <main> per page.

<main>
  <h2>Our Services</h2>
  <p>We offer a full range of computer repair services...</p>
</main>

<section> — Represents a thematic grouping of content, typically with its own heading. Use sections to divide content into logical blocks.

<section>
  <h2>Hardware Repair</h2>
  <p>We fix broken screens, replace batteries, and upgrade RAM...</p>
</section>

<section>
  <h2>Software Services</h2>
  <p>Virus removal, OS installation, data recovery...</p>
</section>

<article> — Represents self-contained content that could be distributed independently — a blog post, a news article, a product card, a forum post. If you could take the content out of the page and it would still make sense on its own, it should probably be an <article>.

<article>
  <h2>How to Speed Up Your Computer</h2>
  <p>Published on February 1, 2026</p>
  <p>Is your computer running slowly? Here are five proven tips...</p>
</article>

<aside> — Represents content that is tangentially related to the content around it — a sidebar, a pull quote, or supplementary information.

<footer> — Represents closing content for a page or section. Typically contains copyright notices, contact information, and secondary navigation links.

<footer>
  <p>&copy; 2026 Computer Store KS. All rights reserved.</p>
  <p>123 Main Street, Topeka, KS 66604</p>
</footer>

CSK Connection The Computer Store KS website uses semantic HTML throughout. The Header.tsx component renders a <header> with a <nav> inside it. Each service page wraps its content in <main> and <section> elements. Blog posts use <article> elements. The footer component renders a <footer>. This semantic structure helps the site rank well in search engines and ensures accessibility for all users.

Text Elements

Headings: h1 through h6

HTML provides six levels of headings, from <h1> (most important) to <h6> (least important). Headings create a hierarchy of content, much like an outline for an essay:

<h1>Computer Store KS</h1>              <!-- Page title -->
  <h2>Our Services</h2>                  <!-- Major section -->
    <h3>Hardware Repair</h3>              <!-- Sub-section -->
      <h4>Screen Replacement</h4>        <!-- Sub-sub-section -->
    <h3>Software Services</h3>            <!-- Another sub-section -->
  <h2>About Us</h2>                      <!-- Another major section -->
Heading Rules
  • Use only one <h1> per page — it represents the page's primary topic.
  • Do not skip levels — do not jump from <h2> to <h4> without an <h3> in between.
  • Never use headings just for styling. If you want bigger text, use CSS. Headings convey document structure, not visual size.

Paragraphs

The <p> element represents a paragraph of text. Browsers automatically add spacing above and below paragraphs:

<p>The Computer Store has been serving the Topeka community
for over 15 years. We specialize in affordable computer
repair and custom-built systems.</p>

<p>Whether you need a virus removed, a screen replaced, or
a brand new computer built from scratch, we have you covered.</p>

Text Formatting

<p>This word is <strong>bold and important</strong>.</p>
<p>This word is <em>emphasized (italic)</em>.</p>
<p>Use <code>npm run dev</code> to start the development server.</p>
<p>This text has a <br>line break in the middle.</p>
<hr> <!-- A horizontal rule (divider line) -->

Note the difference between <strong> and <b>: <strong> indicates semantic importance (screen readers emphasize it), while <b> is purely visual bold with no semantic meaning. Always prefer <strong> for important text.

Lists

Unordered lists (<ul>) display items with bullet points. Use them when the order does not matter:

<h3>Services We Offer</h3>
<ul>
  <li>Virus and malware removal</li>
  <li>Hardware diagnostics and repair</li>
  <li>Custom-built computers</li>
  <li>Data backup and recovery</li>
</ul>

Ordered lists (<ol>) display items with numbers. Use them when sequence matters:

<h3>How to Drop Off Your Computer</h3>
<ol>
  <li>Bring your computer to our shop during business hours.</li>
  <li>Fill out the intake form at the front desk.</li>
  <li>Our technician will diagnose the issue within 24 hours.</li>
  <li>We will call you with a repair estimate.</li>
  <li>Pick up your repaired computer!</li>
</ol>

Description lists (<dl>) pair terms with descriptions. They are perfect for glossaries, FAQs, or metadata:

<dl>
  <dt>RAM</dt>
  <dd>Random Access Memory — temporary storage that your computer
  uses while running programs. More RAM means smoother multitasking.</dd>

  <dt>SSD</dt>
  <dd>Solid State Drive — a fast storage device with no moving parts.
  SSDs make your computer boot and load programs much faster than
  traditional hard drives.</dd>
</dl>

Links

Links are the backbone of the web — they connect pages together. The <a> (anchor) element creates a clickable link:

<!-- Link to another page on the same site -->
<a href="/services">View Our Services</a>

<!-- Link to an external website -->
<a href="https://google.com">Search on Google</a>

<!-- Link that opens in a new tab -->
<a href="https://google.com" target="_blank" rel="noopener noreferrer">
  Google (opens in new tab)
</a>

<!-- Email link -->
<a href="mailto:contact@computerstoreks.com">Email Us</a>

<!-- Phone link (great for mobile) -->
<a href="tel:+17855551234">Call Us: (785) 555-1234</a>

<!-- Link to a section on the same page -->
<a href="#services">Jump to Services</a>
...
<section id="services">...</section>
Security Note: rel="noopener noreferrer" When using target="_blank" to open links in a new tab, always add rel="noopener noreferrer". Without it, the opened page can access and potentially manipulate your page through a JavaScript property called window.opener. This is a known security vulnerability called "tabnapping."

Images

The <img> element embeds images in your page. It is a self-closing element with two required attributes:

<img
  src="/images/storefront.jpg"
  alt="The front entrance of Computer Store KS in Topeka, Kansas"
  width="800"
  height="600"
>
  • src — The source (path or URL) of the image file.
  • alt — Alternative text that describes the image. This is critical for accessibility (screen readers read it aloud), for SEO (search engines use it to understand images), and as a fallback (it displays when the image fails to load).
  • width and height — The dimensions of the image. Including these prevents layout shift (the page jumping around as images load).

Image Formats: When to Use Each

Format Best For Supports Transparency File Size
JPEG (.jpg) Photographs, complex images with many colors No Small to medium
PNG (.png) Graphics with sharp edges, screenshots, text overlays Yes Medium to large
SVG (.svg) Logos, icons, illustrations (vector graphics) Yes Very small
WebP (.webp) Modern replacement for JPEG and PNG — better compression Yes Smallest
GIF (.gif) Simple animations, very limited colors Yes (1 color only) Varies
SVG: The Scalable Vector SVG (Scalable Vector Graphics) is unique among image formats because it uses mathematical descriptions of shapes instead of pixels. This means SVGs look perfectly crisp at any size — whether displayed on a tiny phone or a massive billboard. They are ideal for logos, icons, and illustrations. SVG files are actually XML text files, which means you can open them in a text editor and modify them with code.
CSK Connection The Computer Store KS project uses SVG files for the company logo and icons (stored in public/assets/). Product photos in the gallery use optimized image formats. Next.js provides a built-in <Image> component (covered in Lesson 19) that automatically converts images to WebP format and generates multiple sizes for different screen widths, dramatically improving performance.

Writing Good Alt Text

Writing effective alt text is both an art and a responsibility. Here are guidelines:

<!-- Bad: Too vague -->
<img src="photo.jpg" alt="photo">
<img src="laptop.jpg" alt="image">

<!-- Bad: Too long and redundant -->
<img src="laptop.jpg" alt="This is an image of a laptop computer that is silver colored sitting on a desk">

<!-- Good: Descriptive and concise -->
<img src="laptop.jpg" alt="Silver laptop open on a wooden desk">

<!-- Decorative images (purely visual, no information) use empty alt -->
<img src="decorative-border.png" alt="">

Tables

HTML tables are designed for displaying tabular data — information that naturally fits into rows and columns, like pricing, schedules, or specifications. Never use tables for page layout (that is what CSS is for).

<table>
  <thead>
    <tr>
      <th>Service</th>
      <th>Price</th>
      <th>Turnaround</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Virus Removal</td>
      <td>$75</td>
      <td>1-2 days</td>
    </tr>
    <tr>
      <td>Screen Replacement</td>
      <td>$120</td>
      <td>2-3 days</td>
    </tr>
    <tr>
      <td>Full Diagnostic</td>
      <td>$45</td>
      <td>Same day</td>
    </tr>
  </tbody>
</table>
  • <table> — The table container.
  • <thead> — The header section (column labels).
  • <tbody> — The body section (data rows).
  • <tr> — A table row.
  • <th> — A header cell (bold and centered by default).
  • <td> — A data cell.

Forms: Collecting User Input

Forms are how users interact with web applications — logging in, submitting contact messages, creating accounts, searching, and configuring settings. The <form> element wraps all the input fields, and the action attribute tells the browser where to send the data when the form is submitted.

A Complete Contact Form Example

<form action="/api/contact" method="POST">
  <!-- Text Input -->
  <label for="name">Full Name</label>
  <input type="text" id="name" name="name" required
         placeholder="John Smith">

  <!-- Email Input -->
  <label for="email">Email Address</label>
  <input type="email" id="email" name="email" required
         placeholder="john@example.com">

  <!-- Phone Input -->
  <label for="phone">Phone Number</label>
  <input type="tel" id="phone" name="phone"
         placeholder="(785) 555-1234">

  <!-- Dropdown Select -->
  <label for="service">Service Needed</label>
  <select id="service" name="service">
    <option value="">-- Select a service --</option>
    <option value="repair">Computer Repair</option>
    <option value="virus">Virus Removal</option>
    <option value="custom">Custom Build</option>
    <option value="data">Data Recovery</option>
  </select>

  <!-- Textarea -->
  <label for="message">Your Message</label>
  <textarea id="message" name="message" rows="5"
            placeholder="Describe your issue..."></textarea>

  <!-- Submit Button -->
  <button type="submit">Send Message</button>
</form>

Checkboxes and Radio Buttons

<!-- Checkboxes: select multiple options -->
<fieldset>
  <legend>Issues you are experiencing:</legend>
  <label>
    <input type="checkbox" name="issues" value="slow">
    Computer is running slowly
  </label>
  <label>
    <input type="checkbox" name="issues" value="virus">
    Possible virus or malware
  </label>
  <label>
    <input type="checkbox" name="issues" value="noise">
    Unusual noises
  </label>
</fieldset>

<!-- Radio buttons: select exactly one option -->
<fieldset>
  <legend>Preferred contact method:</legend>
  <label>
    <input type="radio" name="contact" value="email" checked>
    Email
  </label>
  <label>
    <input type="radio" name="contact" value="phone">
    Phone
  </label>
  <label>
    <input type="radio" name="contact" value="text">
    Text Message
  </label>
</fieldset>
Labels and Accessibility Always associate a <label> with every form input using the for attribute (matching the input's id), or by wrapping the input inside the label. This is essential for accessibility: screen readers announce the label when the input receives focus, and clicking the label activates the input (making checkboxes and radio buttons much easier to use, especially on mobile).

Form Validation Attributes

HTML5 provides built-in validation that works without any JavaScript:

<!-- Required field -->
<input type="text" name="name" required>

<!-- Minimum and maximum length -->
<input type="text" name="username" minlength="3" maxlength="20">

<!-- Minimum and maximum number values -->
<input type="number" name="quantity" min="1" max="10">

<!-- Pattern matching with regular expressions -->
<input type="text" name="zipcode" pattern="[0-9]{5}"
       title="Five digit zip code">
CSK Connection The Computer Store KS contact page uses a form with text, email, and textarea inputs. The form sends data to the /api/contact API route, which validates the data server-side (using Zod schemas) and sends a notification email using Resend. The customer intake form in the admin portal (/admin/intake) uses a more complex multi-step form with many input types including select dropdowns and checkboxes.

Accessibility Basics

Web accessibility means designing and building websites that everyone can use, including people with disabilities. Approximately 15% of the world's population has some form of disability, including visual, auditory, motor, and cognitive impairments. Building accessible websites is not just good practice — in many countries, it is a legal requirement.

Screen Readers

A screen reader is software that reads web page content aloud for people who are blind or have low vision. Popular screen readers include NVDA (Windows, free), JAWS (Windows, paid), and VoiceOver (built into Mac and iOS). Screen readers rely heavily on proper HTML semantics to navigate and announce content.

ARIA Roles and Attributes

ARIA (Accessible Rich Internet Applications) is a set of attributes you can add to HTML elements to provide additional accessibility information. ARIA should be used as a supplement to semantic HTML, not a replacement for it.

<!-- ARIA role: tells screen readers this is a search form -->
<form role="search">
  <input type="text" aria-label="Search the site">
  <button type="submit">Search</button>
</form>

<!-- ARIA landmark: identifies the main navigation -->
<nav aria-label="Main navigation">
  <a href="/">Home</a>
  <a href="/services">Services</a>
</nav>

<!-- ARIA for dynamic content -->
<div role="alert" aria-live="polite">
  Your message has been sent successfully!
</div>

<!-- ARIA for custom controls -->
<button aria-expanded="false" aria-controls="menu">
  Menu
</button>
<div id="menu" hidden>...</div>

Keyboard Navigation

Many users navigate websites entirely with a keyboard (no mouse). Ensure your pages support this by:

  • Using native HTML elements (<a>, <button>, <input>) which are keyboard-accessible by default.
  • Maintaining visible focus indicators — the outline that appears when you Tab to an element. Never remove the focus outline with outline: none unless you provide an alternative focus style.
  • Ensuring a logical tab order that follows the visual layout of the page.
  • Providing a "skip to content" link at the top of the page so keyboard users can skip past the navigation.
<!-- Skip to content link (first element in body) -->
<a href="#main-content" class="skip-link">Skip to main content</a>

<header>
  <nav>...</nav>
</header>

<main id="main-content">
  ...
</main>
The First Rule of ARIA "If you can use a native HTML element or attribute with the semantics and behavior you require already built in, instead of re-purposing an element and adding an ARIA role, state or property to make it accessible, then do so." In other words: use semantic HTML first, ARIA second. A <button> is always better than a <div role="button">.

  3. Build a Service Menu Table: Create an HTML table listing at least five computer repair services with columns for Service Name, Description, Estimated Price, and Turnaround Time.
  4. Contact Form: Build a complete contact form with: name (text), email (email), phone (tel), a dropdown to select a service, a textarea for the message, a checkbox for "I agree to the terms," and a submit button. Make sure every input has a proper label.
  5. Image Gallery: Create a section with four images. Use appropriate alt text for each one. Include at least one example each of: a photograph (JPG), a screenshot (PNG), and a logo (SVG). If you do not have real images, use placeholder descriptions in the alt text and any test image URLs.
  6. Accessibility Audit: Visit any website, open Developer Tools, and examine the HTML. List three things the site does well for accessibility and three things it could improve. Look for: semantic elements, alt text on images, labels on form inputs, heading hierarchy, and ARIA attributes.

Key Takeaways

  • HTML is the markup language that gives web content structure and meaning. Every web page is built on HTML.
  • Every HTML document needs a DOCTYPE declaration, an html element with a lang attribute, a head section (with charset, viewport, and title), and a body section.
  • Semantic elements (header, nav, main, section, article, aside, footer) communicate meaning to browsers, screen readers, and search engines.
  • Headings (h1-h6) create a content hierarchy. Use one h1 per page and never skip levels.
  • Images require both a src attribute (the file path) and an alt attribute (a text description). Choose the right image format for the content type.
  • Forms use input elements with specific types (text, email, password, number, checkbox, radio, etc.) to collect user data. Always associate labels with inputs for accessibility.
  • Accessibility is not optional. Use semantic HTML, provide alt text, support keyboard navigation, and use ARIA attributes when native semantics are insufficient.
