Phase 4: Next.js

Image Optimization & Static Assets

Serve images that load fast, look sharp, and do not tank your Core Web Vitals score.

What You Will Learn

  • Understand how the public/ directory serves static files
  • Use the Next.js Image component and know why it exists
  • Configure required and optional props: src, alt, width, height, priority, quality
  • Handle local images vs. remote images and configure remotePatterns
  • Work with SVGs correctly and avoid common cross-browser gotchas
  • Choose the right image format for each use case
  • Optimize LCP (Largest Contentful Paint) with the priority prop

The public/ Directory

The public/ directory in your Next.js project serves static files directly to the browser. Any file you put in public/ is accessible at the root URL:

public/
├── images/
│   ├── logo.png          # Accessible at: /images/logo.png
│   ├── hero-banner.jpg   # Accessible at: /images/hero-banner.jpg
│   └── icons/
│       └── phone.svg     # Accessible at: /images/icons/phone.svg
├── robots.txt            # Accessible at: /robots.txt
├── sitemap.xml           # Accessible at: /sitemap.xml
└── favicon.ico           # Accessible at: /favicon.ico

Files in public/ are:

  • Not processed by webpack or Next.js -- they are served as-is
  • Cached by the browser -- no automatic cache-busting
  • Available at build time and runtime -- they do not change based on environment
Do not put sensitive files in public/! Everything in this directory is publicly accessible to anyone who knows the URL. Never place API keys, configuration files with secrets, or private data here.

The Next.js Image Component

The <Image> component from next/image is one of the most impactful features Next.js provides. It replaces the standard HTML <img> tag with a version that automatically:

  • Optimizes file size: Converts images to modern formats (WebP, AVIF) automatically
  • Serves responsive sizes: Generates multiple sizes and serves the right one for the device
  • Lazy loads: Only loads images when they scroll into the viewport
  • Prevents layout shift: Reserves space before the image loads (no content jumping)
  • Caches aggressively: Optimized images are cached for repeat visits

Basic Usage

import Image from 'next/image';

export default function HomePage() {
  return (
    <div>
      <Image
        src="/images/hero-banner.jpg"
        alt="Computer repair workbench with tools and components"
        width={1200}
        height={600}
      />
    </div>
  );
}

Required Props

Prop Type Purpose
src string or StaticImport Path to the image (local or remote URL)
alt string Descriptive text for accessibility and SEO. Never leave empty unless purely decorative.
width number Rendered width in pixels (used to calculate aspect ratio)
height number Rendered height in pixels (used to calculate aspect ratio)
Width and Height Are Not Display Size: The width and height props define the intrinsic dimensions of the image -- the aspect ratio. CSS controls the actual display size. Setting width={1200} height={600} does not force the image to be 1200px wide; it tells Next.js the image has a 2:1 aspect ratio so it can reserve the correct space.

Important Optional Props

// Hero image -- loads immediately, does not lazy-load
<Image
  src="/images/hero-banner.jpg"
  alt="Hero banner"
  width={1200}
  height={600}
  priority          // Loads immediately (above the fold)
/>

// Thumbnail -- lower quality is fine
<Image
  src="/images/thumbnail.jpg"
  alt="Product thumbnail"
  width={300}
  height={200}
  quality={75}      // 0-100, default is 75
/>

// Blurred placeholder while loading
<Image
  src="/images/gallery-photo.jpg"
  alt="Gallery photo"
  width={800}
  height={600}
  placeholder="blur"
  blurDataURL="data:image/jpeg;base64,/9j/4AAQ..."  // Tiny base64 blur
/>

// Fill the parent container (no width/height needed)
<div style={{ position: 'relative', width: '100%', height: '400px' }}>
  <Image
    src="/images/background.jpg"
    alt="Background"
    fill                    // Fills the parent container
    style={{ objectFit: 'cover' }}
  />
</div>
Prop Default Purpose
priority false Disables lazy loading; preloads the image. Use for LCP images (hero, logo).
quality 75 Image quality 1-100. Lower = smaller file = faster load.
placeholder "empty" Show a blur preview while loading. Options: "blur", "empty".
fill false Image fills its parent container. Requires parent to have position: relative.
sizes "100vw" Responsive size hints for the browser. Important for fill images.

Local vs. Remote Images

Local Images (from public/ or imported)

Local images can be referenced by path or imported directly:

// Method 1: Path from public/ directory
<Image src="/images/logo.png" alt="Logo" width={200} height={50} />

// Method 2: Import (recommended for static images)
import heroImage from '@/public/images/hero.jpg';

<Image
  src={heroImage}
  alt="Hero banner"
  // width and height are auto-detected from the imported file!
  placeholder="blur"  // blur placeholder auto-generated for imports!
/>

Importing images is the preferred approach because Next.js automatically:

  • Detects width and height (no need to specify them)
  • Generates a blur placeholder (no manual blurDataURL)
  • Adds content hashing for cache-busting

Remote Images (from external URLs)

For images hosted on external servers (Supabase Storage, GitHub, a CDN), you must configure remotePatterns in next.config.mjs:

// next.config.mjs
const nextConfig = {
  images: {
    remotePatterns: [
      {
        protocol: 'https',
        hostname: 'your-project.supabase.co',
        pathname: '/storage/v1/object/public/**',
      },
      {
        protocol: 'https',
        hostname: 'raw.githubusercontent.com',
        pathname: '/YourUser/YourRepo/**',
      },
    ],
  },
};

export default nextConfig;

Then use remote URLs in your Image component:

<Image
  src="https://your-project.supabase.co/storage/v1/object/public/gallery/photo1.jpg"
  alt="Gallery photo"
  width={800}
  height={600}
/>
Security Warning: Never set hostname: '**' (wildcard all domains) in production. This allows any external domain to serve images through your Next.js optimization pipeline, which malicious actors could abuse to overload your server. Always list specific, trusted domains.
CSK Connection CSK's next.config.mjs configures remotePatterns to allow images from any HTTPS source (used during development with multiple image sources). In production, you would tighten this to only allow Supabase Storage and GitHub raw URLs. The hero logo on the homepage uses the priority prop to load immediately for a fast LCP score. Gallery computer images use automatic optimization for responsive sizing.

SVG Handling

SVGs (Scalable Vector Graphics) are different from raster images (PNG, JPG, WebP). They are XML-based vector files that scale to any size without losing quality. However, they require special handling in Next.js.

When to Use Each Approach

Approach When to Use Pros Cons
Image component Simple display, no styling needed Consistent with other images, lazy loading Cannot style individual SVG elements
Inline SVG Need to change colors, animate, or interact Full CSS/JS control, no extra request Adds to HTML size, no lazy loading
<img> tag Simple display without optimization needs Simplest approach No Next.js optimization benefits

Using the Image Component with SVGs

import Image from 'next/image';

// Works fine for displaying SVGs
<Image
  src="/images/icons/phone.svg"
  alt="Phone icon"
  width={24}
  height={24}
/>

Inline SVG for Styling Control

// When you need to change colors with CSS
export default function PhoneIcon({ className }: { className?: string }) {
  return (
    <svg
      xmlns="http://www.w3.org/2000/svg"
      viewBox="0 0 24 24"
      fill="currentColor"
      className={className}
      width={24}
      height={24}
    >
      <path d="M6.62 10.79c1.44 2.83 3.76 5.14 6.59 6.59l2.2-2.2..." />
    </svg>
  );
}

// Usage -- color changes with text color
<PhoneIcon className="text-blue-500" />
<PhoneIcon className="text-red-500" />

The Firefox SVG Gotcha

Critical Cross-Browser Issue: Firefox requires explicit width and height attributes on SVG elements. Without them, SVGs in Firefox may render at zero size or collapse entirely. Chrome and Safari are more forgiving, which makes this bug easy to miss during development. 
// BAD: May not render in Firefox!
<svg viewBox="0 0 24 24">
  <path d="..." />
</svg>

// GOOD: Explicit dimensions -- works in all browsers
<svg viewBox="0 0 24 24" width="24" height="24">
  <path d="..." />
</svg>

// ALSO GOOD: CSS dimensions with explicit SVG attributes
<svg viewBox="0 0 24 24" width="24" height="24" className="w-6 h-6">
  <path d="..." />
</svg>

The rule is simple: always include width and height attributes on your SVG elements, even if you also use CSS for sizing.

Image Format Guide

Choosing the right format for each image type is essential for performance:

Format Best For Transparency? File Size
WebP Photos, complex images (modern default) Yes 25-35% smaller than JPEG
AVIF Photos (best compression, newer) Yes 50% smaller than JPEG
JPEG Photos, gradients (universal fallback) No Baseline reference
PNG Screenshots, text, sharp edges, transparency Yes Larger than JPEG for photos
SVG Icons, logos, illustrations, diagrams Yes Tiny (vector, scales infinitely)
GIF Simple animations (avoid for photos) Yes (1-bit) Large for quality
Next.js Auto-Converts: When you use the Image component, Next.js automatically converts JPEG and PNG images to WebP (or AVIF) format when the browser supports it. You do not need to manually convert your images -- just provide the original file and let Next.js handle the optimization.

The Sharp Library

Under the hood, Next.js uses a library called sharp for server-side image processing. Sharp is a high-performance Node.js module for resizing, cropping, and converting images.

Next.js installs sharp automatically when you run npm install (it is a peer dependency). However, sometimes you need to install it explicitly, especially on deployment platforms:

# Install sharp explicitly if needed
npm install sharp

Sharp handles:

  • Resizing images to the requested dimensions
  • Converting between formats (JPEG to WebP, PNG to AVIF)
  • Applying quality settings
  • Generating blur placeholders

You typically never interact with sharp directly -- Next.js uses it behind the scenes. But knowing it exists helps you debug build issues on platforms like Render, where you might see errors like "sharp not found."

Performance: LCP Optimization

LCP (Largest Contentful Paint) is a Core Web Vital that measures how quickly the largest visible element loads. For most pages, the LCP element is an image -- typically the hero banner or main product photo.

The priority Prop

By default, Next.js lazy-loads all images (only loading them when they scroll into view). This is great for below-the-fold images, but terrible for the hero image that users see first. The priority prop disables lazy loading and tells the browser to preload the image:

// Hero section -- the first thing users see
<Image
  src="/images/hero-banner.jpg"
  alt="Computer Store KS storefront"
  width={1200}
  height={600}
  priority      // Preloads this image immediately
/>

When to Use priority

  • The hero image or banner at the top of the page
  • The site logo (if it is the LCP element)
  • The main product image on a product detail page
  • Any image that is visible without scrolling (above the fold)
Only Use priority on 1-2 Images Per Page. Setting priority on too many images defeats the purpose -- the browser cannot prioritize everything. Identify the single most important image on the page and give it priority.

The sizes Prop for Responsive Images

When using fill or when an image displays at different sizes on different screen widths, the sizes prop tells the browser which size to download:

// Image takes full width on mobile, half on tablet, third on desktop
<Image
  src="/images/gallery-photo.jpg"
  alt="Gallery photo"
  fill
  sizes="(max-width: 640px) 100vw, (max-width: 1024px) 50vw, 33vw"
/>

Without the sizes prop, the browser might download a much larger image than needed, wasting bandwidth on mobile devices.

CSK Connection The Computer Store KS homepage hero section uses <Image priority /> for the main logo and banner to achieve a fast LCP score. Gallery images use automatic optimization without priority (they are below the fold and lazy-loaded). The next.config.mjs allows remote images from Supabase Storage and GitHub. Sharp handles all server-side image processing for the gallery system's uploaded computer photos.

Exercises

  1. Public directory setup: Create a public/images/ folder. Add a hero image, a logo, and a few gallery images. Verify you can access them directly at localhost:3000/images/filename.jpg.
  2. Replace img with Image: Take any page that uses HTML <img> tags and replace them with the Next.js <Image> component. Check DevTools Network tab to see that images are now served as WebP.
  3. Configure remote images: Add a remotePatterns configuration in next.config.mjs for Unsplash (images.unsplash.com). Display a remote image using the Image component.
  4. LCP optimization: Use the Chrome Lighthouse tool (DevTools > Lighthouse tab) to measure your page's LCP. Add the priority prop to the hero image and re-measure. Note the improvement.
  5. SVG cross-browser test: Create an inline SVG icon without width and height attributes. Test in Chrome and Firefox. Observe the Firefox rendering issue, then fix it by adding explicit dimensions.
  6. Responsive image gallery: Build a 3-column image grid that becomes 2 columns on tablet and 1 column on mobile. Use the fill prop with proper sizes values. Test at different viewport widths.

Key Takeaways

  • The public/ directory serves static files at the root URL. Never put sensitive data here.
  • The Next.js Image component automatically optimizes images: format conversion, responsive sizing, lazy loading, and layout shift prevention.
  • Required props are src, alt, width, and height (or use fill instead of width/height).
  • Use priority on the hero/LCP image (1-2 per page) and quality to control file size vs. clarity tradeoff.
  • Remote images require remotePatterns configuration in next.config.mjs. List specific trusted domains.
  • SVGs need explicit width and height attributes for Firefox compatibility. Use inline SVGs when you need CSS styling control.
  • Choose WebP/AVIF for photos, PNG for screenshots and transparency, SVG for icons and logos.
  • Sharp handles server-side image processing under the hood. Next.js auto-converts to optimal formats.
