Phase 4: Next.js

Next.js App Router & File-Based Routing

Turn your React skills into full-stack power with automatic routing, layouts, and the file system as your API.

What You Will Learn

  • Understand what Next.js adds on top of React and why it matters
  • Create a Next.js project from scratch with create-next-app
  • Navigate the src/app/ directory structure confidently
  • Build routes using page.tsx and shared layouts with layout.tsx
  • Use route groups, dynamic routes, and special files like loading.tsx and error.tsx
  • Handle client-side navigation with the Link component and router hooks
  • Build a complete multi-page website with nested layouts

Why Next.js? What React Alone Cannot Do

You have spent the last three lessons learning React -- components, hooks, state, and patterns. React is incredibly powerful at building user interfaces, but it is only a UI library. It does not have opinions about how to handle routing, server rendering, data fetching, or deployment. That is where Next.js enters the picture.

Next.js is a full-stack React framework built by Vercel. It takes React and wraps it with everything you need to build a production website:

Feature React Alone Next.js
Routing Install react-router, configure manually Automatic from file system
Server Rendering Complex setup with Express/Node Built-in, on by default
API Endpoints Separate backend server needed Built-in via route.ts files
Image Optimization Manual, or use third-party tools Automatic with <Image>
SEO / Metadata Manual <head> management Built-in metadata API
Code Splitting Manual with React.lazy Automatic per route
Deployment Configure bundler, server, CDN Single build command, deploy anywhere
Analogy: If React is a powerful engine, Next.js is the entire car -- engine, transmission, steering, fuel system, and body all assembled and ready to drive.

The App Router vs. the Pages Router

Next.js has two routing systems. The older Pages Router (pages/ directory) has been around since 2016. The newer App Router (app/ directory) was introduced in Next.js 13 and is now the recommended approach. This lesson teaches the App Router exclusively because:

  • It supports React Server Components (a game-changer for performance)
  • It has a more intuitive nested layout system
  • It supports streaming and loading states natively
  • It is the future of Next.js -- all new features target the App Router
CSK Connection Computer Store KS uses Next.js 14 with the App Router. Every page you see on computerstoreks.com -- the homepage, services pages, blog, admin dashboard -- is built with the patterns taught in this lesson.

Creating Your First Next.js Project

Next.js provides a scaffolding tool called create-next-app that sets up everything for you. Open your terminal and run:

npx create-next-app@latest my-website

The installer will ask you a series of questions. Here are the recommended answers for this curriculum:

Would you like to use TypeScript?             Yes
Would you like to use ESLint?                  Yes
Would you like to use Tailwind CSS?            Yes
Would you like your code inside a `src/` directory?  Yes
Would you like to use App Router?              Yes
Would you like to use Turbopack for next dev?  Yes
Would you like to customize the import alias?  No (keep @/*)

Once finished, move into the project and start the development server:

cd my-website
npm run dev

Open http://localhost:3000 in your browser. You should see the default Next.js welcome page. Congratulations -- you have a running full-stack application.

The src/app/ Directory -- Your Application Lives Here

The src/app/ directory is the heart of the App Router. The folder structure inside app/ directly maps to the URL structure of your website. This is called file-based routing -- instead of writing routing configuration, you create folders and files, and Next.js generates routes automatically.

Two file names have special meaning:

File Name Purpose Required?
page.tsx Makes a folder into a route (the page users see) Yes, for any folder that should be a URL
layout.tsx Shared wrapper UI (header, sidebar, footer) Required at root; optional in nested folders
Key Rule: A folder only becomes a URL route if it contains a page.tsx file. If a folder has no page.tsx, it is just a grouping mechanism -- it will not match any URL.

page.tsx -- Defining Routes

Every page.tsx file exports a default React component that Next.js renders when a user visits that route. The URL is determined by the folder path relative to src/app/.

// src/app/page.tsx
// This renders at URL: /

export default function HomePage() {
  return (
    <main>
      <h1>Welcome to My Website</h1>
      <p>This is the homepage.</p>
    </main>
  );
}

To create an About page at /about, create a folder and add a page.tsx:

// src/app/about/page.tsx
// This renders at URL: /about

export default function AboutPage() {
  return (
    <main>
      <h1>About Us</h1>
      <p>We build websites for local businesses.</p>
    </main>
  );
}

The mapping is straightforward:

File Path URL
src/app/page.tsx/
src/app/about/page.tsx/about
src/app/contact/page.tsx/contact
src/app/services/page.tsx/services
src/app/services/web-design/page.tsx/services/web-design

layout.tsx -- Shared Wrappers

A layout.tsx file wraps the content of its folder and all child folders. The root layout (src/app/layout.tsx) wraps every page in your application. It is the only place where you define the <html> and <body> tags.

// src/app/layout.tsx -- ROOT layout (required)
import './globals.css';

export const metadata = {
  title: 'My Website',
  description: 'A website built with Next.js',
};

export default function RootLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <html lang="en">
      <body>
        <header>
          <nav>
            <a href="/">Home</a>
            <a href="/about">About</a>
            <a href="/contact">Contact</a>
          </nav>
        </header>
        <main>{children}</main>
        <footer>
          <p>Copyright 2026 My Website</p>
        </footer>
      </body>
    </html>
  );
}

The {children} prop is where Next.js injects the current page content. When a user visits /about, the AboutPage component is rendered inside this layout where {children} appears.

Nested Layouts

You can create additional layouts inside any folder. They nest inside the parent layout, creating a hierarchy:

// src/app/admin/layout.tsx -- Layout for ALL /admin/* pages

export default function AdminLayout({
  children,
}: {
  children: React.ReactNode;
}) {
  return (
    <div className="admin-container">
      <aside className="sidebar">
        <h2>Admin Panel</h2>
        <nav>
          <a href="/admin">Dashboard</a>
          <a href="/admin/blog">Blog Posts</a>
          <a href="/admin/gallery">Gallery</a>
        </nav>
      </aside>
      <div className="admin-content">
        {children}
      </div>
    </div>
  );
}

When visiting /admin/blog, the rendering nests like this:

Root Layout (html, body, header, footer) └── Admin Layout (sidebar + content area) └── Blog Page (the actual page content)
Layout Persistence: Layouts do not re-render when navigating between pages within the same layout. If a user clicks from /admin/blog to /admin/gallery, only the page content changes -- the admin sidebar stays mounted, preserving any state (like scroll position or open menus).

Route Groups with Parentheses

Sometimes you want to organize files into folders without creating a new URL segment. Route groups solve this. Wrap a folder name in parentheses, and it is excluded from the URL.

src/app/
├── (public)/            # Route group -- does NOT appear in URL
│   ├── page.tsx         # URL: /
│   ├── about/
│   │   └── page.tsx     # URL: /about
│   ├── contact/
│   │   └── page.tsx     # URL: /contact
│   └── layout.tsx       # Layout for public pages only
├── admin/               # Regular folder -- DOES appear in URL
│   ├── page.tsx         # URL: /admin
│   ├── blog/
│   │   └── page.tsx     # URL: /admin/blog
│   └── layout.tsx       # Admin layout with sidebar
└── layout.tsx           # Root layout (wraps everything)

Notice that (public) is in parentheses. The page at src/app/(public)/about/page.tsx is accessible at /about -- not /public/about. The parentheses tell Next.js "this folder is for organization only."

Why Use Route Groups?

  • Different layouts: Public pages might have a header and footer, while admin pages have a sidebar. Route groups let you assign different layouts to different sections.
  • Code organization: Group related routes together without polluting the URL structure.
  • Team separation: Different developers can work in different route groups without merge conflicts.
CSK Connection Computer Store KS uses route groups extensively. The (public) group contains all customer-facing pages (homepage, about, services, blog, contact, gallery, reviews). The admin folder (no parentheses) is a regular route at /admin for the employee portal. This separation means public pages use a customer-friendly layout with a header and footer, while admin pages use a sidebar navigation layout.

Dynamic Routes: [slug] and [id]

Many pages share the same layout but display different data: individual blog posts, product pages, user profiles. Instead of creating a separate folder for every possible URL, you use dynamic route segments by wrapping the folder name in square brackets.

src/app/blog/
├── page.tsx              # URL: /blog       (blog listing)
└── [slug]/
    └── page.tsx          # URL: /blog/anything-here  (individual post)

The [slug] folder matches any value in that URL position. When a user visits /blog/how-to-build-a-pc, Next.js renders the page.tsx inside [slug]/ and passes the matched value as a parameter.

// src/app/blog/[slug]/page.tsx

interface BlogPostPageProps {
  params: {
    slug: string;
  };
}

export default function BlogPostPage({ params }: BlogPostPageProps) {
  // If URL is /blog/how-to-build-a-pc
  // then params.slug === "how-to-build-a-pc"

  return (
    <article>
      <h1>Blog Post: {params.slug}</h1>
      <p>In a real app, you would fetch the post data using this slug.</p>
    </article>
  );
}

Multiple Dynamic Segments

You can have multiple dynamic segments in a path:

src/app/shop/[category]/[productId]/page.tsx
// URL: /shop/laptops/dell-inspiron-15
// params.category    === "laptops"
// params.productId   === "dell-inspiron-15"

Catch-All Routes with [...slug]

For routes that need to match an arbitrary number of segments, use the spread syntax:

src/app/docs/[...slug]/page.tsx
// URL: /docs/getting-started          → params.slug = ["getting-started"]
// URL: /docs/api/authentication        → params.slug = ["api", "authentication"]
// URL: /docs/api/auth/sessions/create  → params.slug = ["api", "auth", "sessions", "create"]
CSK Connection CSK uses dynamic routes for blog posts at /blog/[slug] (e.g., /blog/how-to-speed-up-your-pc) and for ticket detail pages in the admin area at /admin/tickets/[id] (e.g., /admin/tickets/12345).

Special Files: loading, error, and not-found

Next.js reserves several file names for handling common scenarios. These files are optional but extremely useful:

loading.tsx -- Loading States

Place a loading.tsx file in any folder, and Next.js will show it while the page is loading (during data fetching or code splitting). It works automatically with React Suspense under the hood.

// src/app/blog/loading.tsx

export default function BlogLoading() {
  return (
    <div className="loading-container">
      <div className="spinner"></div>
      <p>Loading blog posts...</p>
    </div>
  );
}

error.tsx -- Error Boundaries

An error.tsx file catches errors that happen in its folder's page or any child pages. It acts as a React Error Boundary and must be a Client Component.

// src/app/blog/error.tsx
'use client'; // Error components MUST be Client Components

export default function BlogError({
  error,
  reset,
}: {
  error: Error & { digest?: string };
  reset: () => void;
}) {
  return (
    <div className="error-container">
      <h2>Something went wrong!</h2>
      <p>{error.message}</p>
      <button onClick={() => reset()}>Try Again</button>
    </div>
  );
}

not-found.tsx -- 404 Pages

A not-found.tsx file renders when a page is not found. You can place one at the root level for a global 404 page, or in specific folders for targeted not-found experiences.

// src/app/not-found.tsx

export default function NotFound() {
  return (
    <div className="not-found">
      <h1>404 - Page Not Found</h1>
      <p>The page you are looking for does not exist.</p>
      <a href="/">Go back to the homepage</a>
    </div>
  );
}

You can trigger the not-found page programmatically with the notFound() function:

// src/app/blog/[slug]/page.tsx
import { notFound } from 'next/navigation';

export default async function BlogPostPage({ params }: { params: { slug: string } }) {
  const post = await getPostBySlug(params.slug);

  if (!post) {
    notFound(); // Renders the nearest not-found.tsx
  }

  return <article>{/* render post */}</article>;
}

Summary of Special Files

File Purpose Must Be Client Component?
page.tsxThe page content for a routeNo
layout.tsxShared UI wrapperNo
loading.tsxLoading skeleton / spinnerNo
error.tsxError boundaryYes
not-found.tsx404 fallbackNo
template.tsxLike layout but re-renders on navigationNo

Client-Side Navigation

The Link Component

In React, navigating between pages with plain <a> tags causes a full page reload. Next.js provides the Link component for client-side navigation -- the browser swaps only the content that changed, without reloading the entire page. This makes navigation instant.

import Link from 'next/link';

export default function Navigation() {
  return (
    <nav>
      <Link href="/">Home</Link>
      <Link href="/about">About</Link>
      <Link href="/services">Services</Link>
      <Link href="/blog">Blog</Link>
      <Link href="/contact">Contact</Link>
    </nav>
  );
}

Link also prefetches pages that are visible in the viewport. When a user hovers over a link (or it scrolls into view), Next.js starts loading that page in the background. By the time they click, the navigation is nearly instantaneous.

Dynamic Link Targets

// Linking to a dynamic route
<Link href={`/blog/${post.slug}`}>
  {post.title}
</Link>

// Linking to an admin route with a ticket ID
<Link href={`/admin/tickets/${ticket.id}`}>
  Ticket #{ticket.id}
</Link>

useRouter() Hook -- Programmatic Navigation

Sometimes you need to navigate in response to an event (like a form submission or button click) rather than a link click. The useRouter hook from next/navigation lets you do this.

'use client';

import { useRouter } from 'next/navigation';

export default function LoginForm() {
  const router = useRouter();

  async function handleSubmit(e: React.FormEvent) {
    e.preventDefault();
    const success = await loginUser(/* ... */);

    if (success) {
      router.push('/admin');       // Navigate to /admin
    }
  }

  return (
    <form onSubmit={handleSubmit}>
      {/* form fields */}
      <button type="submit">Log In</button>
    </form>
  );
}

Key useRouter() methods:

Method What It Does
router.push('/path')Navigate to a new page (adds to history)
router.replace('/path')Navigate without adding to history (like redirect)
router.back()Go back one page in browser history
router.refresh()Re-fetch the current page data from the server
Important: useRouter() requires the 'use client' directive because it uses browser-side state. You cannot use it in Server Components. We will cover this distinction thoroughly in Lesson 16.

usePathname() Hook -- Know Where You Are

The usePathname() hook returns the current URL pathname. It is useful for highlighting the active navigation link:

'use client';

import Link from 'next/link';
import { usePathname } from 'next/navigation';

export default function Navigation() {
  const pathname = usePathname();

  const links = [
    { href: '/', label: 'Home' },
    { href: '/about', label: 'About' },
    { href: '/services', label: 'Services' },
    { href: '/contact', label: 'Contact' },
  ];

  return (
    <nav>
      {links.map(link => (
        <Link
          key={link.href}
          href={link.href}
          className={pathname === link.href ? 'active' : ''}
        >
          {link.label}
        </Link>
      ))}
    </nav>
  );
}

Parallel Routes (Advanced Concept)

Parallel routes let you render multiple pages simultaneously in the same layout. They use the @folder naming convention (a folder name starting with @).

src/app/admin/
├── layout.tsx
├── page.tsx
├── @dashboard/
│   └── page.tsx
└── @notifications/
    └── page.tsx

In the layout, each parallel route becomes a named prop:

// src/app/admin/layout.tsx
export default function AdminLayout({
  children,
  dashboard,
  notifications,
}: {
  children: React.ReactNode;
  dashboard: React.ReactNode;
  notifications: React.ReactNode;
}) {
  return (
    <div className="admin-grid">
      <main>{children}</main>
      <aside>{dashboard}</aside>
      <aside>{notifications}</aside>
    </div>
  );
}

Parallel routes are an advanced feature. They are useful for dashboard UIs where multiple sections load independently, but you will not need them for most websites. The important thing is to know they exist for when your requirements grow.

  5. Use usePathname for active nav: Convert your navigation into a Client Component that highlights the currently active link using usePathname().
  6. Route groups challenge: Reorganize your pages so that all public pages live inside a (public) route group, and create a basic admin/page.tsx at /admin. Verify that the route group does not affect URLs.

Key Takeaways

  • Next.js turns React into a full-stack framework with routing, server rendering, API routes, and optimization built in.
  • The App Router uses file-based routing: the folder structure inside src/app/ maps directly to your URL structure.
  • page.tsx makes a folder a route; layout.tsx wraps pages in shared UI like headers and sidebars.
  • Route groups (parentheses) organize code without affecting URLs.
  • Dynamic routes [slug] match variable URL segments and pass them as props.
  • Special files (loading.tsx, error.tsx, not-found.tsx) handle common UI states automatically.
  • The Link component enables fast client-side navigation with automatic prefetching.
  • useRouter() provides programmatic navigation, while usePathname() tells you the current URL.
