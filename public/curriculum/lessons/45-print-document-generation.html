Why Generate Print Documents from the Web?

In many businesses, there are documents that need to exist on paper: invoices handed to customers, promotional flyers posted on bulletin boards, receipts, shipping labels, and reports. The traditional approach is to create these documents in Word or a design tool like Canva, but this has significant drawbacks. The data is disconnected from your application, so every time prices change or inventory updates, someone has to manually update the document. This leads to errors, outdated information, and wasted time.

A better approach is to generate these documents directly from your web application. The data is always current because it comes from the same database that powers the website. The design is consistent because it is defined in CSS. And the process is automated: click a button, and the document is ready to print.

CSS has a built-in mechanism for this: print media queries. When the user prints a web page (or saves it as PDF), the browser applies special CSS rules that control exactly what appears on paper and how it looks. You can hide navigation, change fonts, adjust spacing, set page sizes, and control where page breaks fall. The result is a document that looks nothing like the screen version — it looks like a professionally designed print piece.

Analogy: Think about how a theater production has different lighting for different scenes. The same stage exists, but the lighting designer can make it look warm and cozy for a living room scene or cold and stark for a prison scene. CSS print styles are the lighting designer for your web page: same content, completely different presentation depending on whether the "audience" is a screen or a printer.
CSK Connection Computer Store KS uses a flyer generator (flyer-generator.ts) that creates print-ready promotional flyers. The flyer pulls current gallery data (computer names, specs, prices) and promotion information, formats them into an 8.5" x 11" layout with CSS print styles, and produces a document ready for the shop to print and display. When inventory or prices change, the flyer updates automatically.

Understanding @media print

You are already familiar with media queries from responsive design: @media (max-width: 768px) applies styles when the screen is narrow. The @media print query works the same way, but it activates when the page is being printed or saved as PDF. Any CSS rules inside a @media print block are completely ignored during normal screen viewing and only take effect during printing.

Basic Syntax

/* These styles ONLY apply when printing */
@media print {
  /* Hide elements that should not appear on paper */
  nav, footer, .sidebar, .ads {
    display: none !important;
  }

  /* Make the body full-width (no max-width constraint) */
  body {
    max-width: 100%;
    margin: 0;
    padding: 0;
  }

  /* Use a serif font for better readability on paper */
  body {
    font-family: 'Georgia', 'Times New Roman', serif;
    font-size: 12pt;
    line-height: 1.5;
    color: #000;
  }

  /* Remove background colors (saves ink) */
  * {
    background: white !important;
    color: black !important;
  }
}

When you press Ctrl+P (or Cmd+P on Mac) on a page with these styles, the browser hides the navigation, footer, sidebar, and ads. The text switches to a serif font at 12pt (a standard size for printed documents), and all backgrounds become white to save ink. The user sees this in the print preview and on the printed page, but the screen version is completely unaffected.

How Browsers Apply Print Styles

The browser applies styles in this order during printing:

  1. All normal stylesheets (without any media query, or with @media screen) are applied first
  2. Then @media print rules override on top
  3. Then the browser's own print stylesheet adjusts some defaults

This means your print styles build on top of your regular styles. You do not need to re-declare everything — just override what needs to change for paper.

Linking a Separate Print Stylesheet Instead of using @media print inside your main CSS file, you can link a completely separate stylesheet that only loads for printing: 
<link rel="stylesheet" href="styles.css">
<link rel="stylesheet" href="print.css" media="print">
The media="print" attribute tells the browser to only apply print.css when printing. This keeps your screen and print styles cleanly separated.

The @page Rule: Controlling Paper

The @page rule controls the physical properties of the printed page: paper size, margins, and orientation. These properties do not exist in screen CSS because screens do not have physical dimensions. But when printing, they are essential for ensuring your document fits the paper correctly.

Setting Page Size

@media print {
  @page {
    /* US Letter (standard American paper) */
    size: 8.5in 11in;

    /* Margins on all sides */
    margin: 0.75in;
  }
}

/* Alternative sizes */
@page {
  size: A4;              /* International standard (210mm x 297mm) */
}

@page {
  size: 8.5in 11in landscape;  /* Landscape orientation */
}

@page {
  size: 5.5in 8.5in;    /* Half letter (for booklets) */
}

The size property sets the paper dimensions. 8.5in 11in is standard US Letter paper. A4 is the international standard used in most other countries. Adding landscape rotates the orientation so the long edge is horizontal.

Custom Margins Per Page

@page {
  margin: 0.75in 1in;  /* top/bottom: 0.75in, left/right: 1in */
}

/* First page can have different margins */
@page :first {
  margin-top: 1.5in;   /* Extra space at top for letterhead */
}

/* Left pages (for double-sided printing) */
@page :left {
  margin-left: 1.25in;  /* Extra space for binding */
  margin-right: 0.75in;
}

/* Right pages */
@page :right {
  margin-left: 0.75in;
  margin-right: 1.25in;
}

The :first, :left, and :right pseudo-classes let you customize margins for specific pages. This is useful for documents with cover pages, headers, or binding margins.

Print-Specific Typography

Screen typography and print typography have different best practices. What looks good on a backlit display at arm's length does not necessarily look good on paper at reading distance.

Font Choices

Property Screen Print Why
Font family Sans-serif (Arial, system-ui) Serif (Georgia, Times) for body; sans-serif for headings Serifs guide the eye along printed lines; screens render sans-serif more clearly at low resolution
Font size 16px (1rem) 11pt–12pt Print uses points (pt), not pixels. 12pt is the standard for readable body text
Line height 1.5–1.7 1.3–1.5 Print can use tighter leading because paper has higher contrast than screens
Color Dark gray (#333) Pure black (#000) On paper, black ink is standard; gray looks faded
Link styling Blue, underlined Black, underlined, with URL shown Blue does not exist on a black-and-white printer; showing the URL lets readers visit the link

Revealing URLs in Print

On screen, a link like click here makes sense because the user can click it. On paper, the link text is meaningless without the actual URL. CSS can automatically show URLs after links in printed output:

@media print {
  a[href]::after {
    content: ' (' attr(href) ')';
    font-size: 0.85em;
    color: #555;
  }

  /* Do not show URLs for internal links or anchors */
  a[href^="#"]::after,
  a[href^="/"]::after {
    content: '';
  }
}

This generates output like: "Visit our website (https://computerstoreks.com)" on the printed page. The ::after pseudo-element appends the URL in parentheses after the link text. Internal links (starting with # or /) are excluded because they are only meaningful within the web application.

Controlling Page Breaks

When a document is longer than one page, the browser decides where to break the content across pages. Sometimes this results in awkward breaks: a heading at the bottom of a page with its content on the next page, or a table split in the middle. CSS page break properties let you control where breaks happen.

The Page Break Properties

@media print {
  /* Force a page break before every h2 heading */
  h2 {
    break-before: page;
  }

  /* Force a page break after the cover section */
  .cover-page {
    break-after: page;
  }

  /* Prevent page breaks inside a card or table row */
  .card, tr, figure {
    break-inside: avoid;
  }

  /* Prevent "orphaned" headings at the bottom of a page */
  h1, h2, h3, h4 {
    break-after: avoid;
  }
}
Property Values What It Does
break-before auto, avoid, page Controls breaks before an element
break-after auto, avoid, page Controls breaks after an element
break-inside auto, avoid Controls breaks inside an element

break-before: page forces a new page to start before the element. break-inside: avoid tells the browser to keep the entire element on one page if possible (it may still break if the element is taller than a page). break-after: avoid on headings prevents the ugly pattern of a heading appearing alone at the bottom of a page.

Legacy Properties You may encounter page-break-before, page-break-after, and page-break-inside in older code. These are the legacy versions of the modern break-* properties. They work the same way but are considered deprecated in favor of the newer syntax. Modern browsers support both.

The .no-print Utility Class

The most common print styling task is hiding elements that should not appear on paper. Navigation bars, footers, login buttons, advertising, and interactive controls are all screen-only content. The .no-print pattern gives you a simple, reusable way to mark elements for exclusion.

/* In your main stylesheet */
@media print {
  .no-print {
    display: none !important;
  }
}

Now you can add className="no-print" to any element that should be hidden when printing:

<nav className="no-print">
  {/* Navigation links - not needed on paper */}
</nav>

<main>
  {/* Main content - this prints */}
  <h1>Invoice #1234</h1>

  <button className="no-print" onClick={() => window.print()}>
    Print this invoice
  </button>
</main>

<footer className="no-print">
  {/* Footer - not needed on paper */}
</footer>

The !important declaration ensures the element is hidden regardless of any other styles. This is one of the rare cases where !important is appropriate: print utility classes need to win over every other style.

The Inverse: .print-only

Sometimes you want elements that appear ONLY on paper but not on screen. For example, a "Printed on [date]" footer or a signature line:

/* Hidden on screen, visible in print */
.print-only {
  display: none;
}

@media print {
  .print-only {
    display: block !important;
  }
}
<p className="print-only">
  Printed on {new Date().toLocaleDateString()} | Computer Store KS
</p>

Triggering Print with window.print()

The window.print() method opens the browser's native print dialog. It is the same dialog that appears when the user presses Ctrl+P, but you can trigger it from a button click, making the print flow part of your application's UI.

function PrintButton() {
  return (
    <button
      className="no-print"
      onClick={() => window.print()}
    >
      Print Document
    </button>
  );
}

Notice the no-print class on the button itself. You do not want the "Print Document" button appearing on the printed page. This is a common pattern: the print trigger hides itself during printing.

Print Events

The browser fires events before and after printing, which you can use to prepare the page:

// Runs just before the print dialog opens
window.addEventListener('beforeprint', () => {
  console.log('Preparing for print...');
  // You could expand collapsed sections, load high-res images, etc.
});

// Runs after printing (or after the dialog is closed)
window.addEventListener('afterprint', () => {
  console.log('Print complete or dialog closed');
  // Restore any changes made in beforeprint
});

These events are useful when you need to modify the DOM before printing. For example, you might expand all accordion sections so their content prints, or switch images to higher-resolution versions for better print quality.

Building an Invoice Template

An invoice is one of the most common print documents in business applications. Let us build one that looks professional on paper with dynamic data from your application.

// components/Invoice.tsx
'use client';

interface InvoiceItem {
  description: string;
  quantity: number;
  unitPrice: number;
}

interface InvoiceProps {
  invoiceNumber: string;
  date: string;
  customerName: string;
  customerAddress: string;
  items: InvoiceItem[];
  taxRate: number;
}

export default function Invoice({
  invoiceNumber, date, customerName, customerAddress, items, taxRate
}: InvoiceProps) {
  const subtotal = items.reduce(
    (sum, item) => sum + item.quantity * item.unitPrice, 0
  );
  const tax = subtotal * taxRate;
  const total = subtotal + tax;

  return (
    <div className="invoice">
      {/* Print button - hidden on paper */}
      <div className="no-print" style={{ marginBottom: '1rem' }}>
        <button onClick={() => window.print()}>Print Invoice</button>
      </div>

      {/* Invoice header */}
      <header className="invoice-header">
        <div>
          <h1>INVOICE</h1>
          <p>Computer Store KS</p>
          <p>123 Main Street</p>
          <p>Topeka, KS 66604</p>
        </div>
        <div className="invoice-meta">
          <p><strong>Invoice #:</strong> {invoiceNumber}</p>
          <p><strong>Date:</strong> {date}</p>
        </div>
      </header>

      {/* Bill to */}
      <section className="bill-to">
        <h2>Bill To</h2>
        <p><strong>{customerName}</strong></p>
        <p>{customerAddress}</p>
      </section>

      {/* Line items */}
      <table className="invoice-table">
        <thead>
          <tr>
            <th>Description</th>
            <th>Qty</th>
            <th>Unit Price</th>
            <th>Amount</th>
          </tr>
        </thead>
        <tbody>
          {items.map((item, i) => (
            <tr key={i}>
              <td>{item.description}</td>
              <td>{item.quantity}</td>
              <td>${item.unitPrice.toFixed(2)}</td>
              <td>${(item.quantity * item.unitPrice).toFixed(2)}</td>
            </tr>
          ))}
        </tbody>
        <tfoot>
          <tr>
            <td colSpan={3} style={{ textAlign: 'right' }}>Subtotal:</td>
            <td>${subtotal.toFixed(2)}</td>
          </tr>
          <tr>
            <td colSpan={3} style={{ textAlign: 'right' }}>
              Tax ({(taxRate * 100).toFixed(1)}%):
            </td>
            <td>${tax.toFixed(2)}</td>
          </tr>
          <tr className="total-row">
            <td colSpan={3} style={{ textAlign: 'right' }}>
              <strong>Total:</strong>
            </td>
            <td><strong>${total.toFixed(2)}</strong></td>
          </tr>
        </tfoot>
      </table>

      {/* Footer - only on printed page */}
      <footer className="invoice-footer">
        <p>Thank you for your business!</p>
        <p>Payment due within 30 days.</p>
      </footer>
    </div>
  );
}

Building a Promotional Flyer Component

A flyer is different from an invoice. Instead of tabular data, a flyer is a visual marketing piece with images, headlines, prices, and calls to action. The layout must fit exactly one page.

// components/PromotionalFlyer.tsx
'use client';

interface FlyerProps {
  shopName: string;
  tagline: string;
  promotions: Array<{
    name: string;
    originalPrice: number;
    salePrice: number;
    image: string;
    specs: string;
  }>;
  validUntil: string;
  phone: string;
  address: string;
}

export default function PromotionalFlyer({
  shopName, tagline, promotions, validUntil, phone, address
}: FlyerProps) {
  return (
    <div className="flyer">
      {/* Print trigger (hidden on paper) */}
      <button className="no-print" onClick={() => window.print()}>
        Print Flyer
      </button>

      {/* Flyer content - exactly one page */}
      <div className="flyer-page">
        {/* Header band */}
        <header className="flyer-header">
          <h1>{shopName}</h1>
          <p className="flyer-tagline">{tagline}</p>
        </header>

        {/* Promotion grid */}
        <div className="promo-grid">
          {promotions.map((promo, i) => (
            <div key={i} className="promo-card">
              <img src={promo.image} alt={promo.name} />
              <h3>{promo.name}</h3>
              <p className="promo-specs">{promo.specs}</p>
              <div className="promo-pricing">
                <span className="original-price">
                  ${promo.originalPrice}
                </span>
                <span className="sale-price">
                  ${promo.salePrice}
                </span>
              </div>
            </div>
          ))}
        </div>

        {/* Footer with contact info */}
        <footer className="flyer-footer">
          <p className="valid-until">
            Sale valid through {validUntil}
          </p>
          <p>{phone} | {address}</p>
        </footer>
      </div>
    </div>
  );
}

Print Preview: Showing Users What They Will Get

The browser's built-in print preview (Ctrl+P) shows users what the printed output will look like. But sometimes you want to show a preview inside your application, before the user opens the print dialog. This is especially useful for document generators where users configure options before printing.

The Preview Approach

function FlyerGenerator() {
  const [shopName, setShopName] = useState('Computer Store KS');
  const [promotions, setPromotions] = useState([]);
  const [showPreview, setShowPreview] = useState(false);

  return (
    <div>
      {/* Configuration Panel (screen only) */}
      <div className="no-print">
        <h2>Flyer Generator</h2>

        <label>Shop Name:</label>
        <input
          value={shopName}
          onChange={e => setShopName(e.target.value)}
        />

        {/* ... more configuration fields ... */}

        <button onClick={() => setShowPreview(true)}>
          Preview Flyer
        </button>
      </div>

      {/* Preview (shown in an iframe-like container) */}
      {showPreview && (
        <div className="preview-wrapper no-print">
          <div className="preview-toolbar">
            <button onClick={() => setShowPreview(false)}>
              Close Preview
            </button>
            <button onClick={() => window.print()}>
              Print
            </button>
          </div>

          {/* Scaled-down preview */}
          <div className="preview-paper">
            <PromotionalFlyer
              shopName={shopName}
              promotions={promotions}
              {/* ... other props ... */}
            />
          </div>
        </div>
      )}

      {/* The actual printable content (hidden on screen, printed) */}
      <div className="print-only">
        <PromotionalFlyer
          shopName={shopName}
          promotions={promotions}
          {/* ... other props ... */}
        />
      </div>
    </div>
  );
}

A Complete Print Stylesheet Template

Here is a complete, production-ready print stylesheet that you can use as a starting point for any project. It handles the most common print needs and can be customized per page.

/* print.css - Production print stylesheet template */

@media print {
  /* ── Page Setup ── */
  @page {
    size: 8.5in 11in;
    margin: 0.75in;
  }

  /* ── Reset for Paper ── */
  body {
    margin: 0;
    padding: 0;
    font-family: 'Georgia', 'Times New Roman', serif;
    font-size: 12pt;
    line-height: 1.5;
    color: #000;
    background: white;
  }

  /* ── Hide Screen-Only Elements ── */
  .no-print,
  nav,
  footer:not(.print-footer),
  .sidebar,
  button,
  .tooltip,
  .modal,
  .toast {
    display: none !important;
  }

  /* ── Show Print-Only Elements ── */
  .print-only {
    display: block !important;
  }

  /* ── Typography ── */
  h1 { font-size: 24pt; }
  h2 { font-size: 18pt; }
  h3 { font-size: 14pt; }

  /* ── Links: Show URLs ── */
  a[href^="http"]::after {
    content: ' (' attr(href) ')';
    font-size: 0.85em;
    color: #555;
    word-break: break-all;
  }

  /* ── Page Break Control ── */
  h1, h2, h3 {
    break-after: avoid;
  }

  table, figure, .card {
    break-inside: avoid;
  }

  /* ── Tables ── */
  table {
    border-collapse: collapse;
    width: 100%;
  }
  th, td {
    border: 1px solid #333;
    padding: 6pt 8pt;
  }
  thead {
    display: table-header-group; /* Repeat header on each page */
  }

  /* ── Images ── */
  img {
    max-width: 100% !important;
    break-inside: avoid;
  }

  /* ── Backgrounds (only where essential) ── */
  .print-bg {
    -webkit-print-color-adjust: exact;
    print-color-adjust: exact;
  }

  /* ── Utility Classes ── */
  .page-break {
    break-before: page;
  }

  .keep-together {
    break-inside: avoid;
  }
}

This template covers the fundamentals. Include it in any project and you immediately have reasonable print output. Customize the page size, margins, and hidden elements per project.

Hands-On Exercises

  1. Hide navigation: Take any web page you have built and add @media print styles that hide the navigation and footer. Open the print preview (Ctrl+P) to verify they disappear.
  2. Invoice template: Build the invoice component from this lesson. Populate it with sample data (3–5 line items). Open the print preview and verify it fits on one page with correct margins. Save it as a PDF and check the output.
  3. Page breaks: Create a long document with multiple sections (use <h2> headings). Add break-before: page to the headings so each section starts on a new page. Add break-inside: avoid to any cards or tables.
  4. URL display: Add the a[href]::after CSS rule from this lesson. Create a page with several links and verify that the URLs appear in parentheses in print preview but not on screen.
  5. Promotional flyer: Build the flyer component from this lesson. Populate it with 4 promotional items (use placeholder images). Style it to fit exactly one 8.5" x 11" page. Print to PDF and verify the layout.
  6. Flyer generator: Build a configuration page where the user can enter a shop name, select promotions from a list, and preview the flyer before printing. Include a "Print Flyer" button that triggers window.print(). The configuration UI should be hidden in print.

Key Takeaways

  • @media print CSS rules only activate when the page is being printed or saved as PDF — they are invisible on screen.
  • The @page rule controls physical paper properties: size (8.5in 11in, A4), margins, and orientation.
  • Use the .no-print class to hide screen-only elements (nav, buttons, footers) and .print-only for paper-only elements.
  • Print typography differs from screen: use serif fonts, point sizes (12pt), and pure black text for best readability on paper.
  • Control page breaks with break-before: page (force new page), break-inside: avoid (keep together), and break-after: avoid (prevent orphaned headings).
  • Browsers strip background colors by default when printing. Use print-color-adjust: exact to force them when needed.
  • window.print() opens the browser print dialog from JavaScript, triggered by a button click.
  • Use physical units (in, pt, cm) instead of screen units (px, rem) for precise paper layouts.
  • Generating documents from your web app keeps data current and eliminates manual updates in Word or design tools.
