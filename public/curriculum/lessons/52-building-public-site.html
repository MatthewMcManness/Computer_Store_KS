Building Page by Page: The Right Order

With your project planned and scaffolded (Lesson 51), it is time to build the customer-facing pages. But which page do you build first? The answer is: start with the shared layout, then build outward from the most important pages.

Here is the recommended build order:

  1. Root layout and public layout — Header navigation and footer (these appear on every page)
  2. Homepage — The most visited page; sets the visual tone
  3. About page — Simple content page; validates your layout works
  4. Services hub and detail pages — Core business content
  5. Contact page — First interactive feature (form + email)
  6. Blog system — Listing + individual posts (database-driven)
  7. Gallery — Visual content with filtering
  8. Reviews page — Social proof

This order works because each step builds on the previous one. The layout must exist before any page. The homepage establishes visual patterns that other pages follow. Simple pages validate your setup before you tackle complex features like forms and database-driven content.

Why is the Header a Client Component? The Header uses usePathname() (for active link highlighting) and useState() (for the mobile menu toggle). Both require browser-side state, so the 'use client' directive is necessary. The Footer, which has no interactivity, can remain a Server Component.

Contact Page: Validated Form with Email

The contact page is often the most important page for a service business — it is where potential customers become actual leads. Building it properly requires several layers working together.

Architecture Overview

User fills form
      |
      v
Client-side validation (Zod) -- catches obvious errors instantly
      |
      v
Turnstile CAPTCHA verification -- proves user is human
      |
      v
POST to /api/contact -- sends data to your API route
      |
      v
Server-side validation (Zod) -- re-validates because never trust the client
      |
      v
Turnstile token verification -- confirms CAPTCHA with Cloudflare
      |
      v
Resend API -- sends email notification to business owner
      |
      v
Response to client -- success message or error details

The Contact Form Component

// src/app/(public)/contact/page.tsx
'use client';

import { useState } from 'react';
import { z } from 'zod';

// Define the validation schema (shared between client and server)
const contactSchema = z.object({
  name: z.string().min(1, 'Name is required').max(100),
  email: z.string().email('Please enter a valid email address'),
  phone: z.string().optional(),
  message: z.string()
    .min(10, 'Message must be at least 10 characters')
    .max(2000, 'Message must be under 2000 characters'),
});

type ContactFormData = z.infer<typeof contactSchema>;

export default function ContactPage() {
  const [formData, setFormData] = useState<ContactFormData>({
    name: '', email: '', phone: '', message: '',
  });
  const [errors, setErrors] = useState<Record<string, string>>({});
  const [status, setStatus] = useState<'idle' | 'submitting' | 'success' | 'error'>('idle');

  async function handleSubmit(e: React.FormEvent) {
    e.preventDefault();
    setErrors({});

    // Client-side validation
    const result = contactSchema.safeParse(formData);
    if (!result.success) {
      const fieldErrors: Record<string, string> = {};
      result.error.issues.forEach(issue => {
        fieldErrors[issue.path[0] as string] = issue.message;
      });
      setErrors(fieldErrors);
      return;
    }

    setStatus('submitting');

    try {
      const response = await fetch('/api/contact', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(result.data),
      });

      if (!response.ok) {
        throw new Error('Failed to send message');
      }

      setStatus('success');
      setFormData({ name: '', email: '', phone: '', message: '' });
    } catch {
      setStatus('error');
    }
  }

  if (status === 'success') {
    return (
      <div className="contact-success">
        <h1>Message Sent!</h1>
        <p>Thank you for reaching out. We will get back to you within 24 hours.</p>
        <button onClick={() => setStatus('idle')}>Send Another Message</button>
      </div>
    );
  }

  return (
    <div className="contact-page">
      <h1>Contact Us</h1>
      <p>Have a question or need a repair? Send us a message.</p>

      {status === 'error' && (
        <div className="form-error-banner" role="alert">
          Something went wrong. Please try again or call us directly.
        </div>
      )}

      <form onSubmit={handleSubmit} noValidate>
        <div className="form-field">
          <label htmlFor="name">Name *</label>
          <input
            id="name"
            type="text"
            value={formData.name}
            onChange={e => setFormData(prev => ({ ...prev, name: e.target.value }))}
            aria-invalid={!!errors.name}
            aria-describedby={errors.name ? 'name-error' : undefined}
          />
          {errors.name && <p id="name-error" className="field-error">{errors.name}</p>}
        </div>

        <div className="form-field">
          <label htmlFor="email">Email *</label>
          <input
            id="email"
            type="email"
            value={formData.email}
            onChange={e => setFormData(prev => ({ ...prev, email: e.target.value }))}
            aria-invalid={!!errors.email}
            aria-describedby={errors.email ? 'email-error' : undefined}
          />
          {errors.email && <p id="email-error" className="field-error">{errors.email}</p>}
        </div>

        <div className="form-field">
          <label htmlFor="phone">Phone (optional)</label>
          <input
            id="phone"
            type="tel"
            value={formData.phone}
            onChange={e => setFormData(prev => ({ ...prev, phone: e.target.value }))}
          />
        </div>

        <div className="form-field">
          <label htmlFor="message">Message *</label>
          <textarea
            id="message"
            rows={6}
            value={formData.message}
            onChange={e => setFormData(prev => ({ ...prev, message: e.target.value }))}
            aria-invalid={!!errors.message}
            aria-describedby={errors.message ? 'message-error' : undefined}
          />
          {errors.message && <p id="message-error" className="field-error">{errors.message}</p>}
        </div>

        {/* Turnstile CAPTCHA widget would go here */}

        <button type="submit" disabled={status === 'submitting'}>
          {status === 'submitting' ? 'Sending...' : 'Send Message'}
        </button>
      </form>
    </div>
  );
}

The API Route

// src/app/api/contact/route.ts
import { NextRequest, NextResponse } from 'next/server';
import { z } from 'zod';
import { Resend } from 'resend';

const resend = new Resend(process.env.RESEND_API_KEY);

const contactSchema = z.object({
  name: z.string().min(1).max(100),
  email: z.string().email(),
  phone: z.string().optional(),
  message: z.string().min(10).max(2000),
});

export async function POST(request: NextRequest) {
  try {
    const body = await request.json();

    // Server-side validation (never trust the client!)
    const result = contactSchema.safeParse(body);
    if (!result.success) {
      return NextResponse.json(
        { error: 'Invalid form data', details: result.error.issues },
        { status: 400 }
      );
    }

    const { name, email, phone, message } = result.data;

    // Send email via Resend
    await resend.emails.send({
      from: 'Contact Form <noreply@yourdomain.com>',
      to: process.env.NOTIFICATION_EMAIL!,
      subject: `New Contact: ${name}`,
      html: `
        <h2>New Contact Form Submission</h2>
        <p><strong>Name:</strong> ${name}</p>
        <p><strong>Email:</strong> ${email}</p>
        <p><strong>Phone:</strong> ${phone || 'Not provided'}</p>
        <p><strong>Message:</strong></p>
        <p>${message}</p>
      `,
      replyTo: email,
    });

    return NextResponse.json(
      { message: 'Message sent successfully' },
      { status: 201 }
    );
  } catch (error) {
    console.error('Contact form error:', error);
    return NextResponse.json(
      { error: 'Failed to send message' },
      { status: 500 }
    );
  }
}
CSK Connection The CSK contact form follows this exact pattern: Zod validation on both client and server, Turnstile CAPTCHA to block bots, and Resend for email delivery. The form also includes honeypot fields and timing-based bot detection (from Lesson 33) for additional spam protection. Success and error states are clearly communicated to the user.

Blog System

A blog drives organic search traffic, establishes expertise, and gives the business fresh content to share. Building a blog requires a listing page, individual post pages, and a way to render Markdown content.

Blog Listing Page

// src/app/(public)/blog/page.tsx
import Link from 'next/link';
import { supabase } from '@/lib/supabase';
import type { Metadata } from 'next';

export const metadata: Metadata = {
  title: 'Blog | Computer Store KS',
  description: 'Tips, guides, and news about computer repair and technology.',
};

async function getBlogPosts(category?: string) {
  let query = supabase
    .from('blog_posts')
    .select('id, title, slug, excerpt, category:blog_categories(name, slug), created_at')
    .eq('status', 'published')
    .order('created_at', { ascending: false });

  if (category) {
    query = query.eq('blog_categories.slug', category);
  }

  const { data, error } = await query;
  if (error) throw error;
  return data;
}

async function getCategories() {
  const { data } = await supabase
    .from('blog_categories')
    .select('name, slug')
    .order('name');
  return data ?? [];
}

export default async function BlogPage({
  searchParams,
}: {
  searchParams: { category?: string };
}) {
  const [posts, categories] = await Promise.all([
    getBlogPosts(searchParams.category),
    getCategories(),
  ]);

  return (
    <div className="blog-page">
      <h1>Blog</h1>

      {/* Category Filter */}
      <nav className="category-filter">
        <Link
          href="/blog"
          className={!searchParams.category ? 'active' : ''}
        >
          All Posts
        </Link>
        {categories.map(cat => (
          <Link
            key={cat.slug}
            href={`/blog?category=${cat.slug}`}
            className={searchParams.category === cat.slug ? 'active' : ''}
          >
            {cat.name}
          </Link>
        ))}
      </nav>

      {/* Post Grid */}
      <div className="posts-grid">
        {posts.map(post => (
          <article key={post.id} className="post-card">
            <Link href={`/blog/${post.slug}`}>
              <h2>{post.title}</h2>
              <p>{post.excerpt}</p>

          </article>
        ))}
      </div>

      {posts.length === 0 && (
        <p className="no-posts">No posts found in this category.</p>
      )}
    </div>

}

Individual Blog Post with Markdown Rendering

// src/app/(public)/blog/[slug]/page.tsx
import { notFound } from 'next/navigation';
import { supabase } from '@/lib/supabase';
import { marked } from 'marked';
import DOMPurify from 'isomorphic-dompurify';
import type { Metadata } from 'next';

async function getPost(slug: string) {
  const { data } = await supabase
    .from('blog_posts')
    .select('*, category:blog_categories(name, slug), tags:blog_post_tags(tag:blog_tags(name, slug))')
    .eq('slug', slug)
    .eq('status', 'published')
    .single();
  return data;
}

export async function generateMetadata(
  { params }: { params: { slug: string } }
): Promise<Metadata> {
  const post = await getPost(params.slug);
  if (!post) return { title: 'Post Not Found' };

  return {
    title: `${post.title} | Computer Store KS Blog`,
    description: post.excerpt,
  };
}

export default async function BlogPostPage({
  params,
}: {
  params: { slug: string };
}) {
  const post = await getPost(params.slug);

  if (!post) {
    notFound();
  }

  // Convert Markdown to HTML and sanitize
  const htmlContent = DOMPurify.sanitize(
    await marked(post.content)
  );

  return (
    <article className="blog-post">
      <header>
        <h1>{post.title}</h1>
        <div className="post-meta">
          <time dateTime={post.created_at}>
            {new Date(post.created_at).toLocaleDateString('en-US', {
              year: 'numeric', month: 'long', day: 'numeric'
            })}
          </time>
          {post.category && (
            <span className="post-category">{post.category.name}</span>
          )}
        </div>
        {post.tags?.length > 0 && (
          <div className="post-tags">
            {post.tags.map((t: any) => (
              <span key={t.tag.slug} className="tag">{t.tag.name}</span>
            ))}
          </div>
        )}
      </header>

      {/* Render sanitized Markdown HTML */}
      <div
        className="post-content prose"
        dangerouslySetInnerHTML={{ __html: htmlContent }}
      />
    </article>
  );
}
Security: Always sanitize HTML generated from Markdown using a library like DOMPurify before rendering with dangerouslySetInnerHTML. Without sanitization, a malicious blog post could inject scripts (XSS attacks). This is especially important if multiple people can create blog content.

The gallery showcases refurbished computers for sale. It needs a grid layout with filtering (desktops vs. laptops) and a way to view details for each item.

// src/app/(public)/gallery/page.tsx
'use client';

import { useState, useEffect } from 'react';
import Image from 'next/image';

interface GalleryItem {
  id: string;
  name: string;
  type: 'desktop' | 'laptop';
  specs: string;
  price: number;
  salePrice?: number;
  imageUrl: string;
  status: 'available' | 'sold';
}

export default function GalleryPage() {
  const [items, setItems] = useState<GalleryItem[]>([]);
  const [filter, setFilter] = useState<'all' | 'desktop' | 'laptop'>('all');
  const [selectedItem, setSelectedItem] = useState<GalleryItem | null>(null);

  useEffect(() => {
    fetch('/api/gallery')
      .then(res => res.json())
      .then(data => setItems(data));
  }, []);

  const filtered = filter === 'all'
    ? items
    : items.filter(item => item.type === filter);

  return (
    <div className="gallery-page">
      <h1>Computers for Sale</h1>

      {/* Filter Buttons */}
      <div className="gallery-filters">
        {(['all', 'desktop', 'laptop'] as const).map(f => (
          <button
            key={f}
            onClick={() => setFilter(f)}
            className={filter === f ? 'active' : ''}
          >
            {f === 'all' ? 'All' : f === 'desktop' ? 'Desktops' : 'Laptops'}
          </button>
        ))}
      </div>

      {/* Gallery Grid */}
      <div className="gallery-grid">
        {filtered.map(item => (
          <button
            key={item.id}
            className="gallery-card"
            onClick={() => setSelectedItem(item)}
          >
            <div className="card-image">
              <Image
                src={item.imageUrl}
                alt={item.name}
                width={300}
                height={200}
                style={{ objectFit: 'cover' }}
              />
              {item.status === 'sold' && (
                <span className="sold-badge">SOLD</span>
              )}
            </div>
            <h3>{item.name}</h3>
            <p className="specs">{item.specs}</p>
            <div className="pricing">
              {item.salePrice ? (
                <>
                  <span className="original-price">${item.price}</span>
                  <span className="sale-price">${item.salePrice}</span>
                </>
              ) : (
                <span className="price">${item.price}</span>
              )}
            </div>
          </button>
        ))}
      </div>

      {/* Detail Modal */}
      {selectedItem && (
        <div className="modal-overlay" onClick={() => setSelectedItem(null)}>
          <div className="modal-content" onClick={e => e.stopPropagation()}>
            <button
              className="modal-close"
              onClick={() => setSelectedItem(null)}
              aria-label="Close"
            >
              &times;
            </button>
            <Image
              src={selectedItem.imageUrl}
              alt={selectedItem.name}
              width={600}
              height={400}
              style={{ objectFit: 'contain' }}
            />
            <h2>{selectedItem.name}</h2>
            <p>{selectedItem.specs}</p>
            <p className="modal-price">
              {selectedItem.salePrice
                ? `$${selectedItem.salePrice} (was $${selectedItem.price})`
                : `$${selectedItem.price}`}
            </p>
          </div>
        </div>
      )}
    </div>
  );
}

Responsive Design Across All Pages

Every page must work on phones, tablets, and desktops. The key responsive patterns to apply:

Pattern Desktop Mobile
Navigation Horizontal link bar Hamburger menu with slide-out
Services grid 3 columns 1 column, stacked
Gallery grid 3-4 columns 1-2 columns
Blog posts 2-3 column grid Single column list
Footer 3-column grid Stacked sections
Hero section Large text, side-by-side buttons Smaller text, stacked buttons
Contact form Two-column layout (form + info) Single column, form only

SEO Metadata for Every Page

Every public page needs SEO metadata so search engines can properly index your site. Next.js makes this easy with the metadata export:

    images: [{ url: 'https://computerstoreks.com/images/og-diagnostics.jpg' }],
  },
};

// Dynamic metadata (for pages with variable content like blog posts)
export async function generateMetadata({ params }): Promise<Metadata> {
  const post = await getPost(params.slug);
  return {
    title: `${post.title} | Computer Store KS Blog`,
    description: post.excerpt,
    openGraph: {
      title: post.title,
      description: post.excerpt,
      type: 'article',
      publishedTime: post.created_at,
      images: post.featured_image ? [{ url: post.featured_image }] : [],
    },
  };
}

SEO Checklist for Every Page

  • Unique title that includes the primary keyword and business name
  • Descriptive description under 160 characters
  • Open Graph tags for social media sharing
  • Proper heading hierarchy (h1 once per page, then h2, h3)
  • Descriptive alt text on all images
  • Internal links between related pages
  • Semantic HTML elements (article, section, nav, main)

Accessibility Review

Before moving on, review every page for accessibility:

  • Keyboard navigation: Can you tab through all interactive elements? Is the focus order logical?
  • Form labels: Every input has an associated <label> with a matching htmlFor/id
  • ARIA attributes: aria-label on icon buttons, aria-expanded on menus, role="alert" on error messages
  • Color contrast: Text meets WCAG AA contrast ratios (4.5:1 for normal text, 3:1 for large text)
  • Image alt text: Every image has descriptive alt text (decorative images use alt="")
  • Skip navigation: A "Skip to main content" link as the first focusable element

Exercises

  1. Build the Layout: Create a (public)/layout.tsx with a Header component (logo, navigation links, mobile hamburger menu) and a Footer component (three-column grid with business info, quick links, and contact details).
  2. Homepage: Build a homepage with a hero section (background image, headline, two CTA buttons), a services overview grid (at least 6 cards), and a call-to-action banner. Make it fully responsive.
  3. Services Pages: Create a services hub page that lists at least 5 services. Implement a dynamic [service]/page.tsx that renders detail pages for each. Use generateStaticParams to pre-render all pages.
  4. Contact Form: Build a contact form with Zod validation (client-side and server-side), proper error messages for each field, success/error states, and an API route that logs the submission to the console (or sends an email if you have Resend configured).
  5. Blog System: Create a blog listing page that fetches posts from Supabase (or use mock data). Build an individual post page with Markdown rendering using the marked library. Sanitize the output with DOMPurify.
  6. Gallery: Build a gallery page with a grid of items, filter buttons (e.g., "All", "Desktops", "Laptops"), and a modal that opens when you click an item to show details. Make the grid responsive (1 column on mobile, 3 on desktop).
  7. SEO Audit: Add complete metadata to every page you have built. Run Lighthouse in Chrome DevTools and aim for a score of 90+ on SEO. Fix any issues it reports.
  8. Accessibility Audit: Navigate your entire site using only the keyboard (Tab, Enter, Escape). Check that every form field has a label, every image has alt text, and error messages use role="alert". Fix any issues.

Key Takeaways

  • Build shared layouts first (Header, Footer), then pages in order of importance: homepage, core content, interactive features, database-driven content.
  • The homepage must communicate what the business does, build trust, and provide clear calls to action — all within five seconds.
  • Services pages use a hub-and-spoke pattern: one listing page links to many detail pages via dynamic routes with generateStaticParams for build-time rendering.
  • Contact forms require dual validation (Zod on client and server), CAPTCHA protection, email delivery, and clear success/error states.
  • Blog systems fetch data from the database, render Markdown to HTML, and must sanitize output to prevent XSS attacks.
  • Gallery pages combine client-side filtering, responsive grid layouts, and modal detail views.
  • Use next/image with priority for above-the-fold images. Set width/height or fill to prevent layout shift.
  • Every page needs unique SEO metadata (title, description, Open Graph) and proper accessibility (labels, alt text, keyboard navigation, color contrast).
