# Task: Update Login API Route

## Description

Update the login API endpoint to accept email and password, authenticate via RepairShopr, and create a secure session. Maintain backward compatibility for legacy mode.

## Acceptance Criteria

- [ ] Update `src/app/api/auth/login/route.ts` to accept `{ email, password }`
- [ ] Call RepairShopr authentication when in repairshopr mode
- [ ] Return user info (excluding sensitive data) on successful login
- [ ] Return appropriate error messages for different failure modes
- [ ] Log authentication attempts (success/failure) for audit
- [ ] Rate limit login attempts (basic protection)

## Technical Details

### File Location
`src/app/api/auth/login/route.ts`

### Request/Response Format
```typescript
// Request body
interface LoginRequest {
  email?: string;      // Required for RepairShopr mode
  password: string;    // Required for both modes
}

// Success response
interface LoginSuccessResponse {
  success: true;
  user: {
    email: string;
    name: string;
    role: 'admin' | 'employee' | 'limited';
  };
}

// Error response
interface LoginErrorResponse {
  success: false;
  error: string;
  code?: 'INVALID_CREDENTIALS' | 'RATE_LIMITED' | 'SERVICE_UNAVAILABLE';
}
```

### Error Handling
- Invalid credentials: 401 with clear message
- RepairShopr unavailable: 503 with fallback suggestion
- Rate limited: 429 with retry-after header
- Missing fields: 400 with field validation

### Logging
```typescript
// Log format (no sensitive data)
console.log(`[AUTH] Login attempt: ${email} - ${success ? 'SUCCESS' : 'FAILED'}`);
```
