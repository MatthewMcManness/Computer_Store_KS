# Task: Database Schema

## Description
Create the `user_profiles` table linking Supabase Auth users to RepairShopr IDs, and the `device_mappings` table for NinjaOne integration. Enable Row-Level Security with appropriate policies.

## Acceptance Criteria
- [ ] `user_profiles` table created with all required columns
- [ ] RLS enabled with policies for self-read/update
- [ ] `device_mappings` table created for NinjaOne device linking
- [ ] Migration file saved to `docs/database/user-profiles-schema.sql`
- [ ] Schema applied to Supabase project

## Technical Details

**user_profiles table:**
```sql
CREATE TABLE user_profiles (
  id UUID PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  email TEXT UNIQUE NOT NULL,
  full_name TEXT,
  role TEXT NOT NULL CHECK (role IN ('admin', 'technician', 'receptionist', 'customer')),
  repairshopr_user_id INTEGER,
  repairshopr_customer_id INTEGER,
  protection_plan_tier TEXT CHECK (protection_plan_tier IN ('bronze', 'silver', 'gold')),
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);
```

**RLS Policies:**
- Users can read their own profile
- Users can update their own profile (except role)
- Admins can read/write all profiles

**device_mappings table:**
- Links RepairShopr asset IDs to NinjaOne device IDs
- Tracks last sync time for cache invalidation

**Files affected:**
