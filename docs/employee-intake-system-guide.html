1. System Overview

The Employee Intake System is a guided wizard at /admin/intake that streamlines the process of creating customer repair tickets. It integrates with RepairShopr API and Supabase for customer portal accounts.

        │                      │                      │                      │                      │
        ▼                      ▼                      ▼                      ▼                      ▼
   RepairShopr            Supabase              RepairShopr            RepairShopr            Display
   Customer API           + RepairShopr         Assets API             Tickets API            Ticket #

Key Features

  • Search existing customers or create new ones
  • Support for individual and business customers
  • Automatic customer portal account creation (Supabase)
  • Device selection or creation
  • Ticket creation with issue description
  • Confirmation with ticket number

Variable Description Required

REPAIRSHOPR_SUBDOMAIN Your RepairShopr subdomain (e.g., "thecomputerstore") Yes
NEXT_PUBLIC_SUPABASE_URL Supabase project URL Yes
NEXT_PUBLIC_SUPABASE_ANON_KEY Supabase anonymous key Yes
SUPABASE_SERVICE_ROLE_KEY Supabase service role key (for server-side) Yes
SESSION_SECRET 64-character hex string for session encryption Yes
⚠️
Important: The SUPABASE_SERVICE_ROLE_KEY is required for creating customer portal accounts. This key bypasses Row Level Security and should never be exposed to the client.

3. Database Setup (Supabase)

Before testing, you must run the database migration to create the customer_accounts table.

1

Open Supabase SQL Editor

  1. Go to Supabase Dashboard
  2. Select your project
  3. Navigate to SQL Editor in the left sidebar
  4. Click New Query
2

Run the Migration

Copy and paste the following SQL:

-- Customer Accounts Table for Portal Authentication
-- This table stores customer portal credentials separately from RepairShopr

CREATE TABLE IF NOT EXISTS customer_accounts (
    id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
    email VARCHAR(255) NOT NULL UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    repairshopr_customer_id INTEGER NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- Index for faster lookups by email (login)
CREATE INDEX IF NOT EXISTS idx_customer_accounts_email
    ON customer_accounts(email);

-- Index for RepairShopr customer ID lookups
CREATE INDEX IF NOT EXISTS idx_customer_accounts_repairshopr_id
    ON customer_accounts(repairshopr_customer_id);

-- Enable Row Level Security
ALTER TABLE customer_accounts ENABLE ROW LEVEL SECURITY;

-- Policy: Only service role can access (server-side only)
CREATE POLICY "Service role access only" ON customer_accounts
    FOR ALL
    USING (auth.role() = 'service_role');

-- Trigger to update updated_at timestamp
CREATE OR REPLACE FUNCTION update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = NOW();
    RETURN NEW;
END;
$$ language 'plpgsql';

CREATE TRIGGER update_customer_accounts_updated_at
    BEFORE UPDATE ON customer_accounts
    FOR EACH ROW
    EXECUTE FUNCTION update_updated_at_column();

Click Run to execute the migration.

✅
Success: You should see "Success. No rows returned" - this means the table was created successfully.

5. Test Scenarios

Scenario A: Existing Customer Flow

  • Search for an existing customer by name, email, or phone
  • Verify search results appear after typing 2+ characters
  • Select an existing customer
  • Verify you skip to Step 3 (Device Selection)
  • Select an existing device OR create a new one
  • Enter an issue description (minimum 10 characters)
  • Click "Create Ticket"
  • Verify success screen shows ticket number
  • Verify ticket exists in RepairShopr

Scenario B: New Individual Customer

  • Click "Create New Individual Customer"
  • Fill in required fields: First Name, Last Name, Email, Phone
  • Set a portal password (minimum 8 characters)
  • Confirm password matches
  • Click "Create Customer"
  • Verify customer is created in RepairShopr
  • Verify portal account is created in Supabase
  • Continue with device and ticket creation

Scenario C: New Business Customer

  • Click "Create New Business Customer"
  • Search for existing business OR create new
  • Fill in contact person details
  • Set portal password
  • Verify business customer is created in RepairShopr
  • Continue with device and ticket creation

Scenario D: New Device

  • On Step 3, click "Add New Device"
  • Select device type from dropdown
  • Enter brand (e.g., "Dell")
  • Enter model (e.g., "OptiPlex 7090")
  • Click "Add Device"
  • Verify device is created and linked to customer in RepairShopr

Scenario E: Validation Testing

  • Try submitting customer form with empty required fields
  • Try submitting with invalid email format
  • Try password less than 8 characters
  • Try mismatched password confirmation
  • Try ticket description less than 10 characters
  • Verify all validation errors display correctly

8. Troubleshooting

Issue: "Failed to search customers"

Possible causes:

  • Invalid or expired REPAIRSHOPR_API_KEY
  • Incorrect REPAIRSHOPR_SUBDOMAIN
  • Network connectivity issues

Solution: Check environment variables and verify API key in RepairShopr settings.

Issue: "Failed to create customer" with portal account

Possible causes:

  • Missing SUPABASE_SERVICE_ROLE_KEY
  • customer_accounts table not created
  • Email already exists in customer_accounts

Solution: Run the database migration and verify Supabase credentials.

Issue: "Unauthorized" when accessing /admin/intake

Possible causes:

  • Session expired
  • Invalid SESSION_SECRET
  • Cookies blocked by browser

Solution: Try logging out and back in. Clear cookies if necessary.

Issue: Build fails on Render

Check:

  • All environment variables are set correctly
  • No TypeScript errors in the build log
  • Node/Bun version compatibility

Local test: Run bun run build locally to identify issues.

Issue: Device types not showing correctly

RepairShopr asset types must match expected values. The system expects:

  • Desktop
  • Laptop
  • Tablet
  • Phone
  • Other

If RepairShopr uses different type names, update the deviceTypes array in DeviceStep.tsx.
