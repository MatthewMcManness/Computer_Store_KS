Lesson 06: JavaScript — The DOM & Events

Connecting JavaScript to the page: selecting elements, modifying content, and responding to user actions

Learning Objectives

  • By the end of this lesson, you will be able to explain what the DOM is and how it relates to HTML
  • By the end of this lesson, you will be able to select elements using querySelector and querySelectorAll
  • By the end of this lesson, you will be able to modify element content, classes, styles, and attributes
  • By the end of this lesson, you will be able to create, insert, and remove DOM elements dynamically
  • By the end of this lesson, you will be able to attach event listeners and handle user interactions
  • By the end of this lesson, you will be able to explain event propagation and why frameworks like React exist

What Is the DOM?

When your browser loads an HTML page, it does not just display the raw text. It parses the HTML and constructs an in-memory representation of the page called the DOM (Document Object Model). The DOM is a tree-shaped data structure where every HTML element becomes a node in the tree.

document | <html> / \ <head> <body> / / \ <title> <header> <main> | / \ <nav> <h1> <p> / | \ <a> <a> <a>

This tree structure is crucial because JavaScript interacts with the DOM, not with the HTML file directly. When JavaScript changes the DOM, the browser re-renders the affected parts of the page. This is how dynamic websites work — JavaScript modifies the DOM tree, and the browser updates what you see on screen.

Analogy: A Building Model
Imagine an architect builds a detailed scale model of a building. The original blueprints (HTML) were used to construct the model (DOM), but once built, the model exists independently. You can rearrange furniture (modify elements), add rooms (create new elements), knock down walls (remove elements), and change paint colors (modify styles) — all by interacting with the model directly. The original blueprints do not change, but the model (and therefore the building you see) does.

The DOM provides a programming interface (API) that JavaScript can use to read and manipulate any part of the page. The starting point for this API is the document object, which represents the entire page.

Selecting Elements

Before you can modify or interact with an element, you need to select it. JavaScript provides several methods for this, but two are by far the most important:

querySelector — Select One Element

document.querySelector() finds the first element that matches a CSS selector:

// Select by element type
const heading = document.querySelector("h1");

// Select by class
const card = document.querySelector(".card");

// Select by ID
const header = document.querySelector("#main-header");

// Select by attribute
const emailInput = document.querySelector('input[type="email"]');

// Complex selectors (any valid CSS selector works)
const firstNavLink = document.querySelector("nav a:first-child");
const submitBtn = document.querySelector("form .btn-submit");

querySelectorAll — Select Multiple Elements

document.querySelectorAll() finds all elements that match a CSS selector, returning a NodeList (similar to an array):

// Select all paragraphs
const paragraphs = document.querySelectorAll("p");

// Select all elements with the "card" class
const cards = document.querySelectorAll(".card");

// Select all links inside the navigation
const navLinks = document.querySelectorAll("nav a");

// Loop through the results
navLinks.forEach(link => {
  console.log(link.textContent);  // Print text of each link
});

// Convert to a real array if needed
const linksArray = Array.from(navLinks);
// or
const linksArray = [...navLinks];

Other Selection Methods

// By ID (older, but still common)
const header = document.getElementById("main-header");

// By class name (returns live HTMLCollection)
const cards = document.getElementsByClassName("card");

// By tag name (returns live HTMLCollection)
const paragraphs = document.getElementsByTagName("p");
Prefer querySelector and querySelectorAll The older methods (getElementById, getElementsByClassName) still work, but querySelector and querySelectorAll are preferred because they accept any CSS selector, making them much more flexible and consistent. You only need to remember one syntax.

Modifying Elements

Once you have selected an element, you can change virtually anything about it.

Changing Text Content

const heading = document.querySelector("h1");

// textContent — gets/sets the raw text (safe, ignores HTML)
heading.textContent = "Welcome to Computer Store KS";

// innerHTML — gets/sets HTML content (can render HTML tags)
heading.innerHTML = "Welcome to <em>Computer Store KS</em>";
Security Warning: innerHTML Never use innerHTML with user-provided data. If a user types <script>alert('hacked')</script> into a form and you render it with innerHTML, that script will execute. This is called a Cross-Site Scripting (XSS) attack. Always use textContent for user data, which treats everything as plain text.

Modifying CSS Classes

The classList property provides methods for adding, removing, and toggling CSS classes:

const card = document.querySelector(".card");

// Add a class
card.classList.add("highlighted");
card.classList.add("urgent", "pinned");  // Multiple at once

// Remove a class
card.classList.remove("highlighted");

// Toggle a class (add if missing, remove if present)
card.classList.toggle("active");

// Check if a class exists
if (card.classList.contains("urgent")) {
  console.log("This card is urgent!");
}

// Replace one class with another
card.classList.replace("old-class", "new-class");

Modifying Inline Styles

const element = document.querySelector(".hero");

// Set individual styles
element.style.backgroundColor = "#0a1481";
element.style.color = "white";
element.style.padding = "2rem";
element.style.borderRadius = "12px";

// Note: CSS property names become camelCase in JavaScript
// background-color → backgroundColor
// font-size → fontSize
// border-radius → borderRadius
// z-index → zIndex
Prefer classList Over style Modifying element.style directly is fine for dynamic values (like setting a width based on a calculation), but for most styling changes, adding/removing CSS classes with classList is better. It keeps your styles in CSS where they belong and keeps JavaScript focused on behavior.

Modifying Attributes

const image = document.querySelector("img");

// Get an attribute
const src = image.getAttribute("src");
const alt = image.getAttribute("alt");

// Set an attribute
image.setAttribute("src", "/images/new-photo.jpg");
image.setAttribute("alt", "Updated photo description");

// Remove an attribute
image.removeAttribute("loading");

// Direct property access (for common attributes)
const link = document.querySelector("a");
link.href = "https://computerstoreks.com";
link.target = "_blank";

const input = document.querySelector("input");
input.value = "Default text";
input.disabled = true;
input.required = true;

Creating and Removing Elements

JavaScript can dynamically create new elements and add them to the page, or remove existing ones.

Creating Elements

// Step 1: Create the element
const card = document.createElement("div");

// Step 2: Configure it
card.className = "card";
card.innerHTML = `
  <h3>Virus Removal</h3>
  <p>We'll clean your computer of all malware.</p>
  <span class="price">$75</span>
`;

// Step 3: Add it to the page
const container = document.querySelector(".services-grid");
container.appendChild(card);  // Adds as the last child

// Other insertion methods
container.prepend(card);       // Add as the FIRST child
container.before(card);        // Add BEFORE the container
container.after(card);         // Add AFTER the container

// Insert before a specific sibling
const reference = container.children[2];
container.insertBefore(card, reference);

Removing Elements

// Modern way (simplest)
const card = document.querySelector(".card");
card.remove();

// Older way (still works)
const parent = card.parentNode;
parent.removeChild(card);

// Remove all children
const container = document.querySelector(".container");
container.innerHTML = "";  // Removes everything inside

Building a Dynamic List

const services = ["Diagnostics", "Virus Removal", "Data Recovery", "OS Install"];

const list = document.querySelector("#service-list");

services.forEach(service => {
  const li = document.createElement("li");
  li.textContent = service;
  li.classList.add("service-item");
  list.appendChild(li);
});

Event Listeners

Events are things that happen in the browser: a user clicks a button, types in an input, scrolls the page, submits a form, moves the mouse, or presses a key. Event listeners let your JavaScript respond to these actions.

addEventListener

const button = document.querySelector("#submit-btn");

// Attach an event listener
button.addEventListener("click", function(event) {
  console.log("Button was clicked!");
  console.log("Clicked element:", event.target);
});

// Using an arrow function (more common in modern code)
button.addEventListener("click", (event) => {
  console.log("Button clicked!");
});

Common Event Types

Event Triggers When Common Use
click Element is clicked Buttons, links, cards
submit Form is submitted Form validation, AJAX submission
input Input value changes (real-time) Live search, character counting
change Input loses focus after changing Select dropdowns, checkboxes
keydown A key is pressed Keyboard shortcuts, key detection
keyup A key is released Search on key release
mouseover Mouse enters an element Hover effects, tooltips
mouseout Mouse leaves an element Hide tooltips
focus Element receives focus Input highlighting
blur Element loses focus Field validation
scroll Page or element is scrolled Sticky headers, infinite scroll
DOMContentLoaded HTML is fully loaded and parsed Initialization code

The Event Object

Every event handler receives an event object containing information about the event:

document.querySelector("#search").addEventListener("input", (event) => {
  // event.target — the element that triggered the event
  console.log("Current value:", event.target.value);

  // event.type — the type of event
  console.log("Event type:", event.type);  // "input"
});

document.addEventListener("keydown", (event) => {
  // event.key — the key that was pressed
  console.log("Key pressed:", event.key);

  // event.ctrlKey, event.shiftKey, event.altKey — modifier keys
  if (event.ctrlKey && event.key === "s") {
    event.preventDefault();  // Prevent browser's default save dialog
    console.log("Custom save triggered!");
  }
});

document.querySelector("a").addEventListener("click", (event) => {
  // event.preventDefault() — stops the default browser behavior
  event.preventDefault();  // Prevents navigation to href
  console.log("Link click intercepted!");
});

Form Handling

Handling form submissions is one of the most common uses of DOM events:

const form = document.querySelector("#contact-form");

form.addEventListener("submit", (event) => {
  // ALWAYS prevent default form submission (page refresh)
  event.preventDefault();

  // Get form values
  const name = document.querySelector("#name").value;
  const email = document.querySelector("#email").value;
  const message = document.querySelector("#message").value;

  // Validate
  if (!name || !email || !message) {
    alert("Please fill in all fields.");
    return;
  }

  // Create data object
  const formData = { name, email, message };
  console.log("Form data:", formData);

  // In a real app, you'd send this to an API:
  // fetch("/api/contact", { method: "POST", body: JSON.stringify(formData) });
});

Using FormData

The FormData API is a cleaner way to get all form values at once:

form.addEventListener("submit", (event) => {
  event.preventDefault();

  const formData = new FormData(form);

  // Get individual values
  const name = formData.get("name");
  const email = formData.get("email");

  // Convert to a plain object
  const data = Object.fromEntries(formData);
  console.log(data);  // { name: "Jane", email: "jane@example.com", message: "..." }
});

Event Propagation: Bubbling and Capturing

When you click a button, you are not just clicking that button — you are also clicking its parent <div>, the <section> that contains it, the <body>, and ultimately the document. Events travel through the DOM tree in a process called propagation.

Event Propagation (click on <button>): CAPTURING PHASE (top-down) BUBBLING PHASE (bottom-up) | ^ v | document document | ^ v | <html> <html> | ^ v | <body> <body> | ^ v | <section> <section> | ^ v | <div> <div> | ^ v | <button> -------TARGET--------- <button>

By default, event listeners fire during the bubbling phase (bottom-up). This means if you click a button, the button's click handler fires first, then its parent's, then its grandparent's, and so on up to the document.

// Bubbling demonstration
document.querySelector(".parent").addEventListener("click", () => {
  console.log("Parent clicked");  // Fires SECOND
});

document.querySelector(".child").addEventListener("click", () => {
  console.log("Child clicked");   // Fires FIRST
});

// Stopping propagation
document.querySelector(".child").addEventListener("click", (event) => {
  event.stopPropagation();  // Parent's handler will NOT fire
  console.log("Only child handles this click");
});

Event Delegation

Event delegation is a powerful pattern that takes advantage of bubbling. Instead of attaching event listeners to every individual item (which is slow and wasteful), you attach a single listener to a parent element and use event.target to determine which child was clicked:

// BAD: Listener on every item (100 items = 100 listeners)
document.querySelectorAll(".ticket-card").forEach(card => {
  card.addEventListener("click", () => {
    console.log("Card clicked");
  });
});

// GOOD: One listener on the parent (1 listener handles all cards)
document.querySelector(".ticket-list").addEventListener("click", (event) => {
  // Find the closest card ancestor of the clicked element
  const card = event.target.closest(".ticket-card");

  if (card) {
    const ticketId = card.dataset.ticketId;
    console.log(`Ticket ${ticketId} clicked`);
  }
});

Event delegation has three major advantages:

  • Performance: One listener instead of hundreds.
  • Dynamic elements: Works for elements added after the listener is attached (since the listener is on the parent, which already exists).
  • Memory efficiency: Fewer event listeners means less memory usage.

Why Frameworks Like React Exist

Now that you understand the DOM and events, let us see why frameworks like React were invented. Consider building a simple ticket counter with vanilla JavaScript:

The Vanilla JavaScript Way (Manual DOM Manipulation)

<!-- HTML -->
<div id="ticket-app">
  <h2>Open Tickets: <span id="count">0</span></h2>
  <ul id="ticket-list"></ul>
  <form id="add-form">
    <input type="text" id="subject" placeholder="Ticket subject">
    <button type="submit">Add Ticket</button>
  </form>
</div>

<script>
// State (data)
let tickets = [];
let nextId = 1;

// DOM references
const countEl = document.querySelector("#count");
const listEl = document.querySelector("#ticket-list");
const formEl = document.querySelector("#add-form");
const inputEl = document.querySelector("#subject");

// Render function — manually update EVERY part of the DOM
function render() {
  // Update count
  countEl.textContent = tickets.length;

  // Clear and rebuild the entire list
  listEl.innerHTML = "";

  tickets.forEach(ticket => {
    const li = document.createElement("li");
    li.textContent = ticket.subject;

    const deleteBtn = document.createElement("button");
    deleteBtn.textContent = "Delete";
    deleteBtn.addEventListener("click", () => {
      tickets = tickets.filter(t => t.id !== ticket.id);
      render();  // Re-render EVERYTHING
    });

    li.appendChild(deleteBtn);
    listEl.appendChild(li);
  });
}

// Event handler
formEl.addEventListener("submit", (event) => {
  event.preventDefault();
  if (!inputEl.value.trim()) return;

  tickets.push({ id: nextId++, subject: inputEl.value });
  inputEl.value = "";
  render();  // Re-render EVERYTHING
});

// Initial render
render();
</script>

The React Way (Declarative)

function TicketApp() {
  const [tickets, setTickets] = useState([]);
  const [subject, setSubject] = useState("");

  const addTicket = (e) => {
    e.preventDefault();
    if (!subject.trim()) return;
    setTickets([...tickets, { id: Date.now(), subject }]);
    setSubject("");
  };

  const deleteTicket = (id) => {
    setTickets(tickets.filter(t => t.id !== id));
  };

  return (
    <div>
      <h2>Open Tickets: {tickets.length}</h2>
      <ul>
        {tickets.map(ticket => (
          <li key={ticket.id}>
            {ticket.subject}
            <button onClick={() => deleteTicket(ticket.id)}>Delete</button>
          </li>
        ))}
      </ul>
      <form onSubmit={addTicket}>
        <input value={subject} onChange={e => setSubject(e.target.value)} />
        <button type="submit">Add Ticket</button>
      </form>
    </div>
  );
}

Notice the fundamental difference:

Aspect Vanilla JavaScript React
Approach Imperative — you tell the browser step-by-step HOW to update the DOM Declarative — you describe WHAT the UI should look like given the data
DOM Updates Manual — you must find and update every element yourself Automatic — React figures out what changed and updates only those parts
State Management You manage variables and manually sync them with the DOM React manages state and re-renders when it changes
Complexity Gets exponentially harder as the app grows Scales much better with complexity

For a simple counter, the vanilla approach works fine. But imagine a real application like the CSK admin dashboard with dozens of interactive components, real-time data, form validation, status filters, and modal dialogs. Managing all of that with manual DOM manipulation would be a nightmare. That is why React exists — and we will learn it in Phase 3.

CSK Connection Interestingly, the CSK codebase includes one significant example of direct DOM manipulation: the spam-detection.ts module. This system tracks user interactions at the DOM level — mouse movements, keyboard presses, click timing, and form focus events — to distinguish humans from bots on the contact form. It uses addEventListener for mousemove, keydown, click, and focus events, collecting behavioral signals over time. This kind of low-level event tracking is one of the few cases where direct DOM access is still necessary even in a React application, because it needs to capture raw browser events that React's event system does not expose.

Practical Example: Interactive Search Filter

Let us build a practical example that combines everything from this lesson — selecting elements, modifying the DOM, and handling events:

<!-- HTML -->
<div class="search-filter">
  <input type="text" id="search" placeholder="Search services...">
  <div class="results-count"><span id="count">0</span> results</div>
  <ul id="service-list">
    <li data-category="repair">Virus Removal</li>
    <li data-category="repair">Screen Replacement</li>
    <li data-category="build">Custom Desktop Build</li>
    <li data-category="data">Data Recovery</li>
    <li data-category="repair">Hardware Diagnostics</li>
    <li data-category="software">OS Installation</li>
    <li data-category="software">Windows Debloat</li>
  </ul>
</div>

<script>
const searchInput = document.querySelector("#search");
const serviceList = document.querySelector("#service-list");
const countDisplay = document.querySelector("#count");

function filterServices() {
  const query = searchInput.value.toLowerCase().trim();
  const items = serviceList.querySelectorAll("li");
  let visibleCount = 0;

  items.forEach(item => {
    const text = item.textContent.toLowerCase();
    const matches = text.includes(query);

    // Show or hide based on match
    item.style.display = matches ? "block" : "none";

    // Highlight matching items
    if (matches && query) {
      item.classList.add("highlighted");
    } else {
      item.classList.remove("highlighted");
    }

    if (matches) visibleCount++;
  });

  // Update count display
  countDisplay.textContent = visibleCount;
}

// Listen for real-time input changes
searchInput.addEventListener("input", filterServices);

// Initial count
filterServices();
</script>

Practice Exercises

  1. Element Selection Practice: Open any web page, open the browser console (F12 > Console tab), and use document.querySelector() to select:
    • The page's main heading
    • The first link on the page
    • An input element (if one exists)
    • All images on the page (use querySelectorAll)
    Print each selection to verify you got the right element.
  2. Toggle Dark Mode: Create an HTML page with a button labeled "Toggle Dark Mode." When clicked, it should toggle a dark-mode class on the <body> element. Add CSS that changes the background to dark and text to light when .dark-mode is present. Use classList.toggle().
  3. Dynamic List Builder: Create a page with a text input, an "Add" button, and an empty <ul>. Each time the user types text and clicks "Add" (or presses Enter), create a new <li> with that text and a "Delete" button. Clicking "Delete" should remove that list item. This is fundamentally the same pattern as a ticket list or task manager.
  4. Character Counter: Create a <textarea> with a character counter below it that updates in real-time as the user types. Display "X / 500 characters" and change the counter color to red when it exceeds 500 characters. Use the input event.
  5. Event Delegation Practice: Create a grid of 20 colored boxes (using a loop). Instead of attaching a click listener to each box, attach a single listener to the parent container. When a box is clicked, toggle a "selected" class on it. Use event.target and classList.toggle().
  6. Form Validator: Build a registration form with name, email, and password fields. Add real-time validation:
    • Name must be at least 2 characters (validate on blur)
    • Email must contain @ and a dot (validate on blur)
    • Password must be at least 8 characters (validate on input, show strength meter)
    • Display error messages below each field using dynamically created elements
    • Prevent form submission if any field is invalid

Key Takeaways

  • The DOM (Document Object Model) is a tree-structured representation of an HTML page that JavaScript can read and manipulate. Changes to the DOM are reflected on screen.
  • document.querySelector() selects the first matching element; document.querySelectorAll() selects all matching elements. Both accept any CSS selector.
  • Modify elements with textContent (safe text), innerHTML (HTML content), classList (CSS classes), style (inline styles), and setAttribute() (attributes).
  • Create elements with document.createElement(), configure them, and add them to the page with appendChild() or append(). Remove them with element.remove().
  • addEventListener() attaches event handlers. Common events include click, submit, input, change, keydown, and mouseover. The event object provides details like event.target and event.preventDefault().
  • Events propagate through the DOM (bubbling). Event delegation leverages this by attaching one listener to a parent instead of many listeners to children.
  • Manual DOM manipulation works for simple cases but becomes unwieldy for complex applications. Frameworks like React automate DOM updates through declarative rendering, which is why the industry adopted them.
