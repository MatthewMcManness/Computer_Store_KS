Admin Portal Architecture

The admin portal is a completely separate section of your application with its own layout, navigation, and design patterns. While the public site is designed to look inviting and market the business, the admin portal is designed for efficiency — employees need to find information fast and complete tasks with minimal clicks.

Admin vs. Public: Key Differences

Aspect Public Site Admin Portal
Layout Top header + bottom footer Sidebar navigation + main content area
Users Anyone on the internet Authenticated employees only
Primary actions Read content, submit contact form Create, read, update, delete data
Styling approach Brand-focused, visually rich Functional, information-dense, utility-focused
SEO Critical (search engines must index) Not needed (blocked by auth, noindex)
Rendering Server Components for SEO Client Components for interactivity

// src/components/admin/AdminSidebar.tsx
'use client';

import Link from 'next/link';
import { usePathname } from 'next/navigation';

interface User {
  name: string;
  email: string;
  role: string;
}

const navItems = [
  { href: '/admin', label: 'Reception', icon: 'home' },
  { href: '/admin/customers', label: 'Customers', icon: 'users' },
  { href: '/admin/businesses', label: 'Businesses', icon: 'building' },
  { href: '/admin/tickets', label: 'Tickets', icon: 'ticket' },
  { href: '/admin/gallery', label: 'Gallery', icon: 'image' },
  { href: '/admin/blog', label: 'Blog Posts', icon: 'file-text' },
  { href: '/admin/blog/new', label: 'New Post', icon: 'plus' },
  { href: '/admin/employees', label: 'Employees', icon: 'shield',
    requiredRole: 'admin' },  // Only visible to admins
];

export default function AdminSidebar({ user }: { user: User }) {
  const pathname = usePathname();

  // Filter nav items by role
  const visibleItems = navItems.filter(item =>
    !item.requiredRole || item.requiredRole === user.role
  );

  function isActive(href: string): boolean {
    if (href === '/admin') {
      return pathname === '/admin';  // Exact match for dashboard
    }
    return pathname.startsWith(href);  // Prefix match for sections
  }

  return (
    <aside className="admin-sidebar">
      <div className="sidebar-header">
        <h2>Computer Store KS</h2>
        <p className="sidebar-subtitle">Admin Portal</p>
      </div>

      <nav className="sidebar-nav">
        {visibleItems.map(item => (
          <Link
            key={item.href}
            href={item.href}
            className={`sidebar-link ${isActive(item.href) ? 'active' : ''}`}
          >
            <span className="sidebar-icon">{item.icon}</span>
            <span className="sidebar-label">{item.label}</span>
          </Link>
        ))}
      </nav>

      <div className="sidebar-footer">
        <div className="user-info">
          <p className="user-name">{user.name}</p>
          <p className="user-role">{user.role}</p>
        </div>
        <form action="/api/auth/logout" method="POST">
          <button type="submit" className="logout-btn">
            Log Out
          </button>
        </form>
      </div>
    </aside>
  );
}
Active State Logic: The dashboard link (/admin) uses exact matching (pathname === '/admin') so it does not highlight when visiting /admin/tickets. All other links use prefix matching (pathname.startsWith(href)) so that /admin/tickets stays highlighted when viewing /admin/tickets/123. This small detail makes a big difference in usability.

Protecting Admin Routes with Middleware

The admin layout check above handles redirection, but you should also protect the API routes that serve admin data. Use Next.js middleware to enforce authentication globally:

// src/middleware.ts
import { NextRequest, NextResponse } from 'next/server';

export function middleware(request: NextRequest) {
  const { pathname } = request.nextUrl;

  // Protect admin pages and admin API routes
  const isAdminRoute = pathname.startsWith('/admin');
  const isAdminApi = pathname.startsWith('/api/blog') &&
    request.method !== 'GET';  // Allow public GET, protect mutations

  if (isAdminRoute || isAdminApi) {
    const sessionCookie = request.cookies.get('session');

    if (!sessionCookie) {
      if (isAdminRoute) {
        return NextResponse.redirect(new URL('/admin/login', request.url));
      }
      return NextResponse.json({ error: 'Unauthorized' }, { status: 401 });
    }
  }

  // Add security headers to all responses
  const response = NextResponse.next();
  response.headers.set('X-Content-Type-Options', 'nosniff');
  response.headers.set('X-Frame-Options', 'DENY');
  response.headers.set('Referrer-Policy', 'strict-origin-when-cross-origin');
  return response;
}

export const config = {
  matcher: ['/admin/:path*', '/api/:path*'],
};

// src/app/admin/blog/page.tsx
'use client';

import { useState, useEffect } from 'react';
import Link from 'next/link';

interface BlogPost {
  id: string;
  title: string;
  slug: string;
  status: 'draft' | 'published';
  category: { name: string } | null;
  created_at: string;
}

export default function AdminBlogList() {
  const [posts, setPosts] = useState<BlogPost[]>([]);
  const [deleteId, setDeleteId] = useState<string | null>(null);

  useEffect(() => {
    fetch('/api/blog?admin=true')
      .then(res => res.json())
      .then(data => setPosts(data));

    const res = await fetch(`/api/blog/${id}`, { method: 'DELETE' });
    if (res.ok) {
      setPosts(prev => prev.filter(p => p.id !== id));
      setDeleteId(null);
    }
  }

  return (
    <div className="admin-blog">
      <div className="page-header">
        <h1>Blog Posts</h1>
        <Link href="/admin/blog/new" className="btn btn-primary">

        </Link>
      </div>

      <table className="data-table">
        <thead>
          <tr>
            <th>Title</th>
            <th>Category</th>
            <th>Status</th>
            <th>Created</th>
            <th>Actions</th>
          </tr>
        </thead>
        <tbody>
          {posts.map(post => (
            <tr key={post.id}>
              <td>
                <Link href={`/admin/blog/${post.id}`}>{post.title}</Link>
              </td>
              <td>{post.category?.name ?? 'Uncategorized'}</td>
              <td>
                <span className={`badge badge-${post.status}`}>
                  {post.status}
                </span>
              </td>
              <td>{new Date(post.created_at).toLocaleDateString()}</td>
              <td className="actions">
                <Link href={`/admin/blog/${post.id}`} className="btn-sm">
                  Edit
                </Link>
                <button
                  onClick={() => setDeleteId(post.id)}
                  className="btn-sm btn-danger"
                >
                  Delete
                </button>
              </td>
            </tr>
          ))}
        </tbody>
      </table>

      {/* Confirmation Dialog */}
      {deleteId && (
        <div className="modal-overlay">
          <div className="confirm-dialog">
            <h3>Delete Post?</h3>

            <div className="dialog-actions">

              <button
                onClick={() => handleDelete(deleteId)}
                className="btn-danger"
              >
                Delete
              </button>
            </div>
          </div>
        </div>
      )}
    </div>
  );
}

Blog Post Editor (Create and Edit)

// src/app/admin/blog/[id]/page.tsx
'use client';

import { useState, useEffect } from 'react';
import { useRouter, useParams } from 'next/navigation';

export default function BlogPostEditor() {
  const router = useRouter();
  const params = useParams();
  const isNew = params.id === 'new';

  const [form, setForm] = useState({
    title: '',
    slug: '',
    content: '',
    excerpt: '',
    category_id: '',
    status: 'draft' as 'draft' | 'published',
    featured_image: '',
  });
  const [saving, setSaving] = useState(false);
  const [toast, setToast] = useState<string | null>(null);

  useEffect(() => {
    if (!isNew) {
      fetch(`/api/blog/${params.id}`)
        .then(res => res.json())
        .then(data => setForm(data));
    }
  }, [params.id, isNew]);

  // Auto-generate slug from title
  function handleTitleChange(title: string) {
    setForm(prev => ({
      ...prev,
      title,
      slug: title
        .toLowerCase()
        .replace(/[^a-z0-9]+/g, '-')
        .replace(/(^-|-$)/g, ''),
    }));
  }

  async function handleSave() {
    setSaving(true);
    try {
      const url = isNew ? '/api/blog' : `/api/blog/${params.id}`;
      const method = isNew ? 'POST' : 'PUT';

      const res = await fetch(url, {
        method,
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(form),
      });

      if (!res.ok) throw new Error('Save failed');

      setToast('Post saved successfully!');
      setTimeout(() => setToast(null), 3000);

      if (isNew) {
        const data = await res.json();
        router.push(`/admin/blog/${data.id}`);
      }
    } catch {
      setToast('Error saving post. Please try again.');
    } finally {
      setSaving(false);
    }
  }

  return (
    <div className="blog-editor">
      <div className="editor-header">
        <h1>{isNew ? 'New Post' : 'Edit Post'}</h1>
        <div className="editor-actions">
          <select
            value={form.status}
            onChange={e => setForm(prev => ({
              ...prev, status: e.target.value as 'draft' | 'published'
            }))}
          >
            <option value="draft">Draft</option>
            <option value="published">Published</option>
          </select>
          <button
            onClick={handleSave}
            disabled={saving}
            className="btn btn-primary"
          >
            {saving ? 'Saving...' : 'Save'}
          </button>
        </div>
      </div>

      <div className="editor-form">
        <div className="form-field">
          <label htmlFor="title">Title</label>
          <input
            id="title"
            type="text"
            value={form.title}
            onChange={e => handleTitleChange(e.target.value)}
            placeholder="Enter post title"
          />
        </div>

        <div className="form-field">
          <label htmlFor="slug">Slug</label>
          <input
            id="slug"
            type="text"
            value={form.slug}
            onChange={e => setForm(prev => ({ ...prev, slug: e.target.value }))}
            placeholder="url-friendly-slug"
          />
        </div>

        <div className="form-field">
          <label htmlFor="excerpt">Excerpt</label>
          <textarea
            id="excerpt"
            rows={2}
            value={form.excerpt}
            onChange={e => setForm(prev => ({ ...prev, excerpt: e.target.value }))}
            placeholder="Brief description for listings and SEO"
          />
        </div>

        <div className="form-field">
          <label htmlFor="content">Content (Markdown)</label>
          <textarea
            id="content"
            rows={20}
            value={form.content}
            onChange={e => setForm(prev => ({ ...prev, content: e.target.value }))}
            placeholder="Write your post in Markdown..."
            className="code-textarea"
          />
        </div>
      </div>

      {/* Toast Notification */}
      {toast && (
        <div className="toast" role="status">
          {toast}
        </div>
      )}
    </div>
  );
}
Analogy: Think of the blog editor like a word processor (Google Docs or Word). The list page is your "File → Open" dialog — it shows all documents with options to open, edit, or delete. The editor page is the actual document workspace where you type, format, and save. The toast notification is like the "Saved" indicator in Google Docs — brief, non-intrusive confirmation.

Data Table Patterns

Admin interfaces are full of tables. A well-built data table supports sorting, filtering, and pagination. Here is a reusable pattern:

Sorting

// Sorting state and handler
const [sortColumn, setSortColumn] = useState('created_at');
const [sortDirection, setSortDirection] = useState<'asc' | 'desc'>('desc');

function handleSort(column: string) {
  if (sortColumn === column) {
    setSortDirection(prev => prev === 'asc' ? 'desc' : 'asc');
  } else {
    setSortColumn(column);
    setSortDirection('asc');
  }
}

// In the table header
<th onClick={() => handleSort('title')} className="sortable">
  Title {sortColumn === 'title' && (sortDirection === 'asc' ? '↑' : '↓')}
</th>

Pagination

const ITEMS_PER_PAGE = 20;
const [currentPage, setCurrentPage] = useState(1);

const totalPages = Math.ceil(totalItems / ITEMS_PER_PAGE);
const startIndex = (currentPage - 1) * ITEMS_PER_PAGE;

// Pagination controls
<div className="pagination">
  <button
    onClick={() => setCurrentPage(prev => Math.max(1, prev - 1))}
    disabled={currentPage === 1}
  >
    Previous
  </button>
  <span>Page {currentPage} of {totalPages}</span>
  <button
    onClick={() => setCurrentPage(prev => Math.min(totalPages, prev + 1))}
    disabled={currentPage === totalPages}
  >
    Next
  </button>
</div>

Form Patterns: Modals, Dialogs, and Toasts

Edit Modal

Modals let employees edit data without leaving the current page. The pattern is: click "Edit" → modal opens with form → save → modal closes and list refreshes.

// Reusable modal component pattern
function Modal({
  isOpen, onClose, title, children
}: {
  isOpen: boolean;
  onClose: () => void;
  title: string;
  children: React.ReactNode;
}) {
  if (!isOpen) return null;

  return (
    <div className="modal-overlay" onClick={onClose}>
      <div
        className="modal-content"
        onClick={e => e.stopPropagation()}
        role="dialog"
        aria-modal="true"
        aria-labelledby="modal-title"
      >
        <div className="modal-header">
          <h2 id="modal-title">{title}</h2>
          <button onClick={onClose} aria-label="Close">&times;</button>
        </div>
        <div className="modal-body">
          {children}
        </div>
      </div>
    </div>
  );
}

Confirmation Dialog

function ConfirmDialog({
  isOpen, onConfirm, onCancel, message
}: {
  isOpen: boolean;
  onConfirm: () => void;
  onCancel: () => void;
  message: string;
}) {
  if (!isOpen) return null;

  return (
    <div className="modal-overlay">
      <div className="confirm-dialog" role="alertdialog">
        <p>{message}</p>
        <div className="dialog-actions">
          <button onClick={onCancel}>Cancel</button>
          <button onClick={onConfirm} className="btn-danger">
            Confirm Delete
          </button>
        </div>
      </div>
    </div>
  );
}

Toast Notifications

// Simple toast pattern
function useToast() {
  const [toast, setToast] = useState<{
    message: string;
    type: 'success' | 'error';
  } | null>(null);

  function showToast(message: string, type: 'success' | 'error' = 'success') {
    setToast({ message, type });
    setTimeout(() => setToast(null), 3000);
  }

  const ToastComponent = toast ? (
    <div className={`toast toast-${toast.type}`} role="status">
      {toast.message}
    </div>
  ) : null;

  return { showToast, ToastComponent };
}
Accessibility for Modals: Always include role="dialog", aria-modal="true", and aria-labelledby on modal containers. Trap keyboard focus inside the modal (the user should not be able to Tab to elements behind the modal). Close on Escape key press. Return focus to the trigger button when the modal closes.

Role-Based UI

Not all employees should see all features. A receptionist does not need to manage employees. A technician does not need to edit blog posts. Role-based UI gating shows or hides features based on the logged-in user's role.

// Pattern: Role-based component visibility
interface RoleGateProps {
  allowedRoles: string[];
  userRole: string;
  children: React.ReactNode;
  fallback?: React.ReactNode;
}

function RoleGate({ allowedRoles, userRole, children, fallback }: RoleGateProps) {
  if (!allowedRoles.includes(userRole)) {
    return fallback ?? null;  // Hide or show alternative
  }
  return <>{children}</>;
}

// Usage in a component
<RoleGate allowedRoles={['admin', 'manager']} userRole={user.role}>
  <Link href="/admin/employees">Employee Management</Link>
</RoleGate>

<RoleGate
  allowedRoles={['admin']}
  userRole={user.role}
  fallback={<p>You do not have permission to view this section.</p>}
>
  <DangerZoneSettings />
</RoleGate>
Critical Security Note: Role-based UI is a convenience feature, not a security measure. Hiding a button does not prevent someone from calling the API directly. You must also enforce role checks on the server side — in your API routes and middleware. If a technician should not be able to delete blog posts, the DELETE /api/blog/[id] endpoint must verify the user's role and return 403 Forbidden for unauthorized roles.

Mobile Admin: Responsive Admin Layouts

Employees sometimes need to check the admin portal from a phone or tablet — perhaps checking ticket status while away from their desk. The admin layout needs to adapt:

  • Sidebar: Collapses into a hamburger menu or horizontal scroll bar on mobile
  • Tables: Scroll horizontally or switch to a card layout on narrow screens
  • Modals: Become full-screen on mobile
  • Filter buttons: Switch from a horizontal row to a collapsible grid
/* Mobile admin: status filter buttons become a grid */
@media (max-width: 768px) {

    display: grid;

  /* Tables scroll horizontally */
  .data-table-wrapper {
    overflow-x: auto;
    -webkit-overflow-scrolling: touch;
  }

  /* Modals go full-screen */
  .modal-content {
    width: 100%;
    height: 100%;
    max-width: none;
    border-radius: 0;
  }
}

Exercises

  1. Admin Layout: Create an admin layout with a fixed sidebar containing at least 5 navigation links. Implement active state highlighting. Style it with a dark background, light text, and a blue accent for the active link.
  2. Protected Routes: Implement authentication middleware that checks for a session cookie. Redirect unauthenticated users to a login page. Test by visiting /admin without being logged in.
  3. Dashboard: Build a dashboard page with four metric cards (use mock data), a recent items table, and an alert banner that appears when a metric exceeds a threshold. Add auto-refresh using setInterval.
  4. Blog CRUD: Build a complete blog management system: list page with a data table, create/edit page with a form (title, slug, content, status), delete with confirmation dialog, and toast notifications for success/error.
  5. Data Table: Build a reusable data table component that supports column sorting (click header to sort), search filtering, and pagination (20 items per page with Previous/Next buttons).
  6. Modal System: Create a reusable Modal component that supports: opening/closing, click-outside-to-close, Escape key to close, focus trapping, and proper ARIA attributes. Use it for an "Edit Customer" modal.
  7. Role-Based UI: Create a RoleGate component that conditionally renders children based on the user's role. Apply it to hide certain sidebar links and action buttons from non-admin users.
  8. Mobile Admin: Make your admin layout responsive. The sidebar should collapse into a hamburger menu on mobile. Tables should scroll horizontally. Test on a phone-sized viewport in DevTools.

Key Takeaways

  • Admin portals use a sidebar layout with persistent navigation, designed for efficiency rather than marketing aesthetics.
  • Protect admin routes at two levels: middleware for route guarding and server-side checks in API routes for data access control.
  • Dashboards surface key metrics, urgent alerts, and recent activity at a glance. Auto-refresh keeps data current without manual page reloads.
  • CRUD interfaces follow a consistent pattern: list page with table → create/edit form → delete with confirmation → toast notification for feedback.
  • Sidebar active state requires exact matching for the root route and prefix matching for section routes.
  • Data tables need sorting (click column headers), filtering (search input), and pagination (page controls) to be usable with large datasets.
  • Modals, confirmation dialogs, and toast notifications are the three essential feedback patterns in admin interfaces.
  • Role-based UI hides features from unauthorized users in the interface, but role checks must also be enforced on the server side for actual security.
  • Mobile admin is important for on-the-go access. Sidebars collapse, tables scroll horizontally, and modals go full-screen on small viewports.
