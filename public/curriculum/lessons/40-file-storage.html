Lesson 40: File Storage & Image Management

Uploading, storing, processing, and serving files and images in your web application

Learning Objectives

  • Compare file storage options: Supabase Storage, AWS S3, GitHub API, and Cloudinary
  • Handle file uploads using multipart form data and the FormData API
  • Upload, download, delete, and serve files through Supabase Storage
  • Use the GitHub API (Octokit) to store and manage files in a repository
  • Process images on the server with the sharp library for resizing and format conversion
  • Implement secure file naming strategies using UUIDs and sanitization
  • Validate file types, enforce size limits, and understand security concerns
  • Build a complete client-side upload flow: file input, preview, upload, and display

File Storage Options Compared

When your application needs to store files (images, documents, PDFs), you have several options. Each has tradeoffs in terms of cost, complexity, and features:

Service Best For Cost Complexity Features
Supabase Storage General file storage with database integration Free tier: 1 GB Low Buckets, public URLs, access policies, CDN
AWS S3 Enterprise-scale storage Pay-per-use ($0.023/GB/mo) Medium Virtually unlimited, lifecycle rules, versioning
GitHub API Version-controlled file storage Free (within repo limits) Medium Version history, branch-based, commit tracking
Cloudinary Image-heavy applications Free tier: 25 GB Low Auto-resize, format conversion, CDN, transformations
CSK Connection CSK uses two storage solutions: GitHub API (via the @octokit/rest library) for gallery images, and Supabase Storage (or external URLs) for blog images. Gallery images are stored as version-controlled files in the GitHub repository, which means every image change is tracked in git history. Blog images can be uploaded to Supabase Storage or referenced as external URLs.

File Upload Handling

When a user uploads a file through a web form, the browser sends the data using a format called multipart form data. This is different from JSON — it can handle binary data (like images) alongside text fields.

The HTML File Input

<!-- Client-side: file input in a form -->
<form onSubmit={handleUpload}>
  <input
    type="file"
    accept="image/jpeg,image/png,image/webp"
    onChange={handleFileSelect}
  />
  <button type="submit">Upload</button>
</form>

The FormData API

To send files from the browser to your server, use the FormData API. Unlike JSON, FormData can carry binary file data:

// Client-side: sending a file to your API route
async function handleUpload(file: File) {
  const formData = new FormData();
  formData.append('file', file);           // The actual file
  formData.append('title', 'My Photo');    // Additional text fields

  const response = await fetch('/api/gallery/upload', {
    method: 'POST',
    body: formData,
    // IMPORTANT: Do NOT set Content-Type header!
    // The browser sets it automatically with the correct boundary
  });

  const result = await response.json();
  if (result.success) {
    console.log('Uploaded! URL:', result.url);
  }
}
Never Set Content-Type for FormData When sending FormData, the browser automatically sets the Content-Type header to multipart/form-data with a unique boundary string. If you manually set the Content-Type header, the boundary will be missing and the server will not be able to parse the upload. Let the browser handle it.

Receiving Files on the Server

// Server-side: receiving a file upload in a Next.js API route
import { NextRequest, NextResponse } from 'next/server';

export async function POST(request: NextRequest) {
  // Parse the multipart form data
  const formData = await request.formData();

  // Get the file
  const file = formData.get('file') as File | null;
  if (!file) {
    return NextResponse.json(
      { error: 'No file provided' },
      { status: 400 }
    );
  }

  // Validate the file
  const MAX_SIZE = 10 * 1024 * 1024; // 10 MB
  if (file.size > MAX_SIZE) {
    return NextResponse.json(
      { error: 'File too large. Maximum size is 10 MB.' },
      { status: 400 }
    );
  }

  const ALLOWED_TYPES = ['image/jpeg', 'image/png', 'image/webp'];
  if (!ALLOWED_TYPES.includes(file.type)) {
    return NextResponse.json(
      { error: 'Invalid file type. Allowed: JPEG, PNG, WebP.' },
      { status: 400 }
    );
  }

  // Convert the file to a Buffer for processing
  const buffer = Buffer.from(await file.arrayBuffer());

  // Get additional form fields
  const title = formData.get('title') as string;

  // ... store the file (see following sections)
  return NextResponse.json({ success: true });
}

Configuring Upload Size Limits

Next.js has a default body size limit that you need to increase for file uploads. Configure this in next.config.mjs:

// next.config.mjs
const nextConfig = {
  experimental: {
    serverActions: {
      bodySizeLimit: '100mb',  // Increase for large uploads
    },
  },
  // For API routes specifically
  api: {
    bodyParser: {
      sizeLimit: '100mb',
    },
  },
};

export default nextConfig;
CSK Connection CSK's next.config.mjs sets the body size limit to 100 MB to support large image uploads for the gallery. The upload API routes at /api/gallery/upload and /api/blog/upload both use request.formData() to receive files.

Supabase Storage

Supabase Storage organizes files into buckets (similar to folders). Each bucket can be public (files accessible via URL) or private (requires authentication).

Creating a Bucket

-- In the Supabase dashboard SQL Editor
-- Create a public bucket for blog images
INSERT INTO storage.buckets (id, name, public)
VALUES ('blog-images', 'blog-images', true);

-- Create a private bucket for user documents
INSERT INTO storage.buckets (id, name, public)
VALUES ('user-docs', 'user-docs', false);

Uploading Files

import { createClient } from '@supabase/supabase-js';

const supabase = createClient(
  process.env.NEXT_PUBLIC_SUPABASE_URL!,
  process.env.SUPABASE_SERVICE_ROLE_KEY!  // Service role for server-side
);

async function uploadToSupabase(
  file: Buffer,
  filename: string,
  contentType: string
) {
  const { data, error } = await supabase.storage
    .from('blog-images')                    // Bucket name
    .upload(`posts/${filename}`, file, {     // Path within bucket
      contentType,
      upsert: true,                         // Overwrite if exists
    });

  if (error) {
    throw new Error(`Upload failed: ${error.message}`);
  }

  return data.path; // "posts/my-image.jpg"
}

Getting Public URLs

// Get the public URL for a file in a public bucket
function getPublicUrl(path: string): string {
  const { data } = supabase.storage
    .from('blog-images')
    .getPublicUrl(path);

  return data.publicUrl;
  // Returns: https://xxx.supabase.co/storage/v1/object/public/blog-images/posts/my-image.jpg
}

Deleting Files

async function deleteFromSupabase(path: string) {
  const { error } = await supabase.storage
    .from('blog-images')
    .remove([path]);  // Array of paths to delete

  if (error) {
    throw new Error(`Delete failed: ${error.message}`);
  }
}

Storage Access Policies

Like Row-Level Security (RLS) for tables, you can set policies on storage buckets:

-- Allow anyone to view public bucket files
CREATE POLICY "Public Access"
ON storage.objects FOR SELECT
USING (bucket_id = 'blog-images');

-- Only authenticated admins can upload
CREATE POLICY "Admin Upload"
ON storage.objects FOR INSERT
WITH CHECK (
  bucket_id = 'blog-images'
  AND auth.role() = 'authenticated'
);

GitHub API for File Storage

Storing files in a GitHub repository via the API is an unconventional but effective approach. Every file change is tracked in git history, you get free CDN through GitHub's raw file URLs, and it integrates naturally with your deployment pipeline.

Using Octokit

Octokit is the official GitHub API client library for JavaScript:

import { Octokit } from '@octokit/rest';

// Initialize with a Personal Access Token
const octokit = new Octokit({
  auth: process.env.GITHUB_TOKEN,
});

Creating/Uploading Files

async function uploadImageToGitHub(
  filename: string,
  imageBuffer: Buffer,
  commitMessage: string
) {
  const path = `public/assets/gallery/${filename}`;

  // Check if file already exists (to get its SHA for updates)
  let existingSha: string | undefined;
  try {
    const { data } = await octokit.repos.getContent({
      owner: process.env.GITHUB_OWNER!,
      repo: process.env.GITHUB_REPO!,
      path,
      ref: process.env.GITHUB_BRANCH!,
    });
    if ('sha' in data) {
      existingSha = data.sha;
    }
  } catch {
    // File does not exist yet, that is fine
  }

  // Create or update the file
  const { data } = await octokit.repos.createOrUpdateFileContents({
    owner: process.env.GITHUB_OWNER!,
    repo: process.env.GITHUB_REPO!,
    path,
    message: commitMessage,
    content: imageBuffer.toString('base64'),  // GitHub API requires Base64
    branch: process.env.GITHUB_BRANCH!,
    sha: existingSha,  // Required for updates, omit for new files
  });

  return {
    sha: data.commit.sha,
    url: data.commit.html_url,
    path: `./${path}`,
  };
}
Base64 Encoding The GitHub API requires file content to be Base64-encoded. Base64 converts binary data (like image bytes) into a text string that can be safely transmitted in JSON. The encoded string is about 33% larger than the original binary, but it is the standard way to include binary data in text-based APIs. In Node.js, use buffer.toString('base64') to encode and Buffer.from(string, 'base64') to decode.

Deleting Files

async function deleteFileFromGitHub(path: string, commitMessage: string) {
  // First get the current SHA (required for deletion)
  const { data } = await octokit.repos.getContent({
    owner: process.env.GITHUB_OWNER!,
    repo: process.env.GITHUB_REPO!,
    path,
    ref: process.env.GITHUB_BRANCH!,
  });

  if (!('sha' in data)) {
    throw new Error('Could not get file SHA');
  }

  // Delete the file
  await octokit.repos.deleteFile({
    owner: process.env.GITHUB_OWNER!,
    repo: process.env.GITHUB_REPO!,
    path,
    message: commitMessage,
    sha: data.sha,
    branch: process.env.GITHUB_BRANCH!,
  });
}

Server-Side Image Processing

Uploaded images often need processing before storage: resizing for thumbnails, converting to efficient formats, compressing for faster loading. The sharp library is the industry-standard tool for server-side image processing in Node.js.

import sharp from 'sharp';

// Resize an image to fit within maximum dimensions
async function processImage(
  inputBuffer: Buffer,
  maxWidth: number = 1200,
  maxHeight: number = 800
): Promise<Buffer> {
  return sharp(inputBuffer)
    .resize(maxWidth, maxHeight, {
      fit: 'inside',        // Maintain aspect ratio, fit within bounds
      withoutEnlargement: true, // Do not upscale small images
    })
    .jpeg({ quality: 85 })  // Convert to JPEG at 85% quality
    .toBuffer();
}

// Create a thumbnail
async function createThumbnail(
  inputBuffer: Buffer,
  size: number = 300
): Promise<Buffer> {
  return sharp(inputBuffer)
    .resize(size, size, {
      fit: 'cover',         // Crop to fill the square
      position: 'center',   // Crop from center
    })
    .webp({ quality: 80 })  // Use WebP for smaller thumbnails
    .toBuffer();
}

// Get image metadata
async function getImageInfo(buffer: Buffer) {
  const metadata = await sharp(buffer).metadata();
  return {
    width: metadata.width,
    height: metadata.height,
    format: metadata.format,
    size: buffer.length,
  };
}

Format Conversion Guide

Format Best For Quality File Size Browser Support
JPEG Photographs, complex images Good (lossy) Medium Universal
PNG Screenshots, images with text/transparency Perfect (lossless) Large Universal
WebP General web use (replaces both JPEG and PNG) Excellent Small (25-35% smaller than JPEG) Modern browsers (97%+)
AVIF Best compression for photos Excellent Very small (50% smaller than JPEG) Growing (85%+)

File Naming Strategies

Never use the original filename from the user's upload directly. User filenames can contain spaces, special characters, unicode, or even path traversal attacks (../../etc/passwd). Always generate or sanitize filenames on the server.

Strategy 1: UUID-Based Names

import { randomUUID } from 'crypto';

function generateSafeFilename(originalName: string): string {
  const extension = originalName.split('.').pop()?.toLowerCase() || 'jpg';
  const uuid = randomUUID();
  return `${uuid}.${extension}`;
  // Result: "a1b2c3d4-e5f6-7890-abcd-ef1234567890.jpg"
}

Strategy 2: Timestamp-Based Names

function generateTimestampFilename(originalName: string): string {
  const extension = originalName.split('.').pop()?.toLowerCase() || 'jpg';
  const timestamp = Date.now();
  const random = Math.random().toString(36).substring(2, 8);
  return `${timestamp}-${random}.${extension}`;
  // Result: "1706800000000-a1b2c3.jpg"
}

Strategy 3: Sanitized Original Names

function sanitizeFilename(originalName: string): string {
  return originalName
    .toLowerCase()
    .replace(/[^a-z0-9.-]/g, '-')   // Replace special chars with hyphens
    .replace(/-+/g, '-')             // Collapse multiple hyphens
    .replace(/^-|-$/g, '');          // Remove leading/trailing hyphens
  // "My Photo (1).JPEG" becomes "my-photo-1-.jpeg"
}
Security: Validate File Types on the Server Never trust the file extension or MIME type sent by the browser — they can be faked. On the server, read the file's "magic bytes" (the first few bytes that identify the file format) to verify it actually is the type it claims to be. For images, using sharp to read metadata will throw an error if the file is not a valid image.

Client-Side Upload Flow

A good upload experience includes file selection, preview before upload, a progress indicator, and displaying the uploaded result:

// React component for image upload
'use client';

import { useState, useRef } from 'react';

export function ImageUploader() {
  const [preview, setPreview] = useState<string | null>(null);
  const [uploading, setUploading] = useState(false);
  const [uploadedUrl, setUploadedUrl] = useState<string | null>(null);
  const fileInputRef = useRef<HTMLInputElement>(null);

  // Step 1: User selects a file - show preview
  function handleFileSelect(event: React.ChangeEvent<HTMLInputElement>) {
    const file = event.target.files?.[0];
    if (!file) return;

    // Client-side validation
    if (file.size > 10 * 1024 * 1024) {
      alert('File must be under 10 MB');
      return;
    }

    // Generate preview using FileReader
    const reader = new FileReader();
    reader.onload = (e) => {
      setPreview(e.target?.result as string);
    };
    reader.readAsDataURL(file);
  }

  // Step 2: User confirms - upload to server
  async function handleUpload() {
    const file = fileInputRef.current?.files?.[0];
    if (!file) return;

    setUploading(true);

    try {
      const formData = new FormData();
      formData.append('file', file);

      const response = await fetch('/api/gallery/upload', {
        method: 'POST',
        body: formData,
      });

      const result = await response.json();

      if (result.success) {
        setUploadedUrl(result.url);
        setPreview(null);
      } else {
        alert(result.error || 'Upload failed');
      }
    } catch (error) {
      alert('Upload error. Please try again.');
    } finally {
      setUploading(false);
    }
  }

  return (
    <div>
      <input
        ref={fileInputRef}
        type="file"
        accept="image/jpeg,image/png,image/webp"
        onChange={handleFileSelect}
      />

      {/* Preview before upload */}
      {preview && (
        <div>
          <img src={preview} alt="Preview" style={{ maxWidth: 300 }} />
          <button onClick={handleUpload} disabled={uploading}>
            {uploading ? 'Uploading...' : 'Confirm Upload'}
          </button>
        </div>
      )}

      {/* Show uploaded result */}
      {uploadedUrl && (
        <div>
          <p>Upload successful!</p>
          <img src={uploadedUrl} alt="Uploaded" style={{ maxWidth: 300 }} />
        </div>
      )}
    </div>
  );
}

Progress Indicators

For large file uploads, showing progress improves the user experience. The XMLHttpRequest API provides upload progress events (the Fetch API does not natively support this):

// Upload with progress tracking
function uploadWithProgress(
  file: File,
  url: string,
  onProgress: (percent: number) => void
): Promise<unknown> {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest();
    const formData = new FormData();
    formData.append('file', file);

    // Track upload progress
    xhr.upload.addEventListener('progress', (event) => {
      if (event.lengthComputable) {
        const percent = Math.round((event.loaded / event.total) * 100);
        onProgress(percent);
      }
    });

    xhr.addEventListener('load', () => {
      if (xhr.status >= 200 && xhr.status < 300) {
        resolve(JSON.parse(xhr.responseText));
      } else {
        reject(new Error(`Upload failed: ${xhr.status}`));
      }
    });

    xhr.addEventListener('error', () => reject(new Error('Network error')));

    xhr.open('POST', url);
    xhr.send(formData);
  });
}

File Upload Security

File uploads are one of the most dangerous features in a web application. Without proper security, attackers can upload malicious files that compromise your server or your users.

Security Checklist

Check Why How
File type validation Prevent uploading executable files or scripts Check MIME type AND magic bytes on the server
File size limit Prevent denial-of-service via huge uploads Enforce in Next.js config AND in your route handler
Filename sanitization Prevent path traversal (../../etc/passwd) Generate new filenames server-side (UUID or timestamp)
Authentication required Only authorized users should upload Check session/auth before processing the upload
Storage isolation Keep uploads separate from application code Store in external service (Supabase, GitHub), not in app directory
No direct execution Uploaded files must never be executed as code Serve files as static assets, never import or require them
The Virus Scanning Concept In high-security environments, uploaded files are scanned for malware before being stored. Services like ClamAV (open source) or commercial solutions can scan files in a processing pipeline. For most small business applications, validating file types and sizes provides adequate protection, but be aware that this level of security exists for applications that handle sensitive uploads.

Key Takeaways

  • Choose your storage based on needs: Supabase Storage for general files, GitHub API for version-controlled files, Cloudinary for image-heavy apps with transformation needs, AWS S3 for enterprise scale.
  • File uploads use multipart form data (FormData API), not JSON. Never manually set the Content-Type header when sending FormData.
  • Supabase Storage organizes files into buckets with access policies. Public buckets provide CDN-backed URLs; private buckets require authentication.
  • The GitHub API stores files as Base64-encoded content in git commits. Every change is version-tracked. Use @octokit/rest for a clean TypeScript API.
  • Process images server-side with sharp: resize to reasonable dimensions, convert to efficient formats (WebP), and compress for faster loading.
  • Always generate filenames on the server using UUIDs or timestamps. Never use the original filename from the user's upload without sanitization.
  • Validate file uploads on the server: check file type (MIME type and magic bytes), enforce size limits, require authentication, and store files externally (not in your application directory).
  • Build a good upload UX: file preview before upload, progress indicators for large files, clear success/error feedback.
