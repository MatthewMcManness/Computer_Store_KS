# Task: API Proxy Routes

## Description
Create Next.js API routes that proxy requests to the RepairShopr API and Supabase. These server-side routes keep API tokens secure and provide a clean interface for the frontend intake wizard.

## Acceptance Criteria
- [ ] All routes require employee authentication
- [ ] Customer search endpoint working
- [ ] Customer creation endpoint (RepairShopr + Supabase account)
- [ ] Asset/device list endpoint
- [ ] Asset/device creation endpoint
- [ ] Ticket creation endpoint
- [ ] Business search/creation endpoints
- [ ] Proper error responses with meaningful messages
- [ ] Input validation on all endpoints

## Technical Details

### Routes to Create
```
src/app/api/repairshopr/
├── customers/
│   ├── route.ts           # GET (search), POST (create)
│   └── [id]/
│       ├── route.ts       # GET (by ID)
│       └── assets/
│           └── route.ts   # GET (customer's devices)
├── assets/
│   └── route.ts           # POST (create device)
├── tickets/
│   └── route.ts           # POST (create ticket)
└── businesses/
    └── route.ts           # GET (search), POST (create)
```

### Request/Response Examples

**Search Customers**
```typescript
GET /api/repairshopr/customers?q=john
Response: { customers: RepairShoprCustomer[] }
```

**Create Customer**
```typescript
POST /api/repairshopr/customers
Body: {
  firstname, lastname, email, phone, address?,
  password?,  // If provided, create Supabase account
  business_id?
}
Response: { customer: RepairShoprCustomer, portal_account_created: boolean }
```

**Create Ticket**
```typescript
POST /api/repairshopr/tickets
Body: { customer_id, asset_id?, subject, problem_type }
Response: { ticket: RepairShoprTicket }
```

### Auth Middleware
- Use existing auth from `src/lib/auth.ts`
- Return 401 if not authenticated
- Only employees (RepairShopr users) can access these routes
