Phase 4: Next.js

API Route Handlers

Build backend API endpoints right inside your Next.js app -- no Express server needed.

What You Will Learn

  • Understand what API routes are and why Next.js includes them
  • Create route handler files using the route.ts convention
  • Export functions for HTTP methods: GET, POST, PUT, DELETE
  • Read request data: headers, query params, JSON body
  • Return responses with proper status codes and JSON
  • Build a complete CRUD API for a real-world feature
  • Handle errors with try/catch and appropriate status codes
  • Test API routes with the browser, curl, and Postman

What Are API Routes?

In the previous lesson, you learned that Server Components can fetch data directly from databases. So why do we need API routes at all? Because not everything happens inside a page render:

  • Form submissions: A contact form needs to POST data somewhere
  • External integrations: Webhooks from other services need an endpoint to hit
  • Client-side actions: A Client Component's "Delete" button needs to call an endpoint
  • Third-party consumers: Mobile apps or other services might use your API
  • CRUD operations: Creating, updating, and deleting data needs dedicated endpoints

API routes are backend endpoints that live inside your Next.js application. They run on the server, have access to databases and secrets, and respond with JSON data. You do not need a separate Express or Fastify server.

Analogy: If your Next.js app is a restaurant, the pages are the dining room (what customers see), and the API routes are the kitchen's order window -- the place where the front-of-house staff sends requests and receives prepared responses.

File Convention: route.ts

API routes follow the same file-based routing as pages, but use route.ts instead of page.tsx. They live in the src/app/api/ directory:

src/app/api/
├── blog/
│   ├── route.ts              # GET /api/blog, POST /api/blog
│   └── [id]/
│       └── route.ts          # GET /api/blog/:id, PUT /api/blog/:id, DELETE /api/blog/:id
├── contact/
│   └── route.ts              # POST /api/contact
├── gallery/
│   ├── route.ts              # GET /api/gallery, POST /api/gallery
│   └── [id]/
│       └── route.ts          # GET /api/gallery/:id, PUT, DELETE
└── health/
    └── route.ts              # GET /api/health

The URL mapping works identically to page routing:

File Path URL
src/app/api/blog/route.ts/api/blog
src/app/api/blog/[id]/route.ts/api/blog/:id
src/app/api/contact/route.ts/api/contact
src/app/api/health/route.ts/api/health
Important: A folder cannot have both a route.ts and a page.tsx. A route is either a page (renders HTML) or an API endpoint (returns data), not both.

Exporting HTTP Method Functions

Inside a route.ts file, you export named functions that correspond to HTTP methods. Next.js automatically routes requests to the correct function based on the method used:

// src/app/api/hello/route.ts
import { NextRequest, NextResponse } from 'next/server';

export async function GET(request: NextRequest) {
  return NextResponse.json({ message: 'Hello, World!' });
}

export async function POST(request: NextRequest) {
  const body = await request.json();
  return NextResponse.json({ received: body }, { status: 201 });
}

The supported HTTP method exports are:

Export HTTP Method Common Use
GETGETRead / list data
POSTPOSTCreate new data
PUTPUTUpdate existing data (full replace)
PATCHPATCHPartial update
DELETEDELETEDelete data
HEADHEADCheck if resource exists (no body)
OPTIONSOPTIONSCORS preflight

If a client sends a method you have not exported, Next.js automatically returns a 405 Method Not Allowed response.

Reading Request Data with NextRequest

The NextRequest object gives you access to everything about the incoming request. Let us look at the most common data you will need to read:

Query Parameters (Search Params)

// GET /api/blog?status=published&limit=10

export async function GET(request: NextRequest) {
  const { searchParams } = new URL(request.url);
  const status = searchParams.get('status');   // "published"
  const limit = searchParams.get('limit');     // "10" (always a string!)

  // Convert to number if needed
  const limitNum = limit ? parseInt(limit, 10) : 20;

  // Use the params in your query
  const posts = await getPostsByStatus(status, limitNum);

  return NextResponse.json(posts);
}

JSON Body (POST, PUT, PATCH)

// POST /api/blog with JSON body
export async function POST(request: NextRequest) {
  // Parse the JSON body
  const body = await request.json();

  // body is now a JavaScript object:
  // { title: "My Post", content: "Hello world", status: "draft" }

  const { title, content, status } = body;

  // Validate before using
  if (!title || !content) {
    return NextResponse.json(
      { error: 'Title and content are required' },
      { status: 400 }
    );
  }

  const newPost = await createPost({ title, content, status });

  return NextResponse.json(newPost, { status: 201 });
}

export async function GET(request: NextRequest) {

  const authHeader = request.headers.get('Authorization');

      { status: 401 }

}

export async function GET(request: NextRequest) {
  // Read a cookie
  const sessionCookie = request.cookies.get('session_token');

  if (!sessionCookie) {
    return NextResponse.json({ error: 'Not authenticated' }, { status: 401 });
  }

  const sessionValue = sessionCookie.value;

Building Responses with NextResponse

NextResponse provides methods for constructing HTTP responses:

JSON Responses

// Basic JSON response (status 200 by default)
return NextResponse.json({ message: 'Success' });

// JSON with specific status code
return NextResponse.json({ id: 1, title: 'New Post' }, { status: 201 });

// Error response
return NextResponse.json({ error: 'Not found' }, { status: 404 });

Custom Headers on Responses

return NextResponse.json(
  { data: results },
  {
    status: 200,
    headers: {
      'Cache-Control': 'public, max-age=60',
      'X-Total-Count': String(totalCount),
    },
  }
);

Dynamic Route Parameters in API Routes

Just like page routes, API routes can use dynamic segments. The parameter is accessed through the second argument of your handler function:

// src/app/api/blog/[id]/route.ts

import { NextRequest, NextResponse } from 'next/server';

export async function GET(
  request: NextRequest,
  { params }: { params: { id: string } }
) {
  const { id } = params;

  const post = await getPostById(id);

  if (!post) {
    return NextResponse.json(
      { error: `Post with ID ${id} not found` },
      { status: 404 }
    );
  }

  return NextResponse.json(post);
}

export async function PUT(
  request: NextRequest,
  { params }: { params: { id: string } }
) {
  const { id } = params;
  const body = await request.json();

  const updated = await updatePost(id, body);

  if (!updated) {
    return NextResponse.json({ error: 'Post not found' }, { status: 404 });
  }

  return NextResponse.json(updated);
}

export async function DELETE(
  request: NextRequest,
  { params }: { params: { id: string } }
) {
  const { id } = params;

  const deleted = await deletePost(id);

  if (!deleted) {
    return NextResponse.json({ error: 'Post not found' }, { status: 404 });
  }

  return NextResponse.json({ message: 'Post deleted' });
}

Building a Complete CRUD API

Let us build a full blog API with Create, Read, Update, and Delete operations. This is the pattern you will use over and over in production applications.

The Collection Route: /api/blog

// src/app/api/blog/route.ts
import { NextRequest, NextResponse } from 'next/server';
import { createClient } from '@supabase/supabase-js';

const supabase = createClient(
  process.env.NEXT_PUBLIC_SUPABASE_URL!,
  process.env.SUPABASE_SERVICE_ROLE_KEY!
);

/**
 * GET /api/blog
 * List blog posts with optional filtering
 *
 * Query params:
 *   ?status=published  - Filter by status
 *   ?limit=10          - Limit results
 *   ?admin=true        - Include drafts (admin only)
 */
export async function GET(request: NextRequest) {
  try {
    const { searchParams } = new URL(request.url);
    const status = searchParams.get('status');
    const limit = parseInt(searchParams.get('limit') || '20', 10);
    const isAdmin = searchParams.get('admin') === 'true';

    let query = supabase
      .from('blog_posts')
      .select('id, title, slug, excerpt, status, published_at, category')
      .order('published_at', { ascending: false })
      .limit(limit);

    // Public requests only see published posts
    if (!isAdmin) {
      query = query.eq('status', 'published');
    } else if (status) {
      query = query.eq('status', status);
    }

    const { data, error } = await query;

    if (error) {
      console.error('Database error:', error);
      return NextResponse.json(
        { error: 'Failed to fetch posts' },
        { status: 500 }
      );
    }

    return NextResponse.json(data);
  } catch (error) {
    console.error('Unexpected error:', error);
    return NextResponse.json(
      { error: 'Internal server error' },
      { status: 500 }
    );
  }
}

/**
 * POST /api/blog
 * Create a new blog post
 *
 * Body: { title, slug, content, excerpt, status, category }
 */
export async function POST(request: NextRequest) {
  try {
    const body = await request.json();

    // Validate required fields
    const { title, slug, content, excerpt, status, category } = body;

    if (!title || !slug || !content) {
      return NextResponse.json(
        { error: 'Title, slug, and content are required' },
        { status: 400 }
      );
    }

    // Check for duplicate slug
    const { data: existing } = await supabase
      .from('blog_posts')
      .select('id')
      .eq('slug', slug)
      .single();

    if (existing) {
      return NextResponse.json(
        { error: 'A post with this slug already exists' },
        { status: 409 }
      );
    }

    // Create the post
    const { data: newPost, error } = await supabase
      .from('blog_posts')
      .insert({
        title,
        slug,
        content,
        excerpt: excerpt || '',
        status: status || 'draft',
        category: category || 'General',
        published_at: status === 'published' ? new Date().toISOString() : null,
      })
      .select()
      .single();

    if (error) {
      console.error('Insert error:', error);
      return NextResponse.json(
        { error: 'Failed to create post' },
        { status: 500 }
      );
    }

    return NextResponse.json(newPost, { status: 201 });
  } catch (error) {
    console.error('Unexpected error:', error);
    return NextResponse.json(
      { error: 'Internal server error' },
      { status: 500 }
    );
  }
}

The Individual Route: /api/blog/[id]

// src/app/api/blog/[id]/route.ts
import { NextRequest, NextResponse } from 'next/server';
import { createClient } from '@supabase/supabase-js';

const supabase = createClient(
  process.env.NEXT_PUBLIC_SUPABASE_URL!,
  process.env.SUPABASE_SERVICE_ROLE_KEY!
);

/**
 * GET /api/blog/:id
 * Get a single blog post by ID or slug
 */
export async function GET(
  request: NextRequest,
  { params }: { params: { id: string } }
) {
  try {
    const { id } = params;

    // Support lookup by ID or slug
    const isUUID = /^[0-9a-f]{8}-/.test(id);
    const column = isUUID ? 'id' : 'slug';

    const { data: post, error } = await supabase
      .from('blog_posts')
      .select('*')
      .eq(column, id)
      .single();

    if (error || !post) {
      return NextResponse.json(
        { error: 'Post not found' },
        { status: 404 }
      );
    }

    return NextResponse.json(post);
  } catch (error) {
    console.error('Unexpected error:', error);
    return NextResponse.json(
      { error: 'Internal server error' },
      { status: 500 }
    );
  }
}

/**
 * PUT /api/blog/:id
 * Update a blog post
 */
export async function PUT(
  request: NextRequest,
  { params }: { params: { id: string } }
) {
  try {
    const { id } = params;
    const body = await request.json();

    // Only update the fields that were provided
    const updates: Record<string, unknown> = {};
    if (body.title !== undefined) updates.title = body.title;
    if (body.content !== undefined) updates.content = body.content;
    if (body.excerpt !== undefined) updates.excerpt = body.excerpt;
    if (body.status !== undefined) {
      updates.status = body.status;
      // Set published_at when publishing for the first time
      if (body.status === 'published') {
        updates.published_at = new Date().toISOString();
      }
    }
    if (body.category !== undefined) updates.category = body.category;

    updates.updated_at = new Date().toISOString();

    const { data: updated, error } = await supabase
      .from('blog_posts')
      .update(updates)
      .eq('id', id)
      .select()
      .single();

    if (error || !updated) {
      return NextResponse.json(
        { error: 'Post not found or update failed' },
        { status: 404 }
      );
    }

    return NextResponse.json(updated);
  } catch (error) {
    console.error('Unexpected error:', error);
    return NextResponse.json(
      { error: 'Internal server error' },
      { status: 500 }
    );
  }
}

/**
 * DELETE /api/blog/:id
 * Delete a blog post
 */
export async function DELETE(
  request: NextRequest,
  { params }: { params: { id: string } }
) {
  try {
    const { id } = params;

    const { error } = await supabase
      .from('blog_posts')
      .delete()
      .eq('id', id);

    if (error) {
      return NextResponse.json(
        { error: 'Failed to delete post' },
        { status: 500 }
      );
    }

    return NextResponse.json({ message: 'Post deleted successfully' });
  } catch (error) {
    console.error('Unexpected error:', error);
    return NextResponse.json(
      { error: 'Internal server error' },
      { status: 500 }
    );
  }
}

Error Handling Best Practices

Every API route should be wrapped in a try/catch block. This prevents your server from crashing and ensures the client always gets a meaningful error response.

export async function POST(request: NextRequest) {
  try {
    // 1. Parse and validate input
    let body;
    try {
      body = await request.json();
    } catch {
      return NextResponse.json(
        { error: 'Invalid JSON in request body' },
        { status: 400 }
      );
    }

    // 2. Validate required fields
    if (!body.email || !body.message) {
      return NextResponse.json(
        { error: 'Email and message are required', fields: ['email', 'message'] },
        { status: 400 }
      );
    }

    // 3. Perform the operation
    const result = await sendContactEmail(body);

    // 4. Return success
    return NextResponse.json(
      { message: 'Email sent successfully' },
      { status: 200 }
    );

  } catch (error) {
    // 5. Catch unexpected errors -- ALWAYS log server-side
    console.error('[API /api/contact] Unexpected error:', error);

    // NEVER expose internal error details to the client
    return NextResponse.json(
      { error: 'Internal server error' },
      { status: 500 }
    );
  }
}
Security Rule: Never include internal error messages, stack traces, or database error details in responses sent to the client. Log them server-side for debugging, but return a generic message to the user. Leaking error details can expose your database schema, file paths, or other sensitive information.

Organizing Routes by Feature

As your API grows, keep routes organized by feature area. Each feature gets its own folder under api/:

src/app/api/
├── auth/                     # Authentication
│   ├── login/route.ts        # POST /api/auth/login
│   ├── logout/route.ts       # POST /api/auth/logout
│   └── session/route.ts      # GET /api/auth/session
├── blog/                     # Blog system
│   ├── route.ts              # GET, POST /api/blog
│   ├── [id]/route.ts         # GET, PUT, DELETE /api/blog/:id
│   └── upload/route.ts       # POST /api/blog/upload
├── contact/                  # Contact form
│   └── route.ts              # POST /api/contact
├── gallery/                  # Gallery system
│   ├── route.ts              # GET, POST /api/gallery
│   ├── [id]/route.ts         # GET, PUT, DELETE /api/gallery/:id
│   └── upload/route.ts       # POST /api/gallery/upload
└── health/                   # Health check
    └── route.ts              # GET /api/health

This structure makes it easy to find, maintain, and reason about your API endpoints.

The Health Check Endpoint

Every production application should have a health check endpoint. This is a simple GET route that external monitoring services (like UptimeRobot) call regularly to verify your application is running:

// src/app/api/health/route.ts
import { NextResponse } from 'next/server';

export async function GET() {
  const startTime = Date.now();

  try {
    // Optionally check database connectivity
    // await supabase.from('health_check').select('count').single();

    return NextResponse.json({
      status: 'healthy',
      timestamp: new Date().toISOString(),
      responseTime: `${Date.now() - startTime}ms`,
      uptime: process.uptime(),
    });
  } catch (error) {
    return NextResponse.json(
      {
        status: 'unhealthy',
        timestamp: new Date().toISOString(),
        error: 'Service check failed',
      },
      { status: 503 }
    );
  }
}
CSK Connection CSK's health check endpoint at /api/health is monitored by UptimeRobot every 5 minutes. This keeps the Render free-tier service alive (preventing cold starts) and alerts the team immediately if the site goes down. The health check also verifies database connectivity with Supabase.

Key Takeaways

  • API route handlers live in route.ts files under src/app/api/ and follow the same file-based routing as pages.
  • Export named functions (GET, POST, PUT, DELETE) to handle different HTTP methods.
  • NextRequest gives you access to query params (searchParams), JSON body (request.json()), headers, and cookies.
  • NextResponse.json() sends JSON responses with customizable status codes and headers.
  • Dynamic route parameters like [id] work the same way as page routes and are accessed via the params argument.
  • Always wrap API handlers in try/catch. Return meaningful status codes (400, 401, 404, 500) and never expose internal error details.
  • Organize API routes by feature (api/blog/, api/gallery/, api/auth/) for maintainability.
  • Every production app needs a /api/health endpoint for monitoring.
