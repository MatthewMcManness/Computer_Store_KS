Executive Summary

This report analyzes options for integrating The Computer Store's Cytracom phone system directly with the computerstoreks.com website. Cytracom offers a comprehensive public API that enables custom integrations including click-to-call functionality, real-time call events, and call data insights.

API Available

Cytracom provides a fully-featured public API with call control, events, and insights endpoints.

No Native RepairShopr Integration

While Cytracom integrates with the Desktop app, there's no pre-built RepairShopr integration.

Custom Build Required

Website integration will require custom development using Cytracom's API.

Real-Time Possible

Server-Sent Events (SSE) enable real-time call status updates on the website.

🔌 Cytracom Public API Overview

The Cytracom Public API provides comprehensive access to voice services data and call control functionality. The API is organized into four main categories:

📊

Data Services

Account & Extension Information

Retrieve lists of extensions and PBX resources for your account. Essential for building user directories and managing phone system configuration.

GET https://api.cytracom.net/v1.0/data/extensions
  • ✓ List all extensions
  • ✓ Get PBX resources
  • ✓ Extension details & status
📞

Call Control Actions

Initiate & Manage Calls

Create, transfer, park, and unpark calls programmatically. This is the foundation for click-to-call functionality on your website.

POST https://api.cytracom.net/v1.0/action/chan/originate
  • ✓ Originate new calls
  • ✓ Blind transfer
  • ✓ Park & unpark calls
🔔

Events (SSE)

Real-Time Call Events

Subscribe to Server-Sent Events for real-time call lifecycle notifications. Monitor calls, queues, and monitored extensions.

GET https://api.cytracom.net/v1.0/events/sse/chan
  • ✓ Channel events (call lifecycle)
  • ✓ Queue events
  • ✓ Monitored extension events
📈

Insights

Call Detail Records

Access call detail records (CDR) for the previous 6 months. Useful for reporting, analytics, and displaying call history.

GET https://api.cytracom.net/v1.0/insights/cdr
  • ✓ Call detail records
  • ✓ 6-month history
  • ✓ Call metrics & statistics

🔑 Authentication

All API requests require a token created by an account admin. Navigate to Settings → Tokens in the Cytracom portal to generate a new API token. Treat this token like a password - never expose it in client-side code.

💻 Implementation Approaches

Approach A: Customer Callback Widget

Add a "Request Callback" button to the website that allows visitors to enter their phone number and receive a call from your team.

// API Route: /api/callback/request
export async function POST(request: Request) {
  const { customerPhone, customerName, page } = await request.json()

  // 1. Check RepairShopr for existing customer
  const customer = await searchRepairShoprCustomer(customerPhone)

  // 2. Initiate call via Cytracom API
  const response = await fetch('https://api.cytracom.net/v1.0/action/chan/originate', {
    method: 'POST',
    headers: {
      'Authorization': `Bearer ${CYTRACOM_API_TOKEN}`,
      'Content-Type': 'application/json'
    },
    body: JSON.stringify({
      extension: 'main',  // Your main line
      destination: customerPhone,
      callerId: customerName || 'Website Callback'
    })
  })

  // 3. Log the callback request
  if (customer) {
    await addRepairShoprNote(customer.id, `Callback requested from ${page}`)
  }

  return Response.json({ success: true })
}

Approach B: Employee Click-to-Call

Add click-to-call buttons throughout the admin portal for employees to call customers directly from ticket pages.

// Component: CallCustomerButton.tsx
export function CallCustomerButton({ phone, customerId }: Props) {
  const [calling, setCalling] = useState(false)

  const initiateCall = async () => {
    setCalling(true)

    // Call API to initiate through Cytracom
    const response = await fetch('/api/cytracom/call', {
      method: 'POST',
      body: JSON.stringify({
        destination: phone,
        customerId: customerId
      })
    })

    if (response.ok) {
      // Call initiated - your phone will ring first
      toast.success('Call initiated - answer your phone!')
    }
    setCalling(false)
  }

  return (
    <button onClick={initiateCall} disabled={calling}>
      {calling ? 'Calling...' : '📞 Call Customer'}
    </button>
  )
}

Approach C: Real-Time Call Events

Subscribe to Cytracom's Server-Sent Events to show live call status in the admin portal.

// Server: Subscribe to Cytracom SSE events
const eventSource = new EventSource(
  'https://api.cytracom.net/v1.0/events/sse/chan',
  { headers: { 'Authorization': `Bearer ${token}` } }
)

eventSource.onmessage = async (event) => {
  const callEvent = JSON.parse(event.data)

  switch (callEvent.type) {
    case 'CALL_INCOMING':
      // Look up customer in RepairShopr
      const customer = await lookupCustomer(callEvent.callerNumber)
      // Push notification to admin dashboard
      broadcastToAdmins({ type: 'incoming_call', customer, callEvent })
      break

    case 'CALL_ANSWERED':
      updateCallStatus(callEvent.callId, 'active')
      break

    case 'CALL_ENDED':
      // Log call to RepairShopr ticket
      await logCallToTicket(callEvent)
      break
  }
}

📵 Missed Calls & Voicemail Handling

Handling missed calls and voicemails is critical for a repair shop where customers often call about urgent issues. Here's how to integrate these into your website and admin portal.

📧 Cytracom Voicemail Features

Cytracom includes built-in voicemail-to-email with transcription. Voicemails can be sent to multiple email addresses with audio attachments and text transcriptions. This is your primary data source for voicemail integration.

Integration Strategies

📧

Strategy 1: Email-Based Integration

Parse voicemail emails automatically
Medium Complexity

Configure Cytracom to send voicemail notifications to a dedicated inbox. Use an email parsing service or custom IMAP listener to automatically process incoming voicemails.

  • ✓ Works with existing Cytracom voicemail settings
  • ✓ Captures transcription text automatically
  • ✓ Can attach audio file to ticket
  • ✓ Look up customer by caller ID in RepairShopr
  • ✓ Auto-create ticket or alert for follow-up

Workflow

Voicemail → Email → Parse → Customer Lookup → Create Ticket/Alert → Display in Admin Dashboard

⚡

Strategy 2: SSE Events + Email Combo

Real-time missed call detection
High Complexity

Use the Events API (SSE) to detect unanswered calls in real-time. When a call goes to voicemail, trigger an immediate alert. Then enrich with transcription when the email arrives.

  • ✓ Instant notification when call missed
  • ✓ Real-time missed call counter in dashboard
  • ✓ Customer lookup happens immediately
  • ⚠ Transcription arrives later via email
  • ⚠ Requires correlating SSE events with emails
📊

Strategy 3: Dashboard Widget

Missed calls queue display
Low Complexity

Create a "Missed Calls" widget in the admin dashboard that displays voicemails needing follow-up. Employees can mark items as "called back" when resolved.

  • ✓ Simple queue-based workflow
  • ✓ Shows caller, time, transcription
  • ✓ One-click to call back
  • ✓ Mark as resolved/create ticket
  • ✓ Integrates with existing admin portal

Implementation: Email-Based Voicemail Processing

// API Route: /api/voicemail/webhook (for email service like SendGrid Inbound Parse)
export async function POST(request: Request) {
  const formData = await request.formData()

  // Parse voicemail email from Cytracom
  const from = formData.get('from') // Cytracom notification address
  const subject = formData.get('subject') // Contains caller number
  const body = formData.get('text') // Contains transcription
  const attachments = formData.getAll('attachments') // Audio file

  // Extract caller phone number from subject/body
  const callerPhone = extractPhoneNumber(subject, body)

  // Extract transcription text
  const transcription = extractTranscription(body)

  // Look up customer in RepairShopr
  const customer = await searchRepairShoprByPhone(callerPhone)

  // Create missed call record in database
  const missedCall = await db.missedCalls.create({
    callerPhone,
    transcription,
    customerId: customer?.id,
    customerName: customer?.name || 'Unknown Caller',
    receivedAt: new Date(),
    status: 'pending', // pending, called_back, ticket_created
    audioUrl: attachments[0] ? await uploadAudio(attachments[0]) : null
  })

  // Optional: Auto-create ticket for known customers
  if (customer && AUTO_CREATE_TICKETS) {
    await createRepairShoprTicket({
      customerId: customer.id,
      subject: `Voicemail from ${customer.name}`,
      description: `Transcription: ${transcription}\n\nPlease call back.`,
      status: 'New'
    })
  }

  // Broadcast to admin dashboard (WebSocket/SSE)
  broadcastToAdmins({ type: 'new_voicemail', missedCall })

  return Response.json({ success: true })
}

Admin Dashboard Widget

// Component: MissedCallsWidget.tsx
export function MissedCallsWidget() {
  const { data: missedCalls } = useSWR('/api/voicemail/pending', fetcher, {
    refreshInterval: 30000 // Refresh every 30 seconds
  })

  const handleCallBack = async (call: MissedCall) => {
    // Initiate call via Cytracom API
    await fetch('/api/cytracom/call', {
      method: 'POST',
      body: JSON.stringify({ destination: call.callerPhone })
    })
    // Mark as called back
    await fetch(`/api/voicemail/${call.id}/status`, {
      method: 'PATCH',
      body: JSON.stringify({ status: 'called_back' })
    })
  }

  return (
    <div className="missed-calls-widget">
      <h3>📵 Missed Calls ({missedCalls?.length || 0})</h3>
      {missedCalls?.map(call => (
        <div key={call.id} className="missed-call-item">
          <div className="caller-info">
            <strong>{call.customerName}</strong>
            <span>{call.callerPhone}</span>
            <time>{formatTime(call.receivedAt)}</time>
          </div>
          <p className="transcription">{call.transcription}</p>
          <div className="actions">
            <button onClick={() => handleCallBack(call)}>📞 Call Back</button>
            <button onClick={() => createTicket(call)}>🎫 Create Ticket</button>
          </div>
        </div>
      ))}
    </div>
  )
}

⚙️ Required Cytracom Settings

Configure these settings in the Cytracom portal at secure.cytracom.net:

Setting Location Recommended Value
Enable Email Notification PBX → Voicemail → Configure Mailbox ✓ Enabled
Voicemail Transcription PBX → Voicemail → Configure Mailbox ✓ Enabled (if on C2 plan or higher)
Email Addresses PBX → Voicemail → Configure Mailbox Add dedicated parsing address (e.g., voicemail-parse@yourdomain.com)

Database Schema

-- Supabase table for missed calls/voicemails
CREATE TABLE missed_calls (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  caller_phone VARCHAR(20) NOT NULL,
  customer_id VARCHAR(50), -- RepairShopr customer ID
  customer_name VARCHAR(255),
  transcription TEXT,
  audio_url TEXT,
  received_at TIMESTAMPTZ DEFAULT NOW(),
  status VARCHAR(20) DEFAULT 'pending', -- pending, called_back, ticket_created, dismissed
  called_back_at TIMESTAMPTZ,
  called_back_by VARCHAR(100),
  ticket_id VARCHAR(50), -- RepairShopr ticket ID if created
  notes TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- Index for quick pending lookups
CREATE INDEX idx_missed_calls_status ON missed_calls(status) WHERE status = 'pending';
CREATE INDEX idx_missed_calls_customer ON missed_calls(customer_id);

-- Enable RLS
ALTER TABLE missed_calls ENABLE ROW LEVEL SECURITY;

API Rate Limits & Considerations

📊 Rate Limits

The number of API requests is limited within a 5-minute timeframe. For high-volume implementations, cache data locally and batch requests where possible. SSE connections don't count against rate limits once established.
