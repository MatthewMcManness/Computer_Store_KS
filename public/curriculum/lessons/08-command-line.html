The Command Line

Your keyboard is mightier than your mouse — learn to navigate, create, and control your computer through text commands.

What You Will Learn

  • How to open the terminal on Mac, Windows, and Linux

Why Developers Use Terminals Instead of GUIs

If you have only ever used a computer by clicking icons and dragging files, the idea of typing commands into a blank screen can feel intimidating. But there is a reason that every professional developer—from junior engineers at startups to senior architects at the largest tech companies—spends most of their day inside a terminal window. The command line is not a relic of the past; it is the single most powerful tool in a developer's toolkit.

The first reason is speed. Think about renaming 200 files in a folder. With a graphical file manager, you would need to right-click each file, choose "Rename," type the new name, and press Enter—200 times. With a single command-line instruction, you can rename all 200 files in under a second. Tasks that take minutes or hours with a mouse take seconds with a keyboard.

The second reason is precision and repeatability. A command is text. Text can be copied, shared, documented, and replayed exactly. If you set up a server by clicking through menus, and then need to set up a second identical server, you have to remember every click. If you set it up with commands, you can simply run those same commands again. This is why deployment systems, CI/CD pipelines, and automation scripts all run through the command line.

The third reason is access to tools that have no graphical equivalent. Git, npm, Docker, database migrations, server management—all of these are primarily or exclusively command-line tools. Many developer tools never get a graphical interface because the command line is already the most efficient way to use them.

Analogy: Think of the command line like learning to touch-type versus hunt-and-peck. At first, touch-typing feels slower and harder. But once you build the muscle memory, you become dramatically faster than someone who has to look at the keyboard. The command line is the same: an investment that pays off enormously.
CSK Connection At Computer Store KS, every part of the development workflow happens in the terminal. Running the development server (npm run dev), building for production (npm run build), committing code with Git, deploying to Render—none of these have graphical equivalents. The terminal is not optional; it is the workspace.

Terminal vs. Shell vs. Console

Before we start typing commands, let us clarify three terms that people often use interchangeably but which actually mean different things. Understanding the distinction will help you troubleshoot problems and follow instructions accurately.

The Terminal (Terminal Emulator)

A terminal is the window application that displays text and accepts your keyboard input. It is the visual interface—the program you open on your screen. Examples include Terminal.app on Mac, Windows Terminal on Windows, and GNOME Terminal or Konsole on Linux. The terminal itself does not understand commands. It is just the screen and keyboard handler. Think of it as the TV set—it displays the picture, but it does not create the content.

The Shell

The shell is the program that actually interprets and executes your commands. When you type ls and press Enter, the shell is the software that reads that text, understands it means "list files," executes the operation, and sends the result back to the terminal for display. The shell is the brain; the terminal is the face.

Common shells include:

The Console

The console is a more general term that historically referred to the physical hardware (keyboard and monitor) connected directly to a machine. Today, people often use "console" loosely to mean the same thing as "terminal." In web development, you will also hear "browser console," which is the developer tools panel in Chrome or Firefox. Context usually makes the meaning clear.

Analogy: Imagine a restaurant. The terminal is the dining room where you sit. The shell is the waiter who takes your order, relays it to the kitchen, and brings back your food. The console is the old term for the whole building. When someone says "open your terminal," they mean sit down in the dining room. When they say "the shell does not recognize that command," they mean the waiter does not understand your order.

Opening the Terminal

The first step is simply getting the terminal open. Here is how to do it on each major operating system.

macOS

Press Cmd + Space to open Spotlight Search, type Terminal, and press Enter. Alternatively, go to Applications > Utilities > Terminal. Mac uses the zsh shell by default. Everything we cover in this lesson works the same in zsh and bash.

Windows

The recommended approach is to use Windows Terminal with Git Bash or WSL (Windows Subsystem for Linux). WSL gives you a real Linux environment inside Windows, which means all the commands in this lesson work identically. To install WSL, open PowerShell as Administrator and run:

wsl --install

After restarting, you will have access to a full Ubuntu terminal. If you prefer something lighter, installing Git for Windows includes Git Bash, which provides bash-compatible commands on Windows.

Linux

Most Linux distributions have a terminal application pre-installed. Look for "Terminal" in your application menu, or press Ctrl + Alt + T on Ubuntu and most Debian-based systems. Linux uses bash by default on most distributions.

Important for Windows Users The commands in this lesson (and throughout the curriculum) use Unix-style syntax that works on Mac, Linux, and WSL/Git Bash. If you are using plain PowerShell or cmd.exe, many commands will be different. We strongly recommend using WSL or Git Bash so you can follow along exactly.

Navigation: Where Am I? What Is Here? How Do I Move?

Once you have a terminal open, you are "standing" inside a directory (folder) on your computer. Every command you run happens relative to wherever you are standing. The three most fundamental questions you will ask are: Where am I? What is in this directory? How do I go somewhere else?

pwd — Print Working Directory

The pwd command answers "Where am I?" It prints the full path of the directory you are currently in.

$ pwd
/home/matthew

This output tells you that you are in the matthew folder, which is inside the home folder, which is at the root of the file system. On Mac, home directories look like /Users/yourname. On Linux, they look like /home/yourname. The / at the very beginning represents the root of the entire file system—the top of the directory tree.

ls — List Directory Contents

The ls command answers "What is here?" By itself, it shows the names of files and folders in your current directory.

$ ls
Desktop  Documents  Downloads  Music  Pictures  Projects

But ls becomes much more useful with flags (options that modify a command's behavior). Flags start with a hyphen.

# Show files in a long list format with details
$ ls -l
total 24
drwxr-xr-x  2 matthew matthew 4096 Jan 15 09:00 Desktop
drwxr-xr-x  5 matthew matthew 4096 Jan 20 14:30 Documents
drwxr-xr-x  3 matthew matthew 4096 Feb 01 10:00 Downloads

# Show ALL files including hidden ones (files starting with .)
$ ls -a
.  ..  .bashrc  .config  Desktop  Documents  Downloads

# Combine flags: long format + all files
$ ls -la
total 40
drwxr-xr-x 10 matthew matthew 4096 Feb 05 08:00 .
drwxr-xr-x  3 root    root    4096 Jan  1 00:00 ..
-rw-r--r--  1 matthew matthew  220 Jan  1 00:00 .bashrc
drwx------  5 matthew matthew 4096 Jan 10 12:00 .config
drwxr-xr-x  2 matthew matthew 4096 Jan 15 09:00 Desktop
drwxr-xr-x  5 matthew matthew 4096 Jan 20 14:30 Documents

The -la combination is one of the most commonly used commands in day-to-day development. The long format shows you file permissions, the owner, the file size, the last modification date, and the file name. The -a flag reveals hidden files, which are files whose names begin with a dot. Configuration files like .bashrc, .gitignore, and .env are hidden by convention so they do not clutter your view during normal browsing.

cd — Change Directory

The cd command answers "How do I move?" You follow it with the path to where you want to go.

# Move into the Documents folder
$ cd Documents

# Verify where you are now
$ pwd
/home/matthew/Documents

There are two types of paths:

Absolute paths start from the root (/) and specify the complete location. They work no matter where you currently are:

$ cd /home/matthew/Projects/my-website

Relative paths start from your current location. If you are in /home/matthew and want to go to /home/matthew/Projects, you just type:

$ cd Projects

There are several special path shortcuts you should memorize:

ShortcutMeaningExample
.Current directoryls . lists current folder
..Parent directory (one level up)cd .. goes up one level
~Home directorycd ~ goes home from anywhere
-Previous directorycd - goes back to where you were
 
# Go up one directory
$ cd ..

# Go up two directories
$ cd ../..

# Go home from anywhere
$ cd ~

# Go to a sibling directory (up one, then into another)
$ cd ../Downloads
Analogy: Think of your file system like a building. pwd tells you which room you are in. ls shows you everything in the room. cd lets you walk to another room. .. takes you to the hallway (parent directory), and ~ teleports you back to the lobby (home directory).

File and Folder Operations

Now that you can navigate, let us learn to create, copy, move, and delete files and folders. These are the operations you will perform hundreds of times as a developer.

mkdir — Make Directory

Creates a new folder. The name you provide becomes the folder name.

# Create a single folder
$ mkdir my-project

# Create nested folders (the -p flag creates parent directories as needed)
$ mkdir -p my-project/src/components

Without the -p flag, mkdir my-project/src/components would fail if my-project and src did not already exist. The -p flag tells mkdir to create the entire path, making any missing parent directories along the way. You will use mkdir -p frequently when setting up project structures.

touch — Create Empty Files

Creates a new empty file, or updates the modification timestamp of an existing file.

# Create a single file
$ touch index.html

# Create multiple files at once
$ touch style.css script.js README.md

Despite its name, touch does not write any content to the file. It simply creates a blank file if one does not exist. Developers use it to quickly scaffold out file structures before writing code.

cp — Copy

Copies files or directories from one location to another.

# Copy a file
$ cp index.html index-backup.html

# Copy a file into a different directory
$ cp index.html backups/

# Copy an entire directory (requires the -r flag for "recursive")
$ cp -r my-project my-project-backup

The -r (recursive) flag is required when copying directories because a directory can contain other directories. Without -r, cp refuses to copy a folder.

mv — Move (and Rename)

Moves a file or directory to a new location. It also serves as the rename command, because renaming is just "moving" a file to the same directory with a different name.

# Rename a file
$ mv old-name.html new-name.html

# Move a file into a directory
$ mv style.css src/

# Move and rename at the same time
$ mv draft.md documents/final.md

rm — Remove (Delete)

Deletes files and directories. This is the most dangerous command on this list because the command line has no recycle bin. When you rm a file, it is gone forever. There is no undo.

# Delete a single file
$ rm old-file.txt

# Delete a directory and everything inside it
$ rm -r old-folder/

# Delete without asking for confirmation
$ rm -rf build/
Why rm -rf Is Dangerous The -r flag means "recursive" (delete everything inside the folder too). The -f flag means "force" (do not ask for confirmation, and do not complain if files do not exist). Together, rm -rf will silently and instantly delete everything you point it at. A typo like rm -rf / (with a space before the slash) would attempt to delete your entire file system. Always double-check the path before pressing Enter. Always use ls first to confirm you are targeting the right files.

Reading Files

You will often need to quickly check the contents of a file without opening it in a full text editor. The command line provides several tools for this, each suited to different situations.

cat — Concatenate and Print

Prints the entire contents of a file to your terminal. Best for short files.

$ cat package.json
{
  "name": "my-project",
  "version": "1.0.0",
  "scripts": {
    "dev": "next dev",
    "build": "next build"
  }
}

For long files, cat will flood your screen with text, which is why we have other tools.

head and tail

head shows the first few lines of a file. tail shows the last few lines. Both default to 10 lines but accept a -n flag to customize.

# First 5 lines of a file
$ head -n 5 README.md

# Last 20 lines of a log file
$ tail -n 20 server.log

# Watch a log file in real-time (tail -f "follows" new additions)
$ tail -f server.log

The tail -f command is extremely useful during development. It keeps the terminal open and shows new lines as they are written to the file, which is perfect for watching server logs or build output in real-time.

less — Paged Viewing

less opens a file in an interactive viewer. You can scroll up and down with the arrow keys, search with /, and quit with q. It is the best tool for reading long files in the terminal.

$ less very-long-file.txt

Inside less: press Space to go forward a page, b to go back a page, /search-term to search, and q to quit.

Searching with grep

grep searches for text patterns inside files. It is one of the most powerful and frequently used command-line tools. The name stands for "Global Regular Expression Print," but you do not need to know regular expressions to use it effectively.

# Find all lines containing "error" in a log file
$ grep "error" server.log

# Search case-insensitively (-i)
$ grep -i "error" server.log

# Search recursively through all files in a directory (-r)
$ grep -r "TODO" src/

# Show line numbers (-n)
$ grep -rn "console.log" src/

# Show only file names that contain the match (-l)
$ grep -rl "import React" src/

The -rn combination (recursive + line numbers) is especially useful during development. If you need to find every file where a certain function is called, or every place where a particular string appears, grep -rn will give you the answer in seconds.

CSK Connection When debugging the CSK codebase, you might use grep -rn "RESEND_API_KEY" src/ to find every file that references the email API key, or grep -rn "supabase" src/lib/ to find all database client usage. This is often faster than using your editor's search feature, especially across large projects.

Environment Variables

An environment variable is a named value that lives in your shell session and can be read by any program you run. They are used to configure programs without hardcoding values into source code. For example, instead of putting a database password directly in your code (which would be visible to anyone who reads the code), you store it in an environment variable and your code reads it from there.

Viewing Environment Variables

# Print a specific environment variable
$ echo $HOME
/home/matthew

# Print the PATH variable
$ echo $PATH
/usr/local/bin:/usr/bin:/bin:/home/matthew/.nvm/versions/node/v22.16.0/bin

# Print all environment variables
$ env

The $PATH Variable

$PATH is the most important environment variable on your system. When you type a command like node or git, your shell does not magically know where those programs are installed. Instead, it looks through the directories listed in $PATH, in order, until it finds a program with that name. The directories are separated by colons.

If you install a new tool and the terminal says "command not found," it almost always means the tool's directory is not in your $PATH.

Setting Environment Variables

# Set a variable for the current session
$ export MY_API_KEY="abc123"

# Verify it was set
$ echo $MY_API_KEY
abc123

# Use it in a command
$ node -e "console.log(process.env.MY_API_KEY)"
abc123

Variables set with export last only for the current terminal session. When you close the terminal, they disappear. To make variables permanent, you add them to your shell's configuration file (~/.bashrc for bash, ~/.zshrc for zsh). In web development, we use .env files to manage project-specific variables, which you will learn about in later lessons.

Never put secrets in your code Database passwords, API keys, and other secrets should always be stored in environment variables or .env files that are excluded from version control. If you commit a secret to Git, it becomes part of the permanent history and is very difficult to fully remove.

Running Programs and Scripts

Every command you type in the terminal is actually running a program. When you type ls, the shell finds and executes the ls program. You can run any installed program the same way:

# Run Node.js
$ node

# Run a specific JavaScript file
$ node server.js

# Run a Python script
$ python3 app.py

# Run an npm script defined in package.json
$ npm run dev

# Run a script file directly (must have execute permission)
$ ./my-script.sh

For script files, you may need to grant execute permission first using chmod:

$ chmod +x my-script.sh
$ ./my-script.sh

Piping and Redirection

One of the most powerful features of the command line is the ability to connect commands together. Each command can receive input, process it, and produce output. Piping takes the output of one command and feeds it as input to another. Redirection sends output to a file instead of the screen.

Piping with |

The pipe character (|) connects commands in a chain. The output of the command on the left becomes the input of the command on the right.

# List files and search for .js files
$ ls -la | grep ".js"

# Count how many JavaScript files are in the src directory
$ find src/ -name "*.js" | wc -l

# Show the 10 largest files in a directory
$ ls -lS | head -n 10

# Search for "error" in logs and show only unique lines
$ grep "error" server.log | sort | uniq

You can chain as many pipes as you want. Each pipe is like handing the result to the next worker in an assembly line.

Redirection with > and >>

The > operator sends a command's output to a file instead of the screen. If the file already exists, it is overwritten completely.

# Save the list of files to a text file
$ ls -la > file-list.txt

# Save grep results to a file
$ grep -rn "TODO" src/ > todos.txt

The >> operator appends to the end of a file instead of overwriting it.

# Add a line to a log file
$ echo "Build completed at $(date)" >> build-log.txt

# Append search results to an existing file
$ grep "WARNING" server.log >> warnings.txt
Be careful with > A single > will erase the entire contents of the target file and replace it with the new output. If you meant to append, use >>. This is a common mistake that can cause data loss.

Tab Completion and Command History

Two features will make you dramatically faster on the command line: tab completion and command history.

Tab Completion

Press the Tab key while typing a file name, directory name, or command, and the shell will attempt to complete it for you. If there is only one possible match, it fills in the rest. If there are multiple matches, pressing Tab twice shows you all the options.

# Type "cd Doc" then press Tab
$ cd Doc[TAB]
$ cd Documents/    # Auto-completed!

# Type "ls pack" then press Tab
$ ls pack[TAB]
$ ls package.json  # Auto-completed!

Tab completion prevents typos and saves an enormous amount of typing. Get in the habit of pressing Tab after every few characters.

Command History

The shell remembers every command you have typed. You can recall previous commands in several ways:

  • Up Arrow: Cycle through previous commands, most recent first
  • Down Arrow: Cycle forward through history
  • history: Print your entire command history
  • Ctrl + R: Reverse search through history. Start typing and it finds matching commands
  • !!: Re-run the last command (useful with sudo !! to re-run with admin privileges)
# Search history for a previous command
$ history | grep "npm"
  145  npm install
  167  npm run dev
  201  npm run build

# Re-run command number 167
$ !167

Ctrl + R is especially powerful. Press Ctrl + R, then start typing any part of a previous command. The shell will search backward through your history and show the most recent match. Press Ctrl + R again to go further back. Press Enter to execute the found command, or Escape to cancel.

Exercises

  1. Navigation drill: Open your terminal, use pwd to see where you are, then cd to your home directory, to the root (/), to /tmp, and back home. At each location, run pwd and ls -la.
  2. Build a project: Without looking at the practice session above, create a new folder called my-first-project with the following structure: a src/ folder containing index.html, style.css, and app.js; a public/ folder containing an images/ subfolder; and a README.md in the root.
  3. File content: Use echo and redirection (> and >>) to write three lines into a file called notes.txt. Then use cat to verify the content, head -n 1 to show just the first line, and tail -n 1 to show just the last line.
  4. Search practice: In the project you created, add the text "TODO: fix this later" to one of the files using echo ... >> filename. Then use grep -rn "TODO" . to find it.
  5. Piping chain: Use ls -la piped to grep to find only directories (hint: directory lines start with d). Then use history | grep "cd" | tail -n 5 to see your last 5 cd commands.
  6. Cleanup: Create a folder called temp-test with three files inside it. Copy it to temp-backup. Rename temp-test to temp-original. Delete temp-backup. Verify each step with ls.
  7. Environment variables: Set an environment variable called MY_NAME to your name using export. Then run echo "Hello, $MY_NAME" to see it in action. Finally, run echo $PATH and count how many directories are listed (hint: pipe to tr ':' '\n' | wc -l).

Key Takeaways

  • The terminal is faster, more precise, and more powerful than graphical file managers for development tasks.
  • The terminal is the window; the shell (bash, zsh) is the program that interprets your commands.
  • pwd, ls -la, and cd are the three commands you will use most often for navigation.
  • mkdir -p creates nested directories in one command; touch creates empty files.
  • rm is permanent—there is no recycle bin on the command line. Always double-check before deleting.
  • grep -rn is your best friend for searching across an entire codebase.
  • Environment variables store configuration outside your code; $PATH tells the shell where to find programs.
  • Piping (|) chains commands together; redirection (>, >>) sends output to files.
  • Tab completion and Ctrl+R history search will double your speed at the command line.
