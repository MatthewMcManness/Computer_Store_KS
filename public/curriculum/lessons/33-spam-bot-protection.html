Spam & Bot Protection

Layered defenses that stop automated attacks without annoying real users

What You Will Learn

  • Why bots attack web forms and the types of attacks to defend against
  • The layered defense strategy: multiple barriers instead of one
  • Honeypot fields: invisible inputs that trap bots
  • Timing analysis: detecting submissions that are too fast to be human
  • Interaction tracking: monitoring mouse/keyboard events to verify human behavior
  • Cloudflare Turnstile: invisible CAPTCHA with server-side verification
  • Browser fingerprinting with FingerprintJS for identifying repeat offenders
  • Disposable email detection: blocking throwaway email domains
  • Combining all defenses into a scoring system

Why Bots Attack Forms

Every public-facing form on your website is a target for automated bots. Understanding why they attack helps you design effective defenses.

Common Bot Objectives

  • Spam: Flooding your contact form with advertisements, phishing links, or SEO spam. The goal is to waste your time or trick you into visiting malicious sites.
  • Credential stuffing: Using stolen email/password combinations from data breaches to try logging into your site. Bots try millions of combinations automatically.
  • Account creation: Creating fake accounts to abuse your service (e.g., free trials, promotions, or to impersonate real people).
  • Scraping: Extracting data from your site by automating form submissions that reveal information.
  • DDoS: Overwhelming your server with requests so legitimate users cannot access it.
Analogy: Imagine your contact form is like a physical mailbox at a business. Most mail is from real customers, but some is junk. You could make everyone solve a puzzle before dropping in their letter (like a CAPTCHA), but that annoys real customers. Instead, you use multiple subtle indicators: Is the letter from a real address? Was it dropped off during business hours? Does it have normal handwriting or does it look mass-produced? Each indicator adds confidence.

The Layered Defense Strategy

No single technique is perfect. Honeypots catch simple bots but miss sophisticated ones. CAPTCHAs block bots but frustrate humans. The solution is layered defense -- multiple independent barriers, each catching different types of bots.

We use a scoring system where each defense layer contributes points to a spam score. If the total score exceeds a threshold, the submission is blocked:

LAYERED DEFENSE SCORING SYSTEM Layer Max Points ---------------------------------------- Honeypot fields 50 points Timing analysis 20 points Content analysis 35 points Spam pattern detection 30 points Request fingerprinting 15 points Disposable email detection 25 points Interaction tracking 20 points Browser fingerprinting 10 points Turnstile CAPTCHA 30 points Gibberish detection 30 points Name validation 25 points ---------------------------------------- Score 0-49: ALLOW (legitimate) Score 50-79: LOG (suspicious but allowed) Score 80-119: BLOCK (likely spam) Score 120+: SILENT SUCCESS (definite spam)

The "silent success" action is clever: instead of showing an error (which tells the bot to try different content), we pretend the submission succeeded. The bot thinks it worked and moves on, but we quietly discard the submission.

Honeypot Fields

A honeypot is an invisible form field that real users never see or fill in, but bots -- which read the HTML and fill every field -- will complete. If the honeypot field has a value, the submission is from a bot.

How It Works

  1. Add hidden input fields to your form with tempting names like website, url, or phone2.
  2. Hide them with CSS so human users never see them.
  3. On the server, check if any honeypot field has a value.
  4. If a honeypot field is filled in, add a large penalty to the spam score.

Client-Side Implementation

// In your form component
function ContactForm() {
  return (
    <form onSubmit={handleSubmit}>
      {/* Real fields that users see */}
      <input type="text" name="name" placeholder="Your Name" />
      <input type="email" name="email" placeholder="Your Email" />
      <textarea name="message" placeholder="Your Message" />

      {/* Honeypot fields -- hidden from humans, visible to bots */}
      <div style={{ position: 'absolute', left: '-9999px', opacity: 0 }}>
        <input
          type="text"
          name="_hp_email2"
          tabIndex={-1}
          autoComplete="off"
          aria-hidden="true"
        />
        <input
          type="text"
          name="_hp_phone_confirm"
          tabIndex={-1}
          autoComplete="off"
          aria-hidden="true"
        />
        <input
          type="text"
          name="_hp_url"
          tabIndex={-1}
          autoComplete="off"
          aria-hidden="true"
        />
      </div>

      <button type="submit">Send Message</button>
    </form>
  );
}

Key details for effective honeypots:

  • Use position: absolute; left: -9999px instead of display: none -- some bots skip fields with display: none.
  • Set tabIndex={-1} so keyboard users do not accidentally tab into the field.
  • Use aria-hidden="true" so screen readers skip the field.
  • Name the fields something a bot would want to fill: url, website, phone2, email2.
  • Set autoComplete="off" to prevent browsers from auto-filling the honeypot.

Server-Side Check

function checkHoneypots(fields: Record<string, string | undefined>): number {
  const honeypotFields = [
    'website', 'url', 'homepage',
    '_hp_email2', '_hp_phone_confirm', '_hp_url',
  ];

  for (const field of honeypotFields) {
    if (fields[field] && fields[field].trim().length > 0) {
      return 50;  // Instant high spam score
    }
  }

  return 0;  // All honeypots empty (good)
}

Timing Analysis

Humans take time to read a page, think about their message, and type it out. A typical contact form submission takes at least 10-30 seconds. Bots, on the other hand, can fill and submit a form in milliseconds.

Implementation

// Client: Record when the page loaded
const pageLoadTime = Date.now();  // e.g., 1706000000000

// Client: Include it when submitting the form
const formData = {
  name: 'Jane',
  email: 'jane@example.com',
  message: 'I need my laptop repaired...',
  pageLoadTime: pageLoadTime,        // When the page loaded
  submitTime: Date.now(),             // When they clicked submit
};

// Server: Validate the timing
function validateTiming(pageLoadTime: number, submitTime: number): number {
  const MIN_TIME_MS = 3000;  // 3 seconds minimum
  const timeDiff = submitTime - pageLoadTime;

  if (timeDiff < 0) {
    return 20;  // Time travel? Definitely a bot.
  }

  if (timeDiff < MIN_TIME_MS) {
    // Submitted too fast -- scale the penalty
    const ratio = timeDiff / MIN_TIME_MS;
    return Math.round(20 * (1 - ratio));
    // 0ms = 20 points, 1500ms = 10 points, 3000ms = 0 points
  }

  return 0;  // Took a normal amount of time
}
Why 3 seconds? This threshold catches automated bots while allowing fast-typing humans. Even the fastest human needs a moment to read the form, move their cursor, type, and click submit. However, do not set this too high (like 30 seconds) because some users might have autocomplete fill the form quickly.
CSK Connection CSK's useBotProtection hook records the page load time using a React ref (useRef(Date.now())) and includes it with every form submission. The server-side validateTiming() function in spam-detection.ts checks that at least 3 seconds elapsed, adding up to 20 spam points for submissions that are too fast.

Interaction Tracking

Humans interact with web pages in characteristic ways: they move their mouse, scroll, click on fields, and type with variable speeds. Bots typically skip all of this -- they just inject values directly into form fields via JavaScript.

What to Track

  • Mouse movements: Did the mouse move at all? How many distinct movements?
  • Keyboard events: Were there keypress events? How many?
  • Click events: Did the user click on form fields before typing?
  • Scroll events: Did the user scroll the page?
  • Focus events: Did form fields receive focus (user clicked or tabbed into them)?

Scoring Interactions

// hooks/useInteractionTracking.ts
'use client';
import { useEffect, useRef, useCallback } from 'react';

export function useInteractionTracking() {
  const interactions = useRef({
    mouseMovements: 0,
    keyPresses: 0,
    clicks: 0,
    scrolls: 0,
    focusEvents: 0,
  });

  useEffect(() => {
    const trackMouse = () => { interactions.current.mouseMovements++; };
    const trackKey = () => { interactions.current.keyPresses++; };
    const trackClick = () => { interactions.current.clicks++; };
    const trackScroll = () => { interactions.current.scrolls++; };
    const trackFocus = () => { interactions.current.focusEvents++; };

    document.addEventListener('mousemove', trackMouse);
    document.addEventListener('keydown', trackKey);
    document.addEventListener('click', trackClick);
    document.addEventListener('scroll', trackScroll);
    document.addEventListener('focusin', trackFocus);

    return () => {
      document.removeEventListener('mousemove', trackMouse);
      document.removeEventListener('keydown', trackKey);
      document.removeEventListener('click', trackClick);
      document.removeEventListener('scroll', trackScroll);
      document.removeEventListener('focusin', trackFocus);
    };
  }, []);

  const getInteractionScore = useCallback(() => {
    const i = interactions.current;
    let score = 0;
    const maxScore = 5;  // 5 interaction types to check

    if (i.mouseMovements > 2) score++;
    if (i.keyPresses > 5) score++;
    if (i.clicks > 0) score++;
    if (i.scrolls > 0) score++;
    if (i.focusEvents > 0) score++;

    const isHumanLike = score >= 3;  // At least 3 of 5 interaction types
    const spamScore = isHumanLike ? 0 : Math.round((1 - score / maxScore) * 20);

    return { score, maxScore, isHumanLike, spamScore };
  }, []);

  return { getInteractionScore };
}

Cloudflare Turnstile

Cloudflare Turnstile is a modern alternative to traditional CAPTCHAs like reCAPTCHA. Unlike reCAPTCHA (which often shows annoying image puzzles), Turnstile runs invisible challenges in the background. Most users never see any challenge at all -- they just see a brief checkmark animation.

How Turnstile Works

  1. You register your site with Cloudflare and get a site key (public) and secret key (private).
  2. The Turnstile widget loads on your form page and runs invisible browser challenges in the background.
  3. When the user submits the form, Turnstile provides a token.
  4. Your server sends this token to Cloudflare's verification API with your secret key.
  5. Cloudflare responds with whether the token is valid (human) or invalid (bot).

Client-Side: Adding the Widget

// 1. Add the Turnstile script to your layout or page
<Script
  src="https://challenges.cloudflare.com/turnstile/v0/api.js"
  async
  defer
/>

// 2. Add the widget to your form
<form onSubmit={handleSubmit}>
  {/* Your form fields */}
  <input type="text" name="name" />
  <input type="email" name="email" />
  <textarea name="message" />

  {/* Turnstile widget -- renders as a small checkbox/animation */}
  <div
    className="cf-turnstile"
    data-sitekey={process.env.NEXT_PUBLIC_TURNSTILE_SITE_KEY}
    data-callback="onTurnstileVerify"
  />

  <button type="submit">Send</button>
</form>

// 3. Capture the token when verification completes
<script>
  function onTurnstileVerify(token) {
    // Store the token to include in form submission
    document.getElementById('turnstile-token').value = token;
  }
</script>

Server-Side: Verifying the Token

async function verifyTurnstile(token: string, clientIP: string): Promise<boolean> {
  const secretKey = process.env.TURNSTILE_SECRET_KEY;

  // If no secret key configured, skip verification (for development)
  if (!secretKey) {
    console.log('Turnstile: No secret key, skipping verification');
    return true;
  }

  if (!token) {
    return false;  // No token provided
  }

  try {
    const response = await fetch(
      'https://challenges.cloudflare.com/turnstile/v0/siteverify',
      {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({
          secret: secretKey,
          response: token,
          remoteip: clientIP,
        }),
      }
    );

    const data = await response.json();
    return data.success === true;
  } catch (error) {
    console.error('Turnstile verification error:', error);
    return false;  // Fail closed: reject on error
  }
}
Turnstile vs reCAPTCHA: Turnstile is free, privacy-focused (no tracking cookies), and usually invisible. reCAPTCHA often requires users to identify traffic lights in images, which is frustrating and slow. Turnstile is the better choice for modern applications.

Browser Fingerprinting with FingerprintJS

Browser fingerprinting generates a unique identifier for a visitor based on their browser and device characteristics. Unlike cookies, a fingerprint persists even if the user clears cookies or uses private browsing.

What Gets Fingerprinted?

FingerprintJS collects 40+ signals to build a unique identifier:

  • Canvas rendering (how the browser draws graphics)
  • WebGL capabilities (GPU information)
  • Audio context properties
  • Installed system fonts
  • Hardware concurrency (CPU cores), device memory
  • Screen resolution and color depth
  • Timezone, language, platform
  • Browser plugins and features

Headless browsers (commonly used by bots) have distinctive fingerprints that differ from real browsers, making fingerprinting useful for bot detection.

Implementation

// hooks/useFingerprint.ts
'use client';
import { useEffect, useState, useCallback } from 'react';

interface FingerprintData {
  visitorId: string;
  confidence: number;
  success: boolean;
}

export function useFingerprint() {
  const [fingerprint, setFingerprint] = useState<FingerprintData>({
    visitorId: '',
    confidence: 0,
    success: false,
  });
  const [isLoading, setIsLoading] = useState(true);

  useEffect(() => {
    async function loadFingerprint() {
      try {
        // Dynamically import FingerprintJS (code splitting)
        const FingerprintJS = await import('@fingerprintjs/fingerprintjs');

        // Initialize the agent
        const fp = await FingerprintJS.load();

        // Get the visitor identifier
        const result = await fp.get();

        setFingerprint({
          visitorId: result.visitorId,
          confidence: result.confidence.score,
          success: true,
        });
      } catch (error) {
        setFingerprint(prev => ({ ...prev, success: false }));
      } finally {
        setIsLoading(false);
      }
    }

    loadFingerprint();
  }, []);

  // Calculate spam score based on fingerprint quality
  const getFingerprintSpamScore = useCallback(() => {
    if (!fingerprint.success) return 5;           // Failed -- slightly suspicious
    if (fingerprint.confidence < 0.3) return 8;   // Low confidence -- likely bot
    if (fingerprint.confidence < 0.5) return 3;   // Medium confidence
    return 0;                                      // High confidence -- likely real
  }, [fingerprint]);

  return { fingerprint, isLoading, getFingerprintSpamScore };
}

Using Fingerprints to Track Repeat Offenders

Once you have a visitor ID, you can track it across form submissions. If the same fingerprint submits the contact form 10 times in an hour, that is suspicious even if each individual submission looks normal:

// On the server: Track submissions by fingerprint
const submissionsByFingerprint = new Map<string, number[]>();

function checkRepeatSubmissions(visitorId: string): number {
  const now = Date.now();
  const oneHour = 60 * 60 * 1000;

  // Get existing submissions for this fingerprint
  const submissions = submissionsByFingerprint.get(visitorId) || [];

  // Remove submissions older than 1 hour
  const recent = submissions.filter(time => now - time < oneHour);

  // Add current submission
  recent.push(now);
  submissionsByFingerprint.set(visitorId, recent);

  // Score based on frequency
  if (recent.length > 10) return 30;  // Way too many
  if (recent.length > 5) return 15;   // Suspicious
  if (recent.length > 3) return 5;    // Mildly concerning
  return 0;
}
CSK Connection CSK uses FingerprintJS in the useFingerprint hook. The fingerprint data (visitor ID and confidence score) is included in every contact form submission. The server uses the confidence score as one of many signals in the spam scoring system. Low-confidence fingerprints (typical of headless browsers) add spam points.

Disposable Email Detection

Disposable email services (like 10minutemail.com, tempmail.com, guerrillamail.com) provide temporary email addresses that expire after a short time. While some legitimate users use them for privacy, spammers use them extensively because they can create unlimited "unique" email addresses.

Implementation

// lib/disposable-email.ts

// Maintain a set of known disposable email domains
const DISPOSABLE_DOMAINS = new Set([
  '10minutemail.com', '10minutemail.net',
  'tempmail.com', 'temp-mail.org', 'temp-mail.io',
  'guerrillamail.com', 'guerrillamail.org',
  'mailinator.com', 'mailinator.net',
  'throwaway.email', 'throwawaymail.com',
  'yopmail.com', 'yopmail.fr',
  'trashmail.com', 'trashmail.net',
  'maildrop.cc',
  'sharklasers.com',
  'dispostable.com',
  'fakeinbox.com',
  'getnada.com',
  // ... hundreds more domains
]);

/**
 * Check if an email uses a known disposable domain.
 */
export function isDisposableEmail(email: string): boolean {
  if (!email || typeof email !== 'string') return false;

  const domain = email.split('@')[1]?.toLowerCase();
  if (!domain) return false;

  return DISPOSABLE_DOMAINS.has(domain);
}

/**
 * Get spam score for disposable email.
 * Returns 25 points if disposable, 0 if legitimate.
 */
export function getDisposableEmailScore(email: string): number {
  return isDisposableEmail(email) ? 25 : 0;
}

In practice, the list of disposable domains is much larger -- CSK's list contains several hundred domains sourced from community-maintained lists like the disposable-email-domains GitHub project.

Combining All Defenses: The Multi-Layer Approach

The real power comes from combining all these layers into a single scoring function. Each layer is independent -- a bot might bypass one or two layers but is unlikely to bypass all of them:

async function calculateSpamScore(
  formData: ExtendedFormData,
  headers: Headers,
  clientIP: string
): Promise<SpamScoreResult> {
  // Layer 1: Content analysis (0-35 points)
  // Checks word validity, entropy, keyboard walk patterns
  const contentScore = analyzeContent(formData.message).score;

  // Layer 2: Spam pattern detection (0-30 points)
  // Checks for spam keywords, excessive links, all caps
  const patternScore = detectSpamPatterns(formData.message, formData.email).score;

  // Layer 3: Timing validation (0-20 points)
  // Was the form submitted suspiciously fast?
  const timingScore = validateTiming(formData.pageLoadTime, formData.submitTime);

  // Layer 4: Honeypot check (0 or 50 points)
  // Were hidden fields filled in?
  const honeypotScore = checkHoneypots({
    website: formData.website,
    _hp_email2: formData._hp_email2,
    _hp_phone_confirm: formData._hp_phone_confirm,
    _hp_url: formData._hp_url,
  });

  // Layer 5: Request fingerprinting (0-15 points)
  // Missing user-agent? Bot-like headers?
  const fingerprintScore = analyzeRequestHeaders(headers);

  // Layer 6: Disposable email (0 or 25 points)
  const disposableScore = getDisposableEmailScore(formData.email);

  // Layer 7: Interaction tracking (0-20 points)
  // Did the user move their mouse, type, scroll?
  const interactionScore = formData._interaction?.spamScore || 0;

  // Layer 8: Browser fingerprint (0-10 points)
  const browserScore = formData._fingerprint?.spamScore || 0;

  // Layer 9: Turnstile CAPTCHA (0 or 30 points)
  let turnstileScore = 0;
  if (formData._turnstile) {
    const valid = await verifyTurnstile(formData._turnstile, clientIP);
    if (!valid) turnstileScore = 30;
  }

  // Layer 10: Gibberish detection (0-30 points)
  const gibberishScore = isGibberish(formData.message).score;

  // Layer 11: Name validation (0-25 points)
  const nameScore = validateName(formData.name).score;

  // Calculate total
  const totalScore = contentScore + patternScore + timingScore +
    honeypotScore + fingerprintScore + disposableScore +
    interactionScore + browserScore + turnstileScore +
    gibberishScore + nameScore;

  // Determine action
  let action: 'allow' | 'log' | 'block' | 'silent_success';
  if (totalScore >= 120) action = 'silent_success';
  else if (totalScore >= 80) action = 'block';
  else if (totalScore >= 50) action = 'log';
  else action = 'allow';

  return { score: totalScore, action, breakdown: { /* all individual scores */ } };
}

Using the Score in the Contact API

// app/api/contact/route.ts
export async function POST(request: NextRequest) {
  const body = await request.json();
  const clientIP = request.headers.get('x-forwarded-for') || 'unknown';

  // Calculate spam score using all layers
  const spamResult = await calculateSpamScore(body, request.headers, clientIP);

  // Take action based on the score
  switch (spamResult.action) {
    case 'allow':
      // Score 0-49: Send the email normally
      await sendContactEmail(body);
      return NextResponse.json({ success: true });

    case 'log':
      // Score 50-79: Send the email but log it for review
      console.warn('Suspicious submission:', spamResult.breakdown);
      await sendContactEmail(body);
      return NextResponse.json({ success: true });

    case 'block':
      // Score 80-119: Reject the submission
      return NextResponse.json(
        { error: 'Your message could not be sent. Please try again.' },
        { status: 400 }
      );

    case 'silent_success':
      // Score 120+: Pretend it worked (fool the bot)
      return NextResponse.json({ success: true });
      // But we never actually send the email!
  }
}

Balancing Security vs. User Experience

Every defense layer has the potential to annoy or block legitimate users. Here is how to balance security with usability:

Defense User Impact UX Strategy
Honeypot fields Zero -- invisible to humans Use aria-hidden and tabIndex={-1}
Timing analysis Zero for normal users Set minimum to 3 seconds (generous)
Interaction tracking Zero -- passive monitoring Do not block solely on interaction score
Turnstile Minimal -- usually invisible Show as last resort, invisible by default
Fingerprinting Zero -- runs in background Use for supplementary scoring only
Disposable email Blocks privacy-conscious users Adds points but does not auto-block alone
Content analysis Could false-positive on unusual messages Use as part of scoring, not sole decision

The scoring approach is key to good UX: no single layer blocks a user by itself (except the honeypot, which only triggers for bots). A legitimate user with a slightly unusual name and message might get 10-15 points -- well under the 80-point block threshold. A bot that bypasses 3 layers still accumulates enough points from the other 8 to get caught.

CSK Connection CSK layers ALL of these defenses in its production contact form. The spam-detection.ts module tracks content analysis, timing, honeypots, request fingerprinting, gibberish detection, and name validation. The disposable-email.ts module blocks throwaway addresses. Cloudflare Turnstile provides invisible CAPTCHA protection. The useFingerprint hook uses FingerprintJS to identify repeat visitors. The useBotProtection hook provides honeypot fields and timing data. All signals feed into a scoring system with thresholds at 50 (log), 80 (block), and 120 (silent success).

Key Takeaways

  • Bots attack forms for spam, credential stuffing, fake accounts, and DDoS. Every public form needs protection.
  • Use layered defense -- no single technique catches all bots. Combine multiple independent layers.
  • Honeypot fields have zero user impact and catch most simple bots (50-point penalty).
  • Timing analysis catches bots that submit forms faster than humanly possible.
  • Interaction tracking detects bots that inject values without mouse/keyboard activity.
  • Cloudflare Turnstile is the modern CAPTCHA -- invisible to most users, effective against bots.
  • Browser fingerprinting with FingerprintJS identifies visitors even without cookies, useful for tracking repeat offenders.
  • Disposable email detection blocks throwaway addresses commonly used by spammers.
  • A scoring system (allow/log/block/silent_success) lets you tune thresholds without binary pass/fail decisions.
  • "Silent success" is a powerful anti-spam technique: pretend the submission worked so the bot does not adapt.
  • Balance security with UX: no single layer should block legitimate users. The combination catches bots.
