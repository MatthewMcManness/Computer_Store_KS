Vision & Goals

The Goal: Build a unified platform where employees never need to leave computerstoreks.com to do their jobs, and customers have full self-service access to their accounts, repairs, and purchases.

The Result: Consistent workflows, faster service, better customer experience, and a scalable foundation for MSP expansion and multi-location growth.

Core Objectives

Employee Efficiency

Eliminate context-switching between RepairShopr and NinjaOne. Standardized workflows ensure every employee follows the same process.

  • One interface for all tasks
  • Templated ticket creation
  • Required fields enforcement
  • Standardized note formats

Customer Self-Service

Customers can check status, pay invoices, and manage their accounts 24/7 without calling the store.

  • Ticket status tracking
  • Online payments
  • Asset management
  • Protection plan signup

Revenue Growth

New revenue streams through PC builder, automated marketing, and MSP service expansion.

  • Custom PC configurator
  • Automated social media
  • B2B MSP portal ready
  • Multi-location support

Critical Deadline: Q1 2026

Payment Processing: Stripe

Stripe is the unified payment platform for all transactions. See Stripe Integration Plan for complete details including fee structures, BNPL options, and implementation timeline.

  • In-Person: 2.7% + $0.05 (Stripe Terminal)
  • Online: 2.9% + $0.30 (Stripe Checkout)
  • ACH: 0.8% max $5 (for large MSP invoices)
  • Subscriptions: 2.9% + $0.30 + 0.5% (Protection Plans, MSP)
  • BNPL: Affirm, Klarna, Afterpay integrated (4-6% fee, you get paid immediately)

Data Flow Architecture

Principle: RepairShopr as Source of Truth

RepairShopr remains the master database for customers, tickets, and invoices. Our platform reads from and writes to RepairShopr, ensuring data consistency and providing a fallback if our system has issues. This also means Max can still access RepairShopr directly for accounting as needed.

🔐 Authentication Layer
  • Custom Supabase Auth (not RepairShopr)
  • Employee vs Customer roles
  • Link accounts to RepairShopr IDs
  • Session management

  • RepairShopr API wrapper
  • NinjaOne API wrapper
  • Rate limiting & caching
💾 Local Cache Layer
  • Supabase for session data

  • Customer search index

🖥️ Frontend Layer
  • Employee Portal (protected)

  • Admin settings

Phase 1: Foundation

🏗️ Authentication & Core Infrastructure

Build the foundation that everything else depends on.

Critical Path ~40-50 hours

  1. Set Up Supabase Authentication

    Replace RepairShopr auth with custom Supabase auth for both employees and customers.

    • Configure Supabase Auth in project
    • Create user roles: admin, technician, customer
    • Set up email verification flow
    • Create profiles table linking to RepairShopr customer IDs
    • Implement password reset flow
    • Add MFA option for employees (recommended for admin)

  2. Create User Profile System

    Link Supabase users to RepairShopr records.

    • Create user_profiles table with repairshopr_customer_id
    • Create employee_profiles table with role and permissions
    • Build account linking flow for existing RepairShopr customers
    • Auto-create RepairShopr customer on new signup

  3. Build API Wrapper Services

    Create typed, cached wrappers for external APIs.

    • RepairShopr API service (src/lib/repairshopr.ts)
    • NinjaOne API service (src/lib/ninjaone.ts)
    • Implement rate limiting (RepairShopr: 180/min, NinjaOne: check docs)
    • Add response caching layer (5-minute TTL for lists, 1-minute for detail)
    • Error handling and retry logic

  4. Create Database Schema

    Local tables for features beyond RepairShopr.

    • user_profiles - Auth user to RepairShopr mapping
    • employee_profiles - Role, permissions, preferences
    • ticket_templates - Standardized ticket templates
    • note_templates - Standardized note formats
    • workflow_steps - Custom workflow definitions
    • device_mappings - RepairShopr Asset ID to NinjaOne Device ID
    • hardware_alerts - Push notifications for failing hardware

  5. Set Up Route Protection

    Middleware to protect employee and customer routes.

    • Create auth middleware for API routes
    • Protect /employee/* routes (employee role required)
    • Protect /portal/* routes (customer role required)
    • Protect /admin/* routes (admin role required)

  6. Configure Stripe Integration

    Set up Stripe for all payment processing.

    • Verify Stripe account is active and verified
    • Configure Stripe in RepairShopr settings
    • Set up Stripe API keys in environment variables
    • Create Stripe webhook endpoint (/api/webhooks/stripe)
    • Test payment flow with small transaction
    • Order Stripe Terminal hardware (2x Reader M2 @ $59 each)
    • Configure Stripe Billing products for Protection Plans

Phase 2: Employee Portal - RepairShopr

🎫 Ticket & Customer Management

Replace RepairShopr's cluttered interface with a streamlined, workflow-driven experience.

Critical Path ~80-100 hours

Pain Points to Solve

  • Too much information: Show only relevant fields, hide the rest
  • No standardized workflows: Force consistent steps for every ticket type
  • Manual everything: Auto-fill from templates, auto-create invoices
  • Inconsistent notes: Structured note entry with required fields

  1. Build Customer Search & Management

    Fast, keyboard-friendly customer lookup.

    • Global search bar (Cmd/Ctrl + K) for customers
    • Search by name, phone, email
    • Quick-create customer inline (minimal fields)
    • Customer detail view with only relevant info
    • Link to their tickets, invoices, assets

  2. Create Ticket Templates System

    Pre-defined templates for common repair types.

    • Template builder in admin settings
    • Templates include: default status, problem type, required fields, estimated time
    • Example templates: Virus Removal, Hardware Diagnostic, Data Transfer, Screen Repair
    • Templates can auto-set ticket properties and pre-fill descriptions

  3. Build Ticket Creation Workflow

    Guided, step-by-step ticket creation.

    • Step 1: Select or create customer
    • Step 2: Choose ticket template (or blank)
    • Step 3: Fill required fields (template-driven)
    • Step 4: Asset selection or creation
    • Step 5: Confirmation with intake checklist
    • Auto-create in RepairShopr on submit

  4. Build Ticket Dashboard

    Kanban-style view of all open tickets.

    • Columns by status: Intake, Diagnosing, Waiting for Parts, In Progress, Ready for Pickup
    • Drag-and-drop to change status
    • Quick filters: assigned to me, unassigned, by ticket type
    • Color coding by priority and age
    • Click to expand ticket details inline

  5. Build Ticket Detail View

    Clean, focused ticket management.

    • Customer info summary at top
    • Asset info with NinjaOne link (if available)
    • Status change with required note
    • Time tracking integration
    • Structured note entry (what was done, what's next, parts used)
    • Invoice creation button

  6. Build Standardized Notes System

    No more freeform notes without structure.

    • Note types: Diagnostic, Work Performed, Customer Communication, Internal
    • Required fields per note type
    • Time spent tracking
    • Parts/materials used selection
    • Auto-timestamp and employee attribution

  7. Build Invoice Management

    Streamlined invoice creation from tickets.

    • One-click invoice from ticket (pulls line items from notes)
    • Add labor, parts, services
    • Apply discounts and protection plan benefits
    • Send invoice email directly
    • Payment processing (link to existing Stripe/Square integration)

  8. Build Inventory Quick-Access

    Search and use inventory without leaving ticket.

    • Search inventory by name, SKU, category
    • Add to ticket/invoice inline
    • Stock level warnings
    • Link to full inventory management (future phase)

  9. Build Quote (Estimate) System

    Renamed from "Estimates" per your preference.

    • Create quote from ticket or standalone
    • Add line items with descriptions
    • Convert quote to invoice when approved
    • Email quote to customer
    • Quote expiration tracking

  10. Build POS Functionality

    Cash drawer control and point-of-sale.

    • Open drawer button (API call to hardware)
    • Close drawer / end-of-day reconciliation
    • Quick sale mode (walk-in purchases without ticket)
    • Receipt printing (integrate with existing printer)

  11. Build Leads Management

    Capture and track sales leads.

    • Lead inbox view
    • Convert lead to customer + ticket
    • Lead status tracking (new, contacted, quoted, won, lost)
    • Integrate with Cytracom voicemail (see below)

  12. Cytracom Voicemail Integration

    Direct voicemail to website instead of RepairShopr.

    • Research Cytracom API capabilities
    • Set up webhook for new voicemail notifications
    • Create voicemail inbox in employee portal
    • Transcription display (if Cytracom provides)
    • One-click convert to lead or ticket
    • Link voicemail to customer if phone number matches

Cytracom Research Needed

Before implementing voicemail integration, research Cytracom's API documentation. Key questions: Do they have a webhook for new voicemails? Can we retrieve audio files? Do they provide transcriptions? If no API exists, alternative is email parsing if they send voicemail notifications via email.

Phase 3: Employee Portal - NinjaOne

🖥️ RMM & Remote Access Integration

Unified device management without leaving the portal.

Critical Path ~50-60 hours

Action Required: Technician Input

You mentioned needing to ask a technician about specific NinjaOne features. Before starting this phase, schedule a 30-minute session with a tech to document: which NinjaOne features they use daily, their workflow for remote sessions, and what frustrations they have.

  1. Build Device-Customer Mapping

    Link NinjaOne devices to RepairShopr customers and assets.

    • Create mapping table in Supabase
    • Auto-match by serial number (RepairShopr asset → NinjaOne device)
    • Manual linking UI for unmatched devices
    • Sync NinjaOne organizations to RepairShopr customers

  2. Build Customer 360 View

    See customer, tickets, AND devices on one screen.

    • Customer info from RepairShopr
    • Device list from NinjaOne (with status indicators)
    • Open tickets from RepairShopr
    • Invoice history
    • Protection plan status

  3. Build Device Detail View

    Full device information from NinjaOne.

    • System info: OS, RAM, storage, CPU
    • Hardware health indicators
    • Last seen / online status
    • Installed software list
    • Patch status
    • Recent alerts and events

  4. Implement Remote Access

    Launch remote session directly from portal.

    • Research NinjaOne remote access API (Splashtop/TeamViewer)
    • One-click "Connect" button on device
    • Opens remote session in new tab/window
    • Log remote sessions for audit trail

  5. Build Quick Actions

    Common tasks without full NinjaOne access.

    • Restart device remotely
    • Run driver updates
    • Run Windows Update
    • Clear temp files (if scripted in Ninja)
    • Run antivirus scan

  6. Build Hardware Monitoring & Alerts

    Proactive alerts for failing hardware.

    • Poll NinjaOne for hardware health (S.M.A.R.T., temps, etc.)
    • Define alert thresholds (disk health critical, CPU overheating)
    • Push notifications to employee portal (toast + notification center)
    • Email/SMS alert to customer (optional per customer setting)
    • Auto-create ticket when critical alert fires

  7. Build MSP Dashboard View

    Overview for B2B managed clients.

    • Organization/company selector
    • All devices for that organization
    • Health summary (% healthy, % needs attention)
    • Open alerts across all devices
    • Quick filters by status

Phase 5: PC Builder

🖥️ Custom PC Configurator

iBuyPower-style build experience for customers and technicians.

Medium Priority ~100-120 hours

Reference: Custom PC Implementation Plan

Detailed supplier relationships and pricing strategy are documented in implementation_plan_custom_pc.html. This phase focuses on the software implementation.

  1. Build Parts Database

    Central catalog of PC components with compatibility data.

    • Create pc_parts table in Supabase
    • Categories: CPU, Motherboard, RAM, GPU, Storage, PSU, Case, Cooling
    • Compatibility fields: socket type, form factor, wattage, etc.
    • Pricing fields: cost, markup, retail price
    • Supplier fields: source, SKU, availability

  2. Build Supplier Price Integration

    Pull live pricing from distributors.

    • Ingram Micro API integration (if available)
    • TD SYNNEX API integration (if available)
    • Newegg Business API integration
    • Fallback: manual price updates with import tool
    • Auto-calculate markup based on rules

  3. Build Compatibility Engine

    Ensure all selected parts work together.

    • CPU + Motherboard socket match
    • RAM type matches motherboard
    • PSU wattage sufficient for components
    • Case form factor fits motherboard and GPU
    • Cooling compatibility (tower height, AIO mount)
    • Display warnings/errors for incompatibilities

  4. Build Customer-Facing Configurator

    Visual builder interface for customers.

    • Start with pre-built tiers (Budget Gaming, Mid-Range, High-End, Workstation)
    • Customize any component
    • Real-time price updates
    • Performance estimates (gaming FPS, workstation benchmarks)
    • Save build for later
    • Request quote → creates Quote in RepairShopr

  5. Build Technician View

    Additional info for internal use.

    • Shows cost price and margin
    • Shows supplier and availability
    • Quick order from supplier
    • Build notes and special instructions
    • Convert quote to ticket for assembly

  6. Build Quote/Invoice Integration

    Seamless handoff to RepairShopr.

    • Generate quote with all components as line items
    • Include labor for assembly and testing
    • Customer approval triggers ticket creation
    • Parts checklist for order tracking
