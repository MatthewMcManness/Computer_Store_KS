SEO, Metadata & Open Graph

Make your pages discoverable by search engines and look professional when shared on social media.

What You Will Learn

  • Understand what SEO is and why it matters for business websites
  • Use the Next.js metadata export in layout.tsx and page.tsx
  • Write effective titles and descriptions
  • Configure Open Graph tags for social media sharing previews
  • Add Twitter card metadata
  • Set canonical URLs to prevent duplicate content issues
  • Implement Schema.org structured data with JSON-LD
  • Configure robots, sitemaps, favicons, and app icons

What Is SEO and Why Does It Matter?

SEO (Search Engine Optimization) is the practice of making your website easy for search engines like Google to find, understand, and rank. For a business website, SEO is often the difference between "found by customers" and "invisible online."

Consider this scenario: someone in Topeka, Kansas, types "computer repair near me" into Google. If your website has good SEO, it appears on the first page of results. If it does not, potential customers will never know you exist.

SEO involves many factors, but the technical foundations you control as a developer include:

  • Metadata: Title tags, descriptions, and structured data that tell search engines what each page is about
  • Open Graph: Tags that control how your pages look when shared on social media
  • Performance: Fast-loading pages rank higher (Core Web Vitals)
  • Accessibility: Semantic HTML, alt text on images, proper heading hierarchy
  • Mobile-friendliness: Responsive design is required for good rankings
  • Crawlability: Robots.txt and sitemaps help search engines navigate your site
Analogy: Think of metadata like a book's cover and back-cover blurb. The title tag is the book title, the description is the blurb that convinces people to read it, and Open Graph tags are the cover art that makes it stand out on the shelf (or in someone's social media feed).

The Metadata Export in Next.js

Next.js provides a built-in metadata export that generates the correct <head> tags automatically. You export a metadata object from any layout.tsx or page.tsx file:

Root Layout Metadata (Global Defaults)

// src/app/layout.tsx
import type { Metadata } from 'next';

export const metadata: Metadata = {
  title: {
    template: '%s | Computer Store KS',    // %s is replaced by page-specific title
    default: 'Computer Store KS - Computer Repair in Topeka, Kansas',
  },
  description: 'Professional computer repair, custom-built PCs, and IT services in Topeka, Kansas. Fast diagnostics, virus removal, data recovery, and more.',
  keywords: ['computer repair', 'Topeka Kansas', 'PC repair', 'custom computers'],
};

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>{children}</body>
    </html>
  );
}

Page-Specific Metadata (Overrides Defaults)

// src/app/(public)/about/page.tsx
import type { Metadata } from 'next';

export const metadata: Metadata = {
  title: 'About Us',  // Becomes: "About Us | Computer Store KS" (from template)
  description: 'Learn about Computer Store KS - family-owned computer repair serving Topeka since 2020. Meet our team of certified technicians.',
};

export default function AboutPage() {
  return (
    <main>
      <h1>About Us</h1>
      {/* page content */}
    </main>
  );
}

The metadata merges hierarchically: page metadata overrides layout metadata, which overrides root layout metadata. The template pattern in the title is particularly useful -- it ensures every page title follows a consistent format like "Page Name | Site Name."

Dynamic Metadata (from Database)

For dynamic pages (like blog posts), use the generateMetadata function instead of the static metadata export:

// src/app/(public)/blog/[slug]/page.tsx
import type { Metadata } from 'next';

// Dynamic metadata generated from the URL params
export async function generateMetadata({
  params,
}: {
  params: { slug: string };
}): Promise<Metadata> {
  // Fetch the post data
  const post = await getPostBySlug(params.slug);

  if (!post) {
    return { title: 'Post Not Found' };
  }

  return {
    title: post.title,
    description: post.excerpt,
    openGraph: {
      title: post.title,
      description: post.excerpt,
      images: post.featured_image ? [{ url: post.featured_image }] : [],
    },
  };
}

export default async function BlogPostPage({ params }: { params: { slug: string } }) {
  // ... render the post
}

Title and Description Best Practices

Title Tag

The title tag is the single most important SEO element. It appears in:

  • The browser tab
  • Google search results as the clickable headline
  • Social media previews

Best practices:

  • Length: 50-60 characters (Google truncates longer titles)
  • Primary keyword first: "Computer Repair Topeka | Computer Store KS" not "Computer Store KS | Computer Repair Topeka"
  • Unique per page: Every page must have a different title
  • Descriptive: Tell users what the page is about
  • Brand at the end: Use the template: '%s | Brand' pattern

Meta Description

The description appears below the title in search results. It does not directly affect ranking, but a compelling description increases click-through rates.

  • Length: 150-160 characters
  • Include a call to action: "Call us today for fast PC repair"
  • Include key information: Location, specialty, unique value
  • Unique per page: Never duplicate descriptions across pages
// GOOD title and description examples
export const metadata: Metadata = {
  title: 'Virus Removal & Malware Cleanup',
  description: 'Fast, thorough virus and malware removal in Topeka, KS. Same-day service available. We clean your PC and install protection to prevent reinfection.',
};

// BAD: too generic, no keywords, no call to action
export const metadata: Metadata = {
  title: 'Services',
  description: 'We offer various services for your computer needs.',
};

Open Graph Protocol

Open Graph (OG) is a protocol created by Facebook that controls how your page appears when shared on social media platforms. When someone shares your URL on Facebook, LinkedIn, Discord, Slack, or iMessage, Open Graph tags determine the title, description, and preview image shown.

export const metadata: Metadata = {
  title: 'Computer Store KS - Computer Repair in Topeka',
  description: 'Professional computer repair and custom PCs in Topeka, Kansas.',
  openGraph: {
    title: 'Computer Store KS - Computer Repair in Topeka',
    description: 'Professional computer repair and custom PCs in Topeka, Kansas.',
    url: 'https://computerstoreks.com',
    siteName: 'Computer Store KS',
    images: [
      {
        url: 'https://computerstoreks.com/images/og-image.jpg',
        width: 1200,
        height: 630,
        alt: 'Computer Store KS storefront and repair workshop',
      },
    ],
    locale: 'en_US',
    type: 'website',  // Other types: 'article', 'product', 'profile'
  },
};

Open Graph Image Guidelines

  • Recommended size: 1200 x 630 pixels (Facebook's recommended ratio)
  • Minimum size: 600 x 315 pixels
  • Format: JPEG or PNG (avoid SVG)
  • Content: Include your logo, a key visual, and optionally the page title
  • File size: Under 1MB for fast loading

For Blog Articles

openGraph: {
  title: post.title,
  description: post.excerpt,
  type: 'article',
  publishedTime: post.published_at,
  modifiedTime: post.updated_at,
  authors: [post.author_name],
  tags: post.tags,
  images: [{ url: post.featured_image }],
}

Twitter Cards

Twitter (now X) has its own metadata system for controlling link previews. Next.js supports it natively:

export const metadata: Metadata = {
  twitter: {
    card: 'summary_large_image',  // Options: 'summary', 'summary_large_image', 'app', 'player'
    title: 'Computer Store KS - Computer Repair in Topeka',
    description: 'Professional computer repair and custom PCs in Topeka, Kansas.',
    images: ['https://computerstoreks.com/images/twitter-card.jpg'],
    creator: '@computerstoreks',
    site: '@computerstoreks',
  },
};

Twitter Card Types

Type Preview Style Best For
summary Small square image + title + description General pages, articles without prominent images
summary_large_image Large banner image + title + description Blog posts, product pages, landing pages
app App download card Mobile app promotion
player Embedded video/audio player Video or music content

Canonical URLs

A canonical URL tells search engines which version of a page is the "official" one. This prevents duplicate content issues when the same page is accessible at multiple URLs:

// These all show the same content:
// https://computerstoreks.com/services
// https://computerstoreks.com/services?ref=homepage
// https://www.computerstoreks.com/services
// http://computerstoreks.com/services

// The canonical URL says "this is the real one":
export const metadata: Metadata = {
  alternates: {
    canonical: 'https://computerstoreks.com/services',
  },
};

Without canonical URLs, search engines might split your page's ranking power across multiple URL variations, hurting your position in search results.

Setting Canonical URLs in the Root Layout

// src/app/layout.tsx
export const metadata: Metadata = {
  metadataBase: new URL('https://computerstoreks.com'),
  // Now all relative URLs in metadata are resolved against this base
};

With metadataBase set, relative paths in Open Graph images and canonical URLs are automatically resolved to full URLs.

Structured Data: Schema.org JSON-LD

Structured data is machine-readable information about your page that helps search engines understand your content better. Google uses structured data to display rich results -- enhanced search listings with ratings, prices, business hours, and more.

The most common format is JSON-LD (JSON for Linked Data), embedded in a <script> tag. For a local business website, the LocalBusiness schema is essential:

// src/app/layout.tsx
export default function RootLayout({ children }: { children: React.ReactNode }) {
  const jsonLd = {
    '@context': 'https://schema.org',
    '@type': 'LocalBusiness',
    name: 'Computer Store KS',
    description: 'Professional computer repair and custom-built PCs in Topeka, Kansas.',
    url: 'https://computerstoreks.com',
    telephone: '+1-785-XXX-XXXX',
    email: 'contact@computerstoreks.com',
    address: {
      '@type': 'PostalAddress',
      streetAddress: '123 Main Street',
      addressLocality: 'Topeka',
      addressRegion: 'KS',
      postalCode: '66601',
      addressCountry: 'US',
    },
    geo: {
      '@type': 'GeoCoordinates',
      latitude: 39.0473,
      longitude: -95.6752,
    },
    openingHoursSpecification: [
      {
        '@type': 'OpeningHoursSpecification',
        dayOfWeek: ['Monday', 'Tuesday', 'Wednesday', 'Thursday', 'Friday'],
        opens: '09:00',
        closes: '18:00',
      },
      {
        '@type': 'OpeningHoursSpecification',
        dayOfWeek: 'Saturday',
        opens: '10:00',
        closes: '14:00',
      },
    ],
    image: 'https://computerstoreks.com/images/storefront.jpg',
    priceRange: '$$',
    sameAs: [
      'https://www.facebook.com/computerstoreks',
      'https://www.google.com/maps/place/...',
    ],
  };

  return (
    <html lang="en">
      <body>
        <script
          type="application/ld+json"
          dangerouslySetInnerHTML={{ __html: JSON.stringify(jsonLd) }}
        />
        {children}
      </body>
    </html>
  );
}

Blog Post Structured Data

// src/app/(public)/blog/[slug]/page.tsx

export default async function BlogPostPage({ params }: { params: { slug: string } }) {
  const post = await getPostBySlug(params.slug);

  const articleJsonLd = {
    '@context': 'https://schema.org',
    '@type': 'Article',
    headline: post.title,
    description: post.excerpt,
    image: post.featured_image,
    datePublished: post.published_at,
    dateModified: post.updated_at,
    author: {
      '@type': 'Organization',
      name: 'Computer Store KS',
    },
  };

  return (
    <article>
      <script
        type="application/ld+json"
        dangerouslySetInnerHTML={{ __html: JSON.stringify(articleJsonLd) }}
      />
      <h1>{post.title}</h1>
      {/* article content */}
    </article>
  );
}
Test Your Structured Data: Use Google's Rich Results Test to verify your JSON-LD is valid and eligible for rich results in search.

Robots Configuration

The robots metadata tells search engines which pages to index and which links to follow:

// Public pages -- index everything
export const metadata: Metadata = {
  robots: {
    index: true,     // Allow search engines to index this page
    follow: true,    // Follow links on this page
  },
};

// Admin pages -- do NOT index
export const metadata: Metadata = {
  robots: {
    index: false,    // Do NOT show in search results
    follow: false,   // Do NOT follow links
  },
};

robots.txt File

You can also generate a robots.txt file using the Next.js metadata API:

// src/app/robots.ts
import type { MetadataRoute } from 'next';

export default function robots(): MetadataRoute.Robots {
  return {
    rules: {
      userAgent: '*',
      allow: '/',
      disallow: ['/admin/', '/api/', '/portal/'],
    },
    sitemap: 'https://computerstoreks.com/sitemap.xml',
  };
}

Sitemap Generation

A sitemap is an XML file that lists all the important pages on your site, helping search engines discover and crawl them efficiently:

// src/app/sitemap.ts
import type { MetadataRoute } from 'next';

export default async function sitemap(): Promise<MetadataRoute.Sitemap> {
  // Static pages
  const staticPages = [
    { url: 'https://computerstoreks.com', lastModified: new Date(), priority: 1.0 },
    { url: 'https://computerstoreks.com/about', lastModified: new Date(), priority: 0.8 },
    { url: 'https://computerstoreks.com/services', lastModified: new Date(), priority: 0.9 },
    { url: 'https://computerstoreks.com/contact', lastModified: new Date(), priority: 0.8 },
    { url: 'https://computerstoreks.com/blog', lastModified: new Date(), priority: 0.7 },
  ];

  // Dynamic pages (from database)
  const posts = await getAllPublishedPosts();
  const blogPages = posts.map(post => ({
    url: `https://computerstoreks.com/blog/${post.slug}`,
    lastModified: new Date(post.updated_at),
    priority: 0.6,
  }));

  return [...staticPages, ...blogPages];
}

Next.js automatically serves this at /sitemap.xml. Submit it to Google Search Console to speed up indexing.

Favicons and App Icons

Favicons are the small icons that appear in browser tabs, bookmarks, and when users add your site to their phone's home screen.

File-Based Approach (Simplest)

Place icon files directly in the src/app/ directory with specific names:

src/app/
├── favicon.ico           # Browser tab icon (32x32)
├── icon.png              # Modern browsers (512x512, auto-resized)
├── apple-icon.png        # Apple devices (180x180)
└── opengraph-image.jpg   # Default OG image (1200x630)

Next.js automatically generates the appropriate <link> tags in the HTML head for these files.

Metadata-Based Approach (More Control)

export const metadata: Metadata = {
  icons: {
    icon: [
      { url: '/favicon-32x32.png', sizes: '32x32', type: 'image/png' },
      { url: '/favicon-16x16.png', sizes: '16x16', type: 'image/png' },
    ],
    apple: [
      { url: '/apple-touch-icon.png', sizes: '180x180', type: 'image/png' },
    ],
    other: [
      { rel: 'mask-icon', url: '/safari-pinned-tab.svg', color: '#0863fd' },
    ],
  },
  manifest: '/site.webmanifest',
};

Testing Social Media Previews

After adding Open Graph and Twitter metadata, test how your pages look when shared:

  • Facebook: Facebook Sharing Debugger -- paste your URL to preview
  • Twitter: Twitter Card Validator -- test your card appearance
  • LinkedIn: LinkedIn Post Inspector -- preview sharing
  • General: OpenGraph.xyz -- test for multiple platforms at once
Caching Issue: Social media platforms cache your OG data aggressively. After updating your metadata, you must use each platform's debug tool to force a re-scrape. Simply sharing the URL again will show the old cached version.

Complete Metadata Example

Here is a comprehensive root layout metadata setup that covers all the bases:

// src/app/layout.tsx
import type { Metadata } from 'next';

export const metadata: Metadata = {
  // Base URL for resolving relative paths
  metadataBase: new URL('https://computerstoreks.com'),

  // Title with template
  title: {
    template: '%s | Computer Store KS',
    default: 'Computer Store KS - Computer Repair in Topeka, Kansas',
  },

  // Description
  description: 'Professional computer repair, custom-built PCs, and IT services in Topeka, Kansas. Fast diagnostics, virus removal, data recovery, and more.',

  // Keywords (less important now, but does not hurt)
  keywords: ['computer repair', 'Topeka KS', 'PC repair', 'custom computers', 'virus removal'],

  // Canonical URL
  alternates: {
    canonical: '/',
  },

  // Open Graph
  openGraph: {
    title: 'Computer Store KS - Computer Repair in Topeka, Kansas',
    description: 'Professional computer repair, custom PCs, and IT services.',
    url: 'https://computerstoreks.com',
    siteName: 'Computer Store KS',
    images: [
      {
        url: '/images/og-image.jpg',
        width: 1200,
        height: 630,
        alt: 'Computer Store KS - Professional Computer Repair',
      },
    ],
    locale: 'en_US',
    type: 'website',
  },

  // Twitter Card
  twitter: {
    card: 'summary_large_image',
    title: 'Computer Store KS - Computer Repair in Topeka',
    description: 'Professional computer repair, custom PCs, and IT services.',
    images: ['/images/twitter-card.jpg'],
  },

  // Robots
  robots: {
    index: true,
    follow: true,
    googleBot: {
      index: true,
      follow: true,
      'max-video-preview': -1,
      'max-image-preview': 'large',
      'max-snippet': -1,
    },
  },

  // Icons
  icons: {
    icon: '/favicon.ico',
    apple: '/apple-touch-icon.png',
  },
};
CSK Connection Computer Store KS's root layout.tsx exports comprehensive metadata with the title template pattern ("%s | Computer Store KS"), Open Graph images, Twitter cards, and a metadataBase pointing to computerstoreks.com. The layout also includes a Schema.org LocalBusiness JSON-LD script with the store's address, hours, phone number, and Google Maps link. Blog posts use generateMetadata to dynamically set titles, descriptions, and OG images from the post's database record. The canonical URL setup prevents duplicate content issues between www and non-www versions of URLs.

Exercises

  1. Add metadata to your project: Export a metadata object from your root layout.tsx with a title template, description, and keywords. Add unique metadata to at least three pages. Verify in the browser by right-clicking and selecting "View Page Source" -- look for the <title> and <meta> tags.
  2. Configure Open Graph: Add Open Graph metadata to your homepage. Create a 1200x630 image (use any design tool or a screenshot) and add it as the OG image. Test with OpenGraph.xyz.
  3. Dynamic metadata: If you have a blog or product page with dynamic routes, implement generateMetadata that sets the title and description from the page data. Test with different slugs.
  4. Add structured data: Create a LocalBusiness JSON-LD script in your root layout. Include the business name, address, hours, and phone number. Validate it with Google's Rich Results Test.
  5. Generate a sitemap: Create a src/app/sitemap.ts file that lists all your pages. Visit localhost:3000/sitemap.xml to verify it generates valid XML.
  6. Robots.txt: Create a src/app/robots.ts file that allows crawling of public pages but blocks /admin/ and /api/. Visit localhost:3000/robots.txt to verify.

Key Takeaways

  • SEO is essential for business websites -- it determines whether customers can find you through search engines.
  • Next.js provides a built-in metadata export for static pages and generateMetadata for dynamic pages.
  • Titles should be 50-60 characters with the primary keyword first. Descriptions should be 150-160 characters with a call to action.
  • Open Graph tags control social media sharing previews. Always include an OG image (1200x630px) for professional appearance.
  • Twitter cards need their own metadata (card, title, description, images).
  • Canonical URLs prevent duplicate content issues and consolidate ranking signals.
  • Schema.org JSON-LD structured data enables rich search results (business hours, ratings, product details).
  • robots.ts controls what search engines crawl; sitemap.ts helps them discover all your pages.
  • Always test social previews with platform-specific debug tools after updating metadata.
