Full-Stack Web Development Curriculum

A complete lesson plan that takes a beginner from zero knowledge to building a production-grade business website — modeled on the Computer Store KS tech stack.

12 Phases • 56 Lessons • Covers 30+ Technologies

About This Curriculum

The Computer Store KS website (computerstoreks.com) is a real production application built for a computer repair business in Topeka, Kansas. It includes a public marketing site, an employee admin portal, blog system, gallery, customer intake, ticket management, and integrations with half a dozen third-party services.

This document breaks down every technology that went into building it and organizes them into a logical sequence of lessons. Each lesson has a clear goal and lists the specific topics a student must master. "CSK Connection" boxes show exactly where each concept appears in the real codebase.

No prior programming experience is assumed. By the end, a student will be capable of building and deploying a comparable full-stack application.

Phase 1

Web Fundamentals

Understand how the web works and learn the three core languages every website is built with.

Estimated: 4–6 weeks
01 How the Web Works
Goal: Understand the request/response cycle that powers every website.
  • Clients and servers — what your browser actually does
  • HTTP protocol: requests, responses, status codes (200, 404, 500)
  • URLs, domains, DNS — how "computerstoreks.com" becomes a server
  • HTTPS and TLS — why the padlock matters
  • Static vs. dynamic websites
  • What a "full-stack" application means
CSK Connection: Every page load on computerstoreks.com triggers HTTP requests. The site forces HTTPS via HSTS headers defined in next.config.mjs and middleware.ts.
02 HTML — Structuring Content
Goal: Build well-structured web pages using semantic HTML.
  • HTML document structure: <!DOCTYPE>, <html>, <head>, <body>
  • Semantic elements: <header>, <nav>, <main>, <section>, <footer>
  • Text: headings, paragraphs, lists, links
  • Images: <img>, alt text, formats (PNG, JPG, SVG, WebP)
  • Forms: <input>, <textarea>, <select>, <button>
  • Tables for tabular data
  • Accessibility basics: ARIA, screen readers, keyboard navigation
CSK Connection: The public pages use semantic HTML throughout — <section class="hero">, <nav> in Header.tsx, form elements in the contact page, and SVG logos in public/assets/.
03 CSS — Visual Styling
Goal: Style HTML pages with layouts, colors, typography, and visual effects.
  • Selectors: element, class, ID, attribute, pseudo-class/element
  • The box model: margin, padding, border, content
  • Colors, backgrounds, gradients (linear-gradient)
  • Typography: font families, sizes, weights, line-height
  • Layout: Flexbox and CSS Grid
  • Positioning: static, relative, absolute, fixed, sticky
  • Transitions and transforms
  • Box shadows, border-radius, filters (drop-shadow)
  • CSS custom properties (variables)
CSK Connection: static-styles.css (570+ lines) styles all public pages with gradients, box-shadows, flexbox layouts, and CSS filters. The silver plaque logo effect uses linear-gradient, box-shadow with insets, and drop-shadow filters.
04 Responsive Design & Media Queries
Goal: Make websites look great on phones, tablets, and desktops.
  • The viewport meta tag
  • Mobile-first vs. desktop-first approach
  • Media queries: breakpoints, min-width, max-width
  • Fluid layouts: percentages, vw/vh, clamp()
  • Responsive images: max-width: 100%, srcset
  • Flexible navigation patterns (hamburger menus)
  • Testing across devices and browser dev tools
CSK Connection: CSK's ticket filter bar collapses to a grid on mobile. The hero section, navigation, and all public pages adapt via media queries in static-styles.css. Admin pages use Tailwind's responsive prefixes (md:, lg:).
05 JavaScript Fundamentals
Goal: Write programs using variables, functions, control flow, and data structures.
  • Variables: let, const (never var)
  • Data types: string, number, boolean, null, undefined, object, array
  • Operators: arithmetic, comparison, logical
  • Control flow: if/else, ternary, switch
  • Loops: for, for...of, while
  • Functions: declarations, expressions, arrow functions
  • Objects and arrays: destructuring, spread operator, methods
  • Template literals
  • Error handling: try/catch/finally
CSK Connection: Every .ts and .tsx file in the project uses these fundamentals. Arrow functions, destructuring, spread operators, and template literals are used pervasively throughout all components and API routes.
06 JavaScript — The DOM & Events
Goal: Understand how JavaScript interacts with web pages (even though React abstracts most of this).
  • The Document Object Model (DOM) tree
  • Selecting elements: querySelector, getElementById
  • Modifying elements: textContent, classList, style
  • Event listeners: click, submit, keydown, change
  • Event propagation: bubbling and capturing
  • Form handling and preventDefault()
  • Why frameworks like React exist (the pain of manual DOM updates)
CSK Connection: CSK's spam detection system (spam-detection.ts) directly tracks DOM events — mouse movements, keyboard presses, and interaction timing to detect bots. Understanding the DOM explains what React is abstracting away.
07 Asynchronous JavaScript
Goal: Handle operations that take time — API calls, database queries, file reads.
  • Synchronous vs. asynchronous execution
  • Callbacks and callback hell
  • Promises: .then(), .catch(), .finally()
  • async/await syntax
  • Promise.all() for parallel operations
  • The fetch() API for HTTP requests
  • JSON: JSON.parse() and JSON.stringify()
  • Error handling in async code
CSK Connection: Nearly every API route and server component uses async/await. The dashboard uses Promise.all() to fetch tickets, customers, and status data in parallel. All Supabase and RepairShopr calls are async.

Phase 1 Milestone

Build a static multi-page business website with a homepage, services page, contact form, and responsive navigation — using only HTML, CSS, and vanilla JavaScript.

Set up a professional development workflow with the command line, version control, and package management.

Goal: Navigate and operate your computer through a terminal.
  • Why developers use terminals
  • Navigation: cd, ls, pwd, mkdir
  • File operations: cp, mv, rm, touch
  • Reading files: cat, head, tail
  • Environment variables and PATH
  • Running scripts and executables
  • Piping and redirection
CSK Connection: Every development task — running the dev server (npm run dev), building (npm run build), committing code, deploying — happens through the terminal.

CSK Connection: CSK uses a Production-branch workflow where code is pushed directly to Production on GitHub. Render auto-deploys from this branch. The .gitignore excludes node_modules/, .env* files, and build artifacts.

Goal: Understand server-side JavaScript and manage project dependencies.
  • What Node.js is (JavaScript outside the browser)
  • Node.js version management with nvm and .nvmrc
  • package.json: name, scripts, dependencies, engines

  • node_modules/ and package-lock.json

CSK Connection: CSK pins Node.js 22 via .nvmrc and package.json engines. It has 25+ dependencies managed through npm. Scripts include dev, build, start, lint, type-check, and custom migration scripts.
11 TypeScript
Goal: Add type safety to JavaScript to catch bugs before they happen.
  • Why TypeScript exists and what problems it solves
  • Basic types: string, number, boolean, null, undefined
  • Arrays and objects with types
  • Interfaces and type aliases
  • Union types and optional properties
  • Generics (basics)
  • Type narrowing and type guards
  • tsconfig.json: strict mode, module resolution, path aliases
  • The @ path alias (e.g., @/lib/supabase)
CSK Connection: The entire codebase is TypeScript with strict mode. Types are defined in src/types/ for roles, gallery items, locations, and more. The tsconfig.json configures @/ path aliases and strict null checking.

Phase 2 Milestone

Set up a TypeScript project from scratch with Git, npm, a .gitignore, and a build script. Push it to GitHub.

Phase 3

React

Learn the UI library that powers the entire frontend.

12 React Fundamentals
Goal: Build UIs with reusable components using JSX.
  • What React is and why it dominates frontend development
  • Components: functions that return UI
  • JSX syntax: HTML-like code inside JavaScript
  • Props: passing data to components
  • Rendering lists with .map()
  • Conditional rendering: ternary, &&, early returns
  • Component composition and children
  • File naming conventions: ComponentName.tsx
CSK Connection: Every page and UI element is a React component. Header.tsx, Footer.tsx, TestimonialsCarousel.tsx are all reusable components with props. The gallery uses .map() to render computer cards.
13 React State & Hooks
Goal: Make components interactive with state and side effects.
  • useState: tracking values that change

  • useRef: referencing DOM elements and storing values
  • useCallback and useMemo: performance optimization
  • The rules of hooks
  • Controlled vs. uncontrolled form inputs
  • State lifting: sharing state between siblings
CSK Connection: The admin ticket page uses useState for filters and search, useEffect for polling ticket updates every 30 seconds, and useRef for form inputs. The "Call Customer" widget auto-refreshes via useEffect intervals.
14 React Patterns & Advanced Hooks
Goal: Organize complex applications with proven patterns.
  • Context API: sharing state across the component tree
  • Custom hooks: extracting reusable logic (e.g., useBotProtection)
  • Form handling patterns: multi-step forms, validation feedback
  • Loading, error, and empty states
  • The 'use client' directive — what it means (preview for Next.js)
  • Component organization: static/, admin/, forms/, gallery/
CSK Connection: CSK has custom hooks for bot protection and interaction tracking. The customer intake is a multi-step wizard. Components are organized into feature folders under src/components/. Client components use 'use client' at the top of the file.

Phase 3 Milestone

Build an interactive React application with multiple pages (via client-side routing), forms with validation, and state management — such as a to-do app or product catalog.

Phase 4

Next.js — The Full-Stack Framework

Turn React into a complete application framework with routing, server rendering, API routes, and more.

Estimated: 4–5 weeks
15 Next.js App Router & File-Based Routing
Goal: Create pages and layouts by placing files in the right folders.
  • Project structure: src/app/ directory
  • page.tsx = a route, layout.tsx = shared wrapper
  • Nested routes and route groups: (public), admin
  • Dynamic routes: [slug], [id]
  • loading.tsx and error.tsx special files
  • Navigation: <Link> component and useRouter()
  • not-found.tsx for 404 pages
CSK Connection: CSK uses route groups: (public) for customer pages, admin for the employee portal. Dynamic routes power blog posts (/blog/[slug]) and ticket detail pages (/admin/tickets/[id]).
16 Server Components vs. Client Components
Goal: Understand the most important architectural decision in modern Next.js.
  • Server Components: run on the server, no JavaScript sent to browser
  • Client Components: run in the browser, needed for interactivity
  • When to use which (decision framework)
  • The 'use client' boundary
  • Fetching data in Server Components (no useEffect needed)
  • Passing server data to client components via props
  • Performance implications: less JavaScript = faster pages
CSK Connection: Public pages like the blog listing are Server Components that fetch directly from Supabase. Interactive elements — the contact form, ticket filters, gallery editor — are Client Components marked with 'use client'.
17 API Route Handlers
Goal: Build a backend API right inside your Next.js project.
  • Route handlers: src/app/api/*/route.ts
  • HTTP methods: GET, POST, PUT, DELETE
  • NextRequest and NextResponse
  • Parsing request bodies and query parameters
  • Returning JSON responses with status codes
  • Error handling in API routes
  • Organizing routes by feature: /api/blog/, /api/auth/, /api/contact/
CSK Connection: CSK has 20+ API routes organized by feature. The blog API (/api/blog/) supports full CRUD. The contact API validates input with Zod, sends email via Resend, and returns appropriate status codes.
18 Middleware & the Request Pipeline
Goal: Intercept and modify every request before it reaches a page or API route.
  • What middleware is and where it runs
  • middleware.ts in the project root
  • The matcher config for targeting specific routes
  • Redirecting unauthenticated users
  • Adding security headers to every response
  • Reading and setting cookies in middleware
  • Role-based route protection
CSK Connection: middleware.ts protects all /admin/* routes by checking session cookies. It adds security headers (HSTS, X-Frame-Options, CSP) to every response and implements role-based access control.
19 Image Optimization & Static Assets
Goal: Serve images fast using Next.js's built-in optimization.
  • The public/ directory for static files
  • Next.js <Image> component: automatic sizing, lazy loading, format conversion
  • width, height, priority, and alt props
  • SVG handling: when to use <Image> vs. inline SVG
  • Remote images: remotePatterns in next.config.mjs
  • The sharp library for server-side image processing
  • Common pitfalls (like SVGs without width/height in Firefox!)
CSK Connection: The hero logo uses <Image> with priority for fast LCP. Gallery images use automatic optimization. next.config.mjs allows remote images from any HTTPS source. The sharp package handles server-side processing.
20 SEO, Metadata & Open Graph
Goal: Make your site discoverable by search engines and shareable on social media.
  • The metadata export in layout.tsx and page.tsx
  • Title, description, keywords
  • Open Graph tags: og:title, og:image, og:description
  • Twitter card metadata
  • Canonical URLs
  • Structured data / Schema.org (JSON-LD)
  • Robots and sitemap configuration
CSK Connection: layout.tsx exports comprehensive metadata including Open Graph images, Twitter cards, Schema.org JSON-LD for LocalBusiness, and canonical URLs pointing to computerstoreks.com.

Phase 4 Milestone

Build a Next.js application with public pages, an API, protected admin routes via middleware, and proper metadata — such as a blog with an admin editor.

Phase 6

Databases & Supabase

Goal: Understand how data is organized, stored, and queried in relational databases.
  • What a database is and why you need one
  • Tables, rows, and columns
  • Primary keys and unique identifiers
  • Data types: text, integer, boolean, timestamp, UUID
  • Relationships: one-to-many, many-to-many
  • Foreign keys: linking tables together
  • Indexes: making queries fast
CSK Connection: CSK has 15+ tables with UUIDs as primary keys, foreign key relationships linking customers to tickets to invoices, timestamps for created/updated tracking, and boolean flags like assets_updated.
24 SQL — Querying Data
Goal: Read and manipulate database data using SQL.
  • SELECT: retrieving data with conditions
  • INSERT: adding new records
  • UPDATE: modifying existing records
  • DELETE: removing records (and why soft deletes are better)
  • WHERE, ORDER BY, LIMIT
  • JOIN: combining data from multiple tables
  • Aggregate functions: COUNT, SUM, AVG
  • Subqueries and common patterns
CSK Connection: CSK's migration files in docs/database/ are raw SQL. The blog schema uses CREATE TABLE, foreign keys, indexes, and junction tables (blog_post_tags). Supabase queries translate to SQL under the hood.
25 Supabase — Setup & Client
Goal: Set up a Supabase project and connect to it from Next.js.
  • Creating a Supabase project (free tier)
  • The Supabase dashboard: table editor, SQL editor
  • @supabase/supabase-js: creating a client
  • @supabase/ssr: server-side Supabase with cookies
  • Anon key (client-safe) vs. service role key (server-only)
  • Environment variables: NEXT_PUBLIC_SUPABASE_URL, keys
  • CRUD operations: .select(), .insert(), .update(), .delete()
  • Filtering: .eq(), .ilike(), .in(), .order()
CSK Connection: src/lib/supabase.ts creates both a public client (anon key) and admin client (service role key). supabase-server.ts creates cookie-based clients for SSR. Every feature reads/writes through these clients.
26 Schema Design & Migrations
Goal: Design a database schema that models real business data and evolve it over time.
  • Planning tables from business requirements
  • Normalization: reducing data duplication
  • Junction tables for many-to-many relationships
  • Timestamps: created_at, updated_at with defaults
  • Soft deletes: is_active, archived_at
  • Migrations: versioned SQL scripts that evolve the schema
  • Supabase migrations with npx supabase db diff
CSK Connection: CSK's schema evolved through multiple migrations in docs/database/migrations/ — adding location support, fixing RLS policies, and restructuring security. The blog uses a junction table (blog_post_tags) for post-to-tag relationships.
27 Row-Level Security (RLS)
Goal: Protect data at the database level so users can only access what they're allowed to.
  • What RLS is and why it's critical
  • Enabling RLS on tables
  • Writing policies: SELECT, INSERT, UPDATE, DELETE
  • auth.uid() — identifying the current user in policies
  • Public read policies for published content
  • Admin-only write policies
  • Testing policies: what happens when they're wrong
CSK Connection: Every Supabase table has RLS enabled. Blog posts have public SELECT policies (published only) and admin-only INSERT/UPDATE/DELETE policies. Multiple migration files specifically fix and refine RLS policies.
28 Database Triggers & Automation
Goal: Automate database operations with PostgreSQL triggers.
  • What triggers are: code that runs automatically on data changes
  • Trigger types: BEFORE and AFTER on INSERT, UPDATE, DELETE
  • Trigger functions in PL/pgSQL
  • Use cases: auto-updating timestamps, auto-linking related records
  • Dangers of triggers: hidden logic, debugging difficulty
CSK Connection: CSK has a PostgreSQL trigger trg_link_customer_business on the rs_customers table that automatically creates and links business records when a customer's business_name changes.

Phase 6 Milestone

Phase 7

Authentication & Security

Protect your application with login systems, session management, role-based access, and security best practices.

Estimated: 3–4 weeks
29 Authentication Concepts
Goal: Understand how websites know who you are.
  • Authentication (who are you?) vs. authorization (what can you do?)
  • Sessions and cookies: how login state persists
  • JSON Web Tokens (JWT): stateless authentication
  • Cookie attributes: httpOnly, secure, sameSite, maxAge
  • Session storage options: cookies, database, in-memory
  • Password security: never store plaintext
CSK Connection: CSK uses both JWT-based auth (Supabase Auth) and custom encrypted session cookies (admin_session). Cookie config includes httpOnly, secure, and sameSite attributes defined in session-cookie.ts.
30 Supabase Auth & Custom Sessions
Goal: Implement a complete authentication system.
  • Supabase Auth: email/password sign-up, sign-in, sign-out
  • Server-side session management with @supabase/ssr
  • Password hashing with bcryptjs: hash() and compare()
  • Custom session encryption: AES-256-GCM
  • Node.js crypto module: createCipheriv, createDecipheriv
  • Login/logout API routes
  • Protected page patterns: redirect if not authenticated
CSK Connection: src/lib/supabase-auth.ts handles Supabase auth. src/lib/session-cookie.ts uses AES-256-GCM encryption via Node's crypto module. src/lib/auth.ts uses bcryptjs for legacy password verification. Login routes are in /api/auth/.
31 Role-Based Access Control (RBAC)
Goal: Restrict features based on user roles (admin, technician, receptionist, etc.).
  • Designing a role system: which roles does the business need?
  • Multi-role users (one person can have several roles)
  • Route-to-role mapping: which pages require which roles
  • Server-side role checking in middleware
  • Client-side role checking for UI elements
  • The user_profiles table with a roles array
  • Role helper utilities
CSK Connection: src/lib/role-helpers.ts defines 10 roles (admin, owner, technician, receptionist, etc.). Middleware checks roles against route requirements. Users can hold multiple roles stored as an array in user_profiles.
32 Web Security Best Practices
Goal: Defend against the most common web attacks (OWASP Top 10).
  • Cross-Site Scripting (XSS): sanitizing user input, Content Security Policy
  • Cross-Site Request Forgery (CSRF): sameSite cookies
  • SQL Injection: parameterized queries (Supabase handles this)
  • Security headers: HSTS, X-Frame-Options, X-Content-Type-Options
  • Rate limiting: preventing brute force attacks
  • Input validation: server-side with Zod schemas
  • Environment variable security: never expose secrets to the client
CSK Connection: middleware.ts sets 7 security headers on every response. The contact API implements rate limiting (10 requests/minute). All API inputs are validated with Zod. NEXT_PUBLIC_ prefix controls which env vars reach the browser.
33 Spam & Bot Protection
Goal: Keep bots and spam out of your forms without hurting real users.
  • Honeypot fields: invisible inputs that trap bots
  • Timing analysis: humans take time to fill forms, bots don't
  • Interaction tracking: mouse/keyboard event monitoring
  • CAPTCHA alternatives: Cloudflare Turnstile
  • Browser fingerprinting with FingerprintJS
  • Disposable email detection
  • Layering multiple defenses for best results
CSK Connection: CSK layers all of these: spam-detection.ts tracks interactions and timing, disposable-email.ts blocks throwaway addresses, Cloudflare Turnstile provides CAPTCHA, and FingerprintJS identifies repeat offenders.

Phase 7 Milestone

Add authentication with multiple roles to your blog app. Admin role can create/edit posts, editor role can only edit, and anonymous users can only read. Implement security headers and rate limiting.

Phase 8

API Design & Data Validation

Build robust, well-structured APIs that validate every input and handle every error.

Estimated: 2–3 weeks
34 REST API Design Principles
Goal: Design APIs that are intuitive, consistent, and follow industry conventions.
  • REST principles: resources, HTTP methods, status codes
  • URL design: /api/blog, /api/blog/[id]
  • HTTP methods and their meanings: GET, POST, PUT, DELETE
  • Status codes: 200, 201, 400, 401, 403, 404, 500
  • Consistent response shapes: { data, error }
  • Pagination, filtering, and sorting via query parameters
  • Versioning strategies
CSK Connection: CSK's APIs follow REST conventions: GET /api/blog lists posts, POST /api/blog creates one, GET /api/blog/[id] retrieves by ID or slug, PUT /api/blog/[id] updates, DELETE /api/blog/[id] deletes. Query params like ?admin=true modify behavior.
35 Data Validation with Zod
Goal: Validate every piece of data entering your system using type-safe schemas.
  • Why server-side validation is mandatory (never trust the client)
  • Zod basics: z.string(), z.number(), z.boolean(), z.object()
  • Constraints: .min(), .max(), .email(), .url()
  • Optional and nullable fields
  • Arrays and nested objects
  • Custom error messages
  • Inferring TypeScript types from Zod schemas (z.infer)
  • Parsing vs. safe parsing: .parse() vs. .safeParse()
CSK Connection: Zod validates contact form submissions (name, email, message), blog post creation (title, content, slug), gallery entries (specs, pricing), and API request bodies throughout the application.
36 Error Handling Patterns
Goal: Handle failures gracefully so your app never crashes silently.
  • Try/catch in async API routes
  • Error response format: message, status code, details
  • Distinguishing client errors (4xx) from server errors (5xx)
  • Logging errors for debugging (without leaking to users)
  • Error boundaries in React for UI crashes
  • Graceful degradation: what to show when something fails
CSK Connection: Every API route wraps its logic in try/catch, returning appropriate status codes. The middleware logs auth debug info. API routes never expose internal errors to clients — they return generic messages while logging details server-side.

Phase 8 Milestone

Refactor your blog API with Zod validation on all inputs, consistent error responses, and proper HTTP status codes for every scenario.
